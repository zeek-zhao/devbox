# C++ 工具指南（G4）

> 工具清单、装在哪、怎么调、参数速查、选型对比、常见误用。
> 所有工具都装在 `devbox-cpp` 镜像里，宿主上没有（格式化器同理，真本 `scripts/fmt.sh`
> 头注释），所以统一经容器调用。命令契约见《知识点清单增强规范》§4.3；
> 版本号一律引用 `images/versions.env` 变量（§4.4），本篇不写字面量。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源（真本 `images/versions.env`） |
|---|---|---|---|
| g++ | 主编译器（用例默认 `CXX=g++`） | 是（进容器跑 `g++ --version` 可核对） | `${GCC_MAJOR}` |
| clang++ | 第二编译器，交叉检查诊断 | 是 | `${CLANG_MAJOR}` |
| clang-format | 格式化（`make fmt` 的底层） | 是 | `${CLANG_FORMAT_MAJOR}`（必须与 `${CLANG_MAJOR}` 同步） |
| cmake | 构建系统（L2 用例与毕业项目） | 是 | `${CMAKE_MIN_VERSION}` |
| gdb | 断点调试、回溯 | 是 | 随镜像层安装 |
| valgrind | 内存错误/泄漏离线检测 | 是 | 随镜像层安装 |
| ASan/UBSan/TSan | 编译器内置消毒器，随编译器分发 | 是（编译开关，非独立二进制） | 随 `${GCC_MAJOR}` / `${CLANG_MAJOR}` |
| perf | 系统级剖析 | **未预装**（实测 `command not found`） | — |

预装核验方法（在容器里逐个跑 `--version`）：

```bash
docker run --rm "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}" bash -c \
  'g++ --version | head -1; clang++ --version | head -1; cmake --version | head -1; \
   clang-format --version; gdb --version | head -1; valgrind --version; make --version | head -1'
```

注意：`perf` 未预装是实测结论。本轨道的剖析用例 `L3-004-profiling-benchmarks`
不依赖 perf——它用操作计数承担精确断言、稳定计时确认量级差距（见其 README），
需要系统级剖析时再自行安装。

## 2. 每工具一节：装在哪、怎么调、常用参数速查

统一调用方式：工具在镜像里，宿主直跑必然 command not found。两条路：

```bash
# 路 A：用 runner 的 --keep 保留用例容器，再 exec 进去（适合接着跑完的现场调试）
TAG=latest scripts/run-example.sh cpp L2-007-gdb-debugging --keep
docker exec -it <容器ID> bash

# 路 B：直接起一个一次性容器（适合独立实验）
docker run --rm "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}" bash
```

### g++ / clang++

- 装在哪：镜像层内，`PATH` 直取；用例经 `CXX` 环境变量选择（真本各用例 `run.sh`）。
- 常用参数速查（本仓库用例的基线口径，见 `L0-hello` / `L2-005-test-harness` 的 `run.sh`）：
  `-std=c++20`（语言标准显式声明，呼应 `L2-003-reproducible-build`）、
  `-Wall -Wextra -pedantic`（警告基线）、`-g`（调试信息，gdb 需要）、
  `-O2`（优化；与 `-g` 并用时 gdb 变量可见性会受影响）、
  `-fsanitize=address|undefined|thread`（消毒器，一次一个）。

### clang-format

- 装在哪：镜像里；不在宿主上跑（真本 `scripts/fmt.sh`）。
- 怎么调：不要直接调，走统一入口 `make fmt` / `bash scripts/fmt.sh --check --lang cpp`；
  风格基线是仓库根 `.clang-format`（fmt 范围与口径见该脚本头注释）。
- 版本约束：`${CLANG_FORMAT_MAJOR}` 与 `${CLANG_MAJOR}` 同步，失配会「本地过 CI 红」。

### cmake

- 装在哪：镜像里；练习入口是 `TAG=latest scripts/run-example.sh cpp L2-002-cmake-targets`。
- 常用参数速查（与该用例 `run.sh` 一致）：
  `cmake -S <src> -B <build>`（源/构建目录分离）、`cmake --build <build>`、
  `cmake --install <build> --prefix <dir>`；构建目录应干净（`L2-003-reproducible-build`）。

### gdb

- 装在哪：镜像里；考点用例 `L2-007-gdb-debugging`。
- 常用参数速查：编译加 `-g`；会话内 `break <行/函数>`、`run`、`bt`（回溯）、
  `print <expr>`；优化构建会内联/重排，断点位置与变量可见性会变（该用例「易错点」）。
- 复现路径：`--keep` 保留容器后进会话（见路 A）。

### valgrind

- 装在哪：镜像里。
- 常用参数速查：`valgrind --leak-check=full ./程序`（泄漏明细与摘要）；
  与 ASan 二选一跑，不要叠加。

### ASan / UBSan / TSan

- 装在哪：编译器内置，编译开关而非独立工具；考点用例 `L2-006-sanitizers`。
- 怎么调：编译时 `-fsanitize=address` / `=undefined` / `=thread`（一次一个，
  TSan 与 ASan 互斥——实测编译器会报不兼容，见 [问题指南.md](问题指南.md)）；
  该用例同时示范了报告「归一化」输出（报告含地址且非零退出，不能直接进 `expected.txt`）。

### 计时与基准

- 本轨道不依赖 perf：`L3-004-profiling-benchmarks` 用操作计数 + 稳定计时，
  墙钟不进 `expected.txt`（受预热/缓存/调度影响，该用例「易错点」）。

## 3. 选型对比

| 需求 | 首选 | 为什么不选另一个 |
|---|---|---|
| 运行时内存错误（越界/UAF/泄漏） | ASan（快，报错点精确） | valgrind 慢一个量级，报错粒度粗；两者不必叠加 |
| 数据竞争 | TSan（专为此设计） | ASan 不查数据竞争；且与 TSan 互斥，必须分开构建 |
| 未定义行为（有符号溢出等） | UBSan（可与 ASan 同开） | gdb 只在崩溃现场停下，UBSan 能报「未崩但未定义」 |
| 断在指定行、看调用栈 | gdb | 消毒器只报「已发生」的错误，不能交互暂停 |
| 悬垂引用/悬垂视图类生命周期问题 | 先跑对应 L1 用例（如 `L1-013-string-view`） | 工具是兜底，编译期与用例判据是第一道 |

g++ 与 clang++ 不构成二选一：两者都预装（`${GCC_MAJOR}` / `${CLANG_MAJOR}`），
惯用法是交叉编译同一份代码，用两套诊断互查（警告与报错文本各有所长）。

## 4. 常见误用

1. **`-DNDEBUG` 构建跑断言测试**：`assert` 被整个编译掉，测试假绿。
   实测：同一份代码 `-DNDEBUG` 下断言不生效（打印后退出码 0），
   去掉后 `Assertion failed`、SIGABRT。复现命令见
   [问题指南.md](问题指南.md)「断言失效」一节的反例一。
2. **TSan 与 ASan 同开**：实测 `error: '-fsanitize=thread' is incompatible with
   '-fsanitize=address'`。TSan 与 ASan/UBSan 分两次构建分别跑
   （`L2-006-sanitizers` README「延伸」）。
3. **宿主上直跑 clang-format / 工具链**：工具只装在镜像里，宿主上必然
   command not found；一律走 `make fmt` / runner / 容器（真本 `scripts/fmt.sh`）。
4. **把 ASan 原始报告直接写进 `expected.txt`**：报告含地址且以非零退出，
   输出不稳定会让 runner 每次都 DIFF；学 `L2-006-sanitizers` 做归一化。
5. **优化构建下用 gdb 查变量**：`-O2` 内联重排后变量可能不可见、断点位置漂移
   （`L2-007-gdb-debugging`「易错点」）；调试构建用 `-g -O0` 口径。
