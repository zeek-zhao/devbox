# C++ 错误处理指南（how-to）

> 面向「要在 C++ 代码里把错误处理写对」的操作指南：按任务路由到 E 类示例，
> 每条纪律给得出用例 ID 与验证命令。从已有故障出发的排查走
> [排查手册](排查手册.md)；语法层知识归 L1/L2/L4 用例，本篇不重复贴代码。
> 全部 15 个 E 例已于 2026-11-11 在 `devbox-cpp:latest` 内真跑通过
> （`TAG=latest scripts/run-example.sh cpp <ID>`）。

## 1. 适用边界

- 适用于：在本仓库 C++ 代码（含毕业项目）里设计或修复错误处理路径——异常层次、
  上下文携带、errno 边界、栈展开与 RAII、Result/optional、错误码枚举、嵌套异常、
  强异常保证、句柄守卫、契约分层、结构化日志、重试、聚合、快速失败、反模式自查。
- 不适用于：第一次学 C++ 的语法（见 [知识点清单](知识点清单.md) L1 段）；
  手上已经有一个故障要排查（见 [排查手册](排查手册.md)）。
- 本篇是 how-to：只讲「做某件事的步骤」。命令契约见
  [docs/11](../../docs/11-知识点清单增强规范.md) §4.3（统一 `TAG=latest
  scripts/run-example.sh cpp <ID>`，禁止硬编码镜像 tag）。

## 3. 七条核心纪律（每条可执行、可断言）

1. **先选通道：异常还是错误值**（E-005 + E-001）：可预期、调用方必然要分支的失败
   用 `variant<T, E>`/`optional` 当返回值；真正的异常状态用异常，且异常层次
   按失败类别组织，基类引用捕获保虚分发。
2. **异常必须携带定位上下文**（E-002 + E-007）：继承 `std::runtime_error` 附加
   path/line/code 字段；转译异常用 `throw_with_nested` 挂原异常，顶层
   `rethrow_if_nested` 剥链——普通 `throw 新异常` 会把根因丢在中间层。
3. **C 边界处理 errno**（E-003）：C 库调用失败后立即检查 errno；记住「成功的调用
   不清零 errno」，隔了其他调用再判就是判旧值；能用 `std::system_error` 就把
   errno 与上下文一起打包。
4. **资源交 RAII，不靠手写清理**（E-004 + E-009）：栈展开沿构造逆序调析构，
   正常返回同一逆序——释放逻辑只写一份在析构里；裸句柄（`FILE*` 等）包进
   `unique_ptr` 加自定义删除器，三条路径（正常/异常/打不开）都恰好关闭一次。
5. **强异常保证是接口承诺**（E-008）：会修改状态的批量操作要承诺「失败即回滚到
   操作前」；做不到就写明弱保证，让调用方按半成品状态设计（对照 E-008 weak 路径）。
6. **校验分层**（E-010 + E-013 + E-014）：用户输入永远校验（返回错误值，
   全量收集一次报完）；内部不变式用 `assert`（上游已保证，debug 生效）；
   坏配置在入口 fail-fast，抛出时资源占用为零——拒绝发生在任何副作用之前。
7. **按错误类别决定重试与退出**（E-012 + E-006 + E-011）：瞬时错误才重试，
   指数退避有上限；持续抖动耗尽后放弃；永久错误立即放弃；退出码由
   `to_exit_code` 一处映射；错误以结构化行（级别 序号 event= 键值对）进日志。

## 4. 反模式清单（每条可复现）

- 空 catch 吞异常：调用方一无所知（E-015 ANTI swallow；正确做法是记录后 `throw;`）。
- 按值捕获异常对象：切片丢派生字段（E-015 ANTI slicing，`seq=77` 取不到；
  E-001 的 sliced-free catch 行是同型现象）。
- 笼统报错 `failed`：不保留根因路径（E-015 ANTI vague；GOOD 是前缀拼接
  `build: open /data/index.bin: errno=2`）。
- 中层转译丢根因：`throw runtime_error("build failed")` 不挂 nest（E-007 对照组）。
- 成功调用之后判 errno：读到上一次失败的旧值（E-003 第二行）。
- 手写清理序列配异常路径：任何一处早退都漏放（E-004/E-009 的 RAII 对照）。

可运行对照反例入口：`TAG=latest bash scripts/run-example.sh cpp E-015-antipattern-compare`，
三对 ANTI/GOOD 输出紧邻，差异即输出本身。

## 5. 评审清单（review 错误处理代码时逐条问）

- [ ] 失败走的通道（异常/错误值）与失败类别匹配吗？
- [ ] catch 是引用捕获吗？异常对象带定位字段吗？转译挂 nest 了吗？
- [ ] C 库边界 errno 是不是失败后立即检查？
- [ ] 资源是不是 RAII？有没有手写清理序列出现在异常可达路径上？
- [ ] 批量改状态的函数承诺了什么保证（强/弱）？
- [ ] 输入校验与内部不变式分层了吗？坏配置是不是在副作用之前被拒绝？
- [ ] 重试是不是先分类？退出码是不是一处映射？日志行是不是可检索格式？

逐条判据都对应第 2 节路由表里的一行用例；写法契约与状态机见
[docs/11](../../docs/11-知识点清单增强规范.md) §4、§7.1。
