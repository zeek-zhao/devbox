# C++ 排查手册（troubleshooting）

> 按「症状 → 排查命令 → 判据 → 修复」组织的手册。§2 是错误处理章，含
> §2.1–§2.15 共 15 节，逐节对应 `cpp/examples/E-001..E-015`（各例 README 的
> `coverage: exempt` 注释指向本手册错误处理章）。
> §3、§4 是路由章：内存/资源与构建/运行问题的入口指向既有指南与 lab。
> 全部排查命令已于 2026-11-11 在 `devbox-cpp:latest` 内真跑核对；写法纪律见
> [docs/72-排障演练规范](../../docs/72-排障演练规范.md)（现象禁止编造，只许来自
> 真跑或已登记问题）。

## 1. 使用方法

1. 先在本手册按症状定位到节；每节给一条可直接执行/粘贴的排查命令与判据输出。
2. 判据不成立 → 按该节「修复」处理；判据成立但问题仍在 → 走该节给出的关联文档。
3. 「怎么写对」的设计问题走 [错误处理指南](错误处理指南.md)；镜像、版本、环境变量
   事实走 [工程参考](工程参考.md)。

## 2. 错误处理章（对应 E-001..E-015）

### 2.1 不同类失败进了同一个 catch（E-001-exception-hierarchy）

- 症状：多种失败被一并兜住统一处理，或基类按值捕获后 `what()` 只剩基类信息。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-001-exception-hierarchy`
- 判据：`parse branch: parse failed token=<name>` 与 `schema branch: schema
  failed field=age` 各进各的分支；`sliced-free catch: parse failed` 证明
  基类引用捕获仍走虚分发；未知类型落 `catch-all: unknown throwable`。
- 修复：异常层次按失败类别组织，一条 try 只进一个 catch；catch 一律引用捕获。
  详见 E-001 README。

### 2.2 异常只有一句概要消息（E-002-custom-exception-context）

- 症状：catch 到异常后不知道是哪个文件哪一行哪类错，定位靠猜。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-002-custom-exception-context`
- 判据：`load: what=index file corrupt` 之外还有字段行
  `load: path=data/index.bin line=7 code=3`，外层 `outer: summary=...` 仍可读。
- 修复：自定义异常继承 `std::runtime_error`，附加 path/line/code 字段，
  catch 处直接读字段。详见 E-002 README。

### 2.3 errno 读到旧值（E-003-errno-checking）

- 症状：C 库调用「看起来没失败」却报了错——实际是读到了上一次失败的 errno。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-003-errno-checking`
- 判据：`after success call errno still reports: No such file or directory`
  （成功的 fopen 不清零 errno）；`system_error: open missing-dir/file.txt:
  No such file or directory` 与 `system_error: code=2`。
- 修复：errno 在失败返回后立即检查/保存；跨 C 边界用 `std::system_error`
  打包。详见 E-003 README。

### 2.4 异常路径资源释放顺序错乱或漏放（E-004-unwinding-cleanup-order）

- 症状：抛异常后部分资源没释放，或释放顺序与依赖相反。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-004-unwinding-cleanup-order`
- 判据：异常路径 `release tx` → `release conn` 先于 `caught: peer reset`；
  正常路径 `release b` → `release a` → `exit: clean`——同一逆序。
- 修复：资源交 RAII 对象，释放逻辑只在析构里写一份，靠栈展开保证。
  详见 E-004 README。

### 2.5 错误与正常返回值混型（E-005-result-value-return）

- 症状：调用方忘记判错就取值，或错误被硬塞进特殊值/全局状态。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-005-result-value-return`
- 判据：`good: value=entry-42`、`miss: error=not found`、`denied: ok=false`、
  `optional: has=false` 与 `optional: value_or=7`。
- 修复：`variant<T, E>` 最小 Result——`ok()` 先查再取；只论有无用
  `optional`。详见 E-005 README。

### 2.6 进程退出码口径漂移（E-006-error-code-enum）

- 症状：同一类失败在不同调用点退出码不同，脚本没法按码分支。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-006-error-code-enum`
- 判据：`empty: bad input exit=1`（BadInput=1）、`ghost: not found exit=0`
  （业务失败不进退出码）、`ghost: raw=4`（原始码可查）。
- 修复：`enum class Errc` 定义错误码，`to_exit_code` 一处统一映射；
  禁止散落的手写 exit 数字。详见 E-006 README。

### 2.7 转译异常后根因丢失（E-007-nested-exceptions）

- 症状：顶层只看到 `build failed`，底层真正的 `checksum mismatch` 不见了。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-007-nested-exceptions`
- 判据：`depth 0: build failed` + `depth 1: checksum mismatch at offset 16`
  两行完整因果链；对照组 `plain: no nested exception`（普通重抛 nest 为空）。
- 修复：中层转译用 `std::throw_with_nested` 挂原异常，顶层递归
  `std::rethrow_if_nested` 剥链。详见 E-007 README。

### 2.8 失败后状态改了一半（E-008-strong-guarantee）

- 症状：批量修改中途失败，容器里留下半成品，调用方无法决定重试还是回滚。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-008-strong-guarantee`
- 判据：强保证路径 `failed: storage full` 后仍 `after: size=2 last=bob`
  （与操作前一致）；weak 对照 `weak: size=1 (state already changed)`。
- 修复：会改状态的批量操作实现强保证（先在副本上做，成功再交换）；
  做不到就在接口上写明弱保证。详见 E-008 README。

### 2.9 异常路径句柄泄漏（E-009-leak-guard）

- 症状：读一半抛异常后 `FILE*` 没人关；只在长跑/压测时以 fd 耗尽形式暴露。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-009-leak-guard`
- 判据：异常路径 `closed` 出现在 `bad path: caught bad header` 之前
  （展开时守卫关闭）；missing 路径 `caught cannot open ...` 根本不产生句柄。
- 修复：裸句柄包 `unique_ptr` + 自定义删除器；同一主题的内存错误实机
  排障演练见 [T-001-asan-heap-overflow](../examples/T-001-asan-heap-overflow/WALKTHROUGH.md)。
  详见 E-009 README。

### 2.10 输入校验与内部不变式混用（E-010-contract-assert）

- 症状：用户输入上 assert（release 下被 NDEBUG 删掉，坏输入直达深处），
  或内部不变式做成温柔降级（bug 被掩盖）。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-010-contract-assert`
- 判据：`empty: ok=false`、`junk: ok=false`（输入校验返回 `nullopt`）；
  `good: value=8080 mask=144`、`boundary: value=1 mask=1`；`assert: active=true`
  证明不变式构建生效。
- 修复：输入校验永远执行（返回错误值）；`assert` 只守上游已保证的内部不变式。
  详见 E-010 README。

### 2.11 日志翻不到、聚不了类（E-011-structured-logging）

- 症状：错误日志是人话整段，grep 不到模式、按字段聚合失败。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-011-structured-logging`
- 判据：五行 `INFO #1 event=startup pid=static` …
  `ERROR #4 event=index_corrupt offset=16 code=3` 格式齐整、字段可检。
- 修复：固定 `级别 序号 event=名 键值对` 单行格式，ERROR 自带上下文字段。
  详见 E-011 README。

### 2.12 重试策略失当（E-012-retry-backoff）

- 症状：永久错误也被重试到上限；或真瞬时错误一次失败就放弃。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-012-retry-backoff`
- 判据：瞬时 `attempt 1/2: transient: connection reset` 后 `attempt 3: ok`；
  持续抖动 5 次后 `give up: attempts exhausted`；永久 `dead: give up immediately`。
- 修复：先分类（瞬时/持续/永久）再重试，2ms/4ms/8ms 指数退避 + 次数上限。
  详见 E-012 README。

### 2.13 一次只报一个输入错误（E-013-error-aggregation）

- 症状：表单校验遇错即停，用户修一个再爆一个，来回试错。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-013-error-aggregation`
- 判据：`bad input: 3 problems` 且逐条列出 `- name: must not be empty`、
  `- port: must be numeric`、`- tags: need at least one`；
  `valid input: 0 problems`（空列表即成功信号）。
- 修复：校验全量收集不早退，一次返回全部 field + message。
  详见 E-013 README。

### 2.14 坏配置流入主流程（E-014-fail-fast）

- 症状：`workers=0` 这类坏配置进到深处才炸，清理时背着半初始化状态。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-014-fail-fast`
- 判据：`fail-fast: config: workers must be positive` + `cleanup: release 0
  items`（资源占用为零）；好配置 `batch: started with 4 workers` +
  `cleanup: release 2 items`。
- 修复：配置校验放 `start_batch` 入口，拒绝发生在任何副作用之前。
  详见 E-014 README。

### 2.15 吞异常 / 切片 / 笼统消息（E-015-antipattern-compare）

- 症状：空 catch 调用方一无所知；按值捕获切片丢字段；报错只剩一句 failed。
- 排查命令：`TAG=latest bash scripts/run-example.sh cpp E-015-antipattern-compare`
- 判据：每对 ANTI/GOOD 紧邻——`ANTI swallow: caller saw nothing` vs
  `GOOD log: disk full` + `GOOD rethrown: disk full`；`ANTI slicing: what=rich
  error`（无 seq）vs `GOOD ref: what=rich error seq=77`；`ANTI vague: failed` vs
  `GOOD context: build: open /data/index.bin: errno=2`。
- 修复：记录后 `throw;` 重抛；catch 一律引用捕获；消息前缀拼接保留根因路径。
  详见 E-015 README。
