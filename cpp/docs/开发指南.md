# C++ 开发指南（G2）

> 从零到能改：环境、目录、一条命令跑通、改动循环、调试入口。
> 跨语言通用内容（runner 通用用法、CI 红灯定位、提交身份、门禁与 PR 约定）集中在
> [docs/13-通用开发指南.md](../../docs/13-通用开发指南.md)（T0 单一真本），本篇只写 C++ 轨道差异，见 §6。
> 命令契约与版本引用契约见《知识点清单增强规范》§4.3/§4.4：版本号只写
> `images/versions.env` 的变量名，全文不出现手写版本常量与硬编码镜像 tag。

## 1. 环境与启动（镜像 tag / 版本号来源）

**镜像**：C++ 轨道用 `devbox-cpp` 镜像。语言名到镜像层的映射真本是
`images/lang-images.tsv`（`c` 与 `cpp` 复用同一个 cpp 层，同一套工具链）；
仓库前缀 `REGISTRY` 真本是 `images/versions.env`。镜像 tag 一律经变量传入，
禁止把任何 tag 字面量写死：

```bash
docker pull "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}"
```

runner 读取 tag 的优先级是 `TAG` → `IMAGE_TAG` → `local`（真本 `scripts/run-example.sh`）。
两者是同一个值的两个名字：CI 传 `IMAGE_TAG`，本地习惯传 `TAG`；
名字不一致曾导致 6 个用例 job 全红而本地各跑各的都不报错（真实事故，规范 §4.3 留痕）。

**工具链版本**（一律以 `images/versions.env` 为真本，禁止手写字面量）：

| 工具 | 版本来源（真本 `images/versions.env`） |
|---|---|
| g++ | `${GCC_MAJOR}` |
| clang++ / clang-format | `${CLANG_MAJOR}` / `${CLANG_FORMAT_MAJOR}`（必须与 `${CLANG_MAJOR}` 同步，否则「本地 fmt 通过、CI fmt-check 报差异」） |
| cmake | `${CMAKE_MIN_VERSION}` |

**启动后的自检**：镜像内的工具链是否与真本一致，用版本命令核对
（`g++ --version` / `clang++ --version` / `cmake --version`），输出的主版本号应与上表变量相符。

## 2. 目录结构与各文件职责

```text
cpp/
  docs/                     # 本篇与另外四篇指南、知识点清单、用例编写规范
    知识点清单.md           # 用例 ID 清单（练什么的真本）
    用例编写规范.md         # 怎么写用例（验收真本）
    实践指南.md             # G1：什么时候用、怎么验
    开发指南.md             # G2：本篇
    问题指南.md             # G3：按问题域排查
    工具指南.md             # G4：工具与参数速查
    FAQ.md                  # G5：高频短问答
  examples/                 # 77 个用例（L0–L4）
    <ID>/
      run.sh                # 必须存在：自己负责编译与运行，只往 stdout 打业务输出
      expected.txt          # 期望输出：逐行精确，忽略行尾空白与首尾空行
      README.md             # 考点说明
  project/                  # 毕业项目（倒排索引）
```

runner 对每个用例目录强制执行三文件契约（真本 `scripts/run-example.sh` 头注释）：
缺目录报 `MISSING`，缺 `run.sh` 报 `NO-RUNNER`，输出与 `expected.txt` 不一致报 `DIFF`。
新用例的写法以 [用例编写规范.md](用例编写规范.md) 为准；练什么以
[知识点清单.md](知识点清单.md) 的 KP 编号为准（一个 KP 一个用例，不合并不拆分）。

## 3. 一条命令跑通（含失败时先看哪里）

```bash
TAG=latest scripts/run-example.sh cpp L0-hello
# 实测输出：cpp/L0-hello                  PASS (1s)
```

失败时按这个顺序看：

1. **`MISSING(...)` / `NO-RUNNER`**：三文件契约没满足。检查目录名拼写（对照
   [知识点清单.md](知识点清单.md) 的建议用例 ID）与 `run.sh` 是否存在、可执行。
2. **`manifest unknown` / 拉镜像失败**：`TAG` 指向的镜像不存在，或本地还没拉过。
   先 `docker pull "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}"`；更多排查路径见
   [问题指南.md](问题指南.md)「镜像与标签」一节。
3. **`DIFF`**：实际输出与 `expected.txt` 不一致。runner 会并排打印两侧行；
   如果你是故意改了行为，按 [用例编写规范.md](用例编写规范.md) 的流程更新期望文件。
4. 需要进容器手工复现时，给 runner 加 `--keep` 保留容器，再 `docker exec` 进去。

第二个可跑通的进阶例是带构建系统的 `L2-002-cmake-targets`（配置、构建、安装一步到位，
实测 `PASS (1s)`）；L1 单文件例如 `L1-001-references-pointers` 同样一条命令。

## 4. 改动循环：改 → 格式化 → 检查 → 测试 → 提交

```bash
# 1. 改 cpp/ 下的源码或用例（编辑器里完成）
# 2. 就地格式化（唯一真本是 scripts/fmt.sh；clang-format 版本与 ${CLANG_MAJOR} 同步约束见 §1）
make fmt                                # 全部语言
bash scripts/fmt.sh --lang cpp          # 只 C++ 轨道
# 3. 只读检查（CI 跑的就是 --check）
bash scripts/fmt.sh --check --lang cpp
# 4. 跑受影响用例
TAG=latest scripts/run-example.sh cpp L0-hello
# 5. 提交（提交身份须在仓库白名单内，禁止 AI 署名尾巴；CI 的 authors job 会卡）
```

格式化范围注意：`scripts/fmt.sh` 只处理各语言目录下的源码，`scripts/`、`images/`
与用例里的 `run.sh` 不在范围内（真本 `scripts/fmt.sh` 头注释）——它们属于基础设施，
改它们是门禁变更，不是排版变更。本地与 CI 的格式化口径差异的排查见
[问题指南.md](问题指南.md)「格式化与门禁漂移」一节。
