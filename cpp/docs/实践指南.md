# C++ 实践指南（G1）

> 回答「什么时候用哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 本文所有用例命令遵守《知识点清单增强规范》§4.3 命令契约：统一 `TAG=latest scripts/run-example.sh cpp <ID>`；
> 版本号只写 `images/versions.env` 的变量名（版本引用契约见同文 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 C++ 工程能力——从 L1 语言特性、
L2 构建与测试、L3 并发与序列化专题，到 L4 设计模式，共 77 个用例；终点是
`cpp/project` 的毕业项目（倒排索引）。每一层都用「可观察判据」验收：
用例跑通、输出与 `expected.txt` 逐行一致（见 [用例编写规范.md](用例编写规范.md)）。

**什么时候别用本指南**：

- 想学某个语言特性本身（如 SFINAE 推导规则、`constexpr` 语义）——直接跑对应 L1 用例，
  指南不讲语法，读了也学不会；
- 想找某个具体报错的排查路径——去 [问题指南.md](问题指南.md)（G3，按问题域组织）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令：

  ```bash
  grep 'KP-L1-09' cpp/docs/知识点清单.md
  ```

  输出会指向用例 `L1-009-template-constraints`——语法知识点的正主是用例，不是指南。
- 后果：只读不跑，等于没碰过编译器；模板约束写错时编译期诊断不会替你兜底。
  正确动作是 `TAG=latest scripts/run-example.sh cpp L1-009-template-constraints`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（由已解决的 `KI-05` 定案：`hello` 改名并定义 L0 语义），
它验证镜像能编译并运行 C++20，与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh cpp L0-hello
# 实测输出：cpp/L0-hello                  PASS (1s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh cpp L3-002-thread-synchronization
  ```

- 后果（实测）：`docker: Error response from daemon: manifest unknown`，
  runner 以非零退出。通路用例 1 秒就能把这类环境问题暴露出来；
  不验通路时，同样的错误会发生在你等得最久的那一步，且难以与代码 bug 区分。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| 一律经 runner 跑用例 | 手写 `docker run` / `g++` 复刻 runner 的行为 | CI 与本地用同一个 runner（真本 `scripts/run-example.sh`）；口径分裂会造成「本地假绿」（规范 §4.3 记录过 TAG 与 IMAGE_TAG 名字不一致导致 6 个用例 job 全红的真实事故） |
| 镜像 tag 只用 `TAG`/`IMAGE_TAG` 变量传入 | 硬编码镜像 tag 字面量 | `:latest` 可变（ROADMAP `KI-08`）；要可复现用 `sha-<commit>` 标签，PR 只推 sha 标签（历史 bug `#184`） |
| 资源交给 RAII 对象管理（见 `L1-004-raii`） | 手动 `new`/`delete`，且提前 `return` 绕过释放 | 异常与提前返回都会跳过手工释放；实测 LeakSanitizer 立即报泄漏（反例见下） |
| 测试用例默认开启 `assert`（见 `L2-005-test-harness`） | 用 `-DNDEBUG` 构建去跑基于 assert 的测试 | 实测 `-DNDEBUG` 会把断言整个编译掉，测试假绿（详见 [问题指南.md](问题指南.md) 断言失效一节） |
| 构建目录干净、语言标准显式声明（见 `L2-003-reproducible-build`） | 依赖本机默认标准或残留构建产物 | 他人机器上结果不可复现；这是 L2 用例的核心考点 |
| 版本号只引用 `images/versions.env` 变量 | 在文档/脚本里手写版本常量 | 升级时手写常量集体过期，且过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：手动管理数组 + 提前 return**

- 错误做法：

  ```cpp
  #include <cstdio>
  int main() {
    int* p = new int[100];
    p[0] = 1;
    if (p[0] > 0) {
      return 1;          // 错误：跳过了下面的 delete[]
    }
    delete[] p;
    return 0;
  }
  ```

- 复现命令（在本轨道镜像里用 ASan 编译运行；镜像 tag 经变量传入，`REGISTRY` 真本为 `images/versions.env`）：

  ```bash
  docker run --rm "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}" bash -c \
    'g++ -std=c++20 -fsanitize=address /tmp/leak.cpp -o /tmp/leak && /tmp/leak'
  ```

- 后果（实测）：`ERROR: LeakSanitizer: detected memory leaks`、
  `SUMMARY: AddressSanitizer: 400 byte(s) leaked in 1 allocation(s).`，退出码 1。
  换成 `L1-004-raii` 的 RAII 写法（资源与对象生命周期绑定），提前返回与异常路径都会正确释放。

## 4. 真实工作中的变体

**变体 1：本地已自建镜像（`make images` 或 `scripts/build-images.sh`）**
runner 的 `TAG` 默认值是 `local`（真本 `scripts/run-example.sh`：
`TAG="${TAG:-${IMAGE_TAG:-local}}"`），所以本地调试自建镜像时不用传 `TAG`，
或显式 `TAG=local scripts/run-example.sh cpp <ID>`。注意规范 §4.3 的告诫：
`local` 只是本地约定的名字，不要把它写死进任何文档或 CI 配置。

**变体 2：需要可复现的构建结果（对应 `L2-003-reproducible-build` 的工程化延伸）**
`:latest` 随 `main` 变动（`KI-08`），复现某个历史结果时用 CI 每次构建都打的
`sha-<commit>` 标签：`TAG=sha-<commit-sha> scripts/run-example.sh cpp <ID>`。

**变体 3：整轨回归**
改动波及面大（如升级编译器标准、动公共构建配置）时跑全轨 77 例，与 CI 的
`examples` job 同款入口：`TAG=latest scripts/run-example.sh cpp --all`。
并发类用例（如 `L3-002-thread-synchronization`）也在这一步一起验，
不要因为「本地跑过单例」就跳过整轨。

**反例（可执行）**

- 错误做法：并发 PR 都把各自的镜像推成 `:latest` 并互相依赖。
- 复现思路（真实历史 bug `#184`）：两个任务同时跑，A 推的 `:latest` 被 B 覆盖，
  A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」无法区分。
- 可直接观察 tag 风险的命令：

  ```bash
  TAG=nosuchtag scripts/run-example.sh cpp L0-hello   # manifest unknown，实测
  ```

- 后果与修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  本地需要固定版本时同样优先 sha 标签。
