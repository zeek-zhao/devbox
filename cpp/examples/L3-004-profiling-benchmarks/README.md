# L3-004-profiling-benchmarks


## 考点
对应 KP-L3-04：用可复现的基准比较"优化前"和"优化后"，并验证收益是真的。
同一份有序数据上，线性扫描要比较 100 万次，二分查找只要 20 次上下；
看到 `comparison ratio` 和 `timing: linear slower than binary by >100x`，
说明收益既在操作计数上成立，也在实测时间上成立。

## 易错点
把墙钟时间写进期望值会立刻变成不确定输出：耗时受预热、缓存和调度影响。
这里的做法是——操作计数承担精确断言，墙钟只用来确认"确实测了、且差距远超噪声"。
另一类坑是只测一次二分查找：单次约几十纳秒，低于时钟分辨率，
所以脚本对二分重复 1000 次再取单次均值，否则测出来的"0 ns"毫无意义。

## 延伸
把同样的思路用到真实热点上：先用 `perf record` 找瓶颈（本镜像不含 perf，
可在宿主或换镜像做），再针对热点做改动，最后用同一套计数与计时验证收益。
多轮测量时报告分位数而不是单次值，避免把偶发抖动当成优化成果。
