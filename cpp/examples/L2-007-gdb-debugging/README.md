# L2-007-gdb-debugging


## 考点
对应 KP-L2-07：运行脚本在未优化、带调试信息的二进制上设置断点并取得回溯。
看到调用栈依次指出 `report_query_error`、`find_query` 和 `main`，就说明能从错误点追到调用来源。

## 易错点
优化可能内联函数或改变变量、断点位置，因此调试构建使用 `-g` 且不加优化选项。
GDB 地址和路径会随环境变化；脚本归一化地址，只输出稳定的函数名帧。

## 延伸
可以在断点处用 `print` 检查查询值，并对比正常路径与错误路径的调用栈。
再尝试条件断点，定位大型索引中仅特定查询触发的问题。
