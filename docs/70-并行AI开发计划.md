## 0. 一句话模型

**一张卡 = 一个独立完整克隆目录 + 一个 `feat/<issue#>-<slug>` 分支 + 一个 PR。**
批次内各卡只改自己的独占文件 → 可以全部同时拉；批次末用本地总闸
一次性 squash、跑全量、推 `main`（§6）。**并发的敌人从来不是 CPU，是共享文件与合并身份。**

## 2. 并发模型

### 2.1 一卡一环境（硬性）

| 项 | 规定 | 为什么 |
|---|---|---|
| 工作目录 | `~/work/devbox/<issue#>-<slug>/`，**完整克隆** | 每个 AI 拿到独立 `.git` 与工作树；并发 `fetch` / `rebase` 不互相锁。远程/容器里 `git worktree` 的 `.git` 绝对路径常不可达，不作为并发方案 |
| 基线 | 每次从**最新 `origin/main`** 切出，不从别的 PR 分支切 | PR 之间不互相 base，否则合并顺序被绑死 |
| 分支 | `feat/<issue#>-<slug>` | `.githooks/pre-push` 只放行这个形状；直推 `main` 会被拒 |
| PR | 目标 `main`，描述写 `Closes #N`，关联所属里程碑 | 与 [ROADMAP](ROADMAP.md)「Issue ↔ 里程碑对照」的流程一致；无合适里程碑要显式登记 |
| 产出 | **只改本卡的独占文件**（§2.2） | 共享文件是多卡并发唯一真正的冲突源 |
| 类型 | 只有 `docs` / `code` / `bug` 卡派自动化 | `decision` / `needs-human` 一律进人工队列（§7） |

### 2.2 独占文件 / 共享文件（并发能否成立的关键）

[60](60-AI工作指南.md) §3 第 7 步要求每张卡回写 `40` / `41` / `12` / `ROADMAP` / `30`。
若字面照做，八张并发卡会同时改这五份文件，**必定冲突**，且冲突最常发生在 `pre-merge.sh`
默认「不自动解冲突」的那一步。因此本计划把「产出」与「状态回写」拆开：

| 类别 | 文件 | 谁改 / 何时改 |
|---|---|---|
| **独占**（可并发） | `<lang>/docs/*`（每卡一门语言）、`docs/13-通用开发指南.md`、`docs/21-发布工程七域.md`、`docs/20-开发发布增强.md`（仅 `#212`）、`docs/24-G3素材池.md`、`<lang>/project/COVERAGE.md`（`#228` 按轨道拆） | 各卡自己的 PR |
| **共享**（禁止并发改） | `docs/ROADMAP.md`、`docs/30-GitHub现状与时限.md`、`docs/40-问题清单.md`、`docs/41-里程碑拆分.md`、`docs/12-语言指南覆盖矩阵.md` | **批次集成卡**：一批合并完后一张串行 PR 统一回写 |
| **生成物** | `docs/进度看板.html` | 禁止手改；改数据源后跑 `bash scripts/build-repo-board.sh`，CI 校验重新生成后无差异 |
| **门禁** | `scripts/gate-files.txt` 命中的一切（CI / 判定脚本 / Dockerfile / 版本真本 / 钩子 / 格式化配置） | AI 一律不改；`#226` / `#227` 只能人工评审后显式放行 |

四条规则：

- **A**：任务卡 PR 不碰共享文件，`60` §3 的第 7 步由集成卡在批次末尾一次做完（勾 Q → 回写 `41` 状态 → 更新 `12` 格子 → 更新 `30` 快照 → 更新 ROADMAP 的 Issue 表）。
- **B**：某卡确实必须改共享文件（例如 `#216` 要改 `30`）→ 从并发组里摘出来，**串行排在该批最后**。
- **C**：新增表格不要复用「里程碑」作首列表头，且与 ROADMAP 的里程碑表隔着非表格行，否则看板生成器会误认（[60](60-AI工作指南.md) §1）。
- **D**：`docs/*.md` 里以 `verify:` 开头的 HTML 注释标记会被 `check-docs.sh` 逐条真跑；**只标任何环境都该成功的只读命令**，新文档不加无把握的标记。本文故意不写出完整标记，免得自己被扫到。

### 2.3 工程依据：为什么这些 PR 能同时跑

| 依据 | 结论 |
|---|---|
| CI 同仓 PR 只推 `sha-<commit>` 镜像标签，不推 `:latest`（`KI-08` / `#184` 的修复） | 每个 PR 的镜像互不覆盖；这正是并发曾踩过的坑 |
| `ci.yml` 的 `concurrency` 按 `github.ref` 分组，且只在 PR 上 `cancel-in-progress` | 各 PR 独立成组，不会互相取消 |
| `pull_request` 触发全量 33 job；公开仓 Actions 不计量 | 并发 4–8 个 PR 可行；建议**单批上限 8**，超过就分批合并 |
| `pre-merge.sh` 里写明 db 栈 compose 项目名固定 `devbox-db`，会顶掉别的 worktree 正在用的那套 | **db 相关卡串行**：`#197`（M7-07）、`#208`（M8-10）不与彼此、也不与总闸的 db 跑批同时 |
| `check-authors.sh` 同时校验 author **与** committer 邮箱，白名单只有 `zeek.zhao@foxmail.com` | 决定合并方式，见 §6 |

## 5. 单卡 SOP（八步）

1. **认定卡类型**：`decision` / `needs-human` → 不派（§7）；读 [40](40-问题清单.md) §0.1、[41](41-里程碑拆分.md) §8、[60](60-AI工作指南.md) §2。
2. **查硬前置**：本卡所属 GATE 是否已答；`#197` 查 `Q-G-07`，`#228` 查人工判定进度。
3. **独立克隆**到 `~/work/devbox/<issue#>-<slug>/`，不要复用别的卡的目录。
4. **从最新 `origin/main` 建分支** `feat/<issue#>-<slug>`。
5. **只改独占文件**；本地跑对应检查（`bash scripts/check-docs.sh`、`bash scripts/check-board-truth.sh`、
   `bash scripts/coverage-check.sh --strict`、`git diff --check`），文档命令统一写 `TAG=latest`。
6. **提交**：Conventional Commits 标题、身份 `zeek.zhao <zeek.zhao@foxmail.com>`、无 AI 署名尾巴、LF。
7. **推分支 → 开 PR**：`Closes #N` + 里程碑；等 CI 全量绿。
8. **进合并队列**：CI 绿 + 未触碰门禁文件 + 独占文件无冲突 → 交给 §6 的批次总闸。

命令模板（示意，不含任何凭证；派单工具与运行环境由维护者本地提供）：

```bash
git clone https://github.com/zeek-zhao/devbox.git ~/work/devbox/186-general-guide
cd ~/work/devbox/186-general-guide
git switch -c feat/186-general-guide origin/main
# ...只改 docs/13-通用开发指南.md...
git add docs/13-通用开发指南.md
git commit -m "docs: 建通用开发指南（T0 骨架）"
git push -u origin feat/186-general-guide
gh pr create --base main --head feat/186-general-guide \
  --milestone "M6 指南层骨架" --title "docs: 建通用开发指南（T0 骨架）" \
  --body "Closes #186"
```

## 6. 合并纪律（本计划最要紧的一节）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 在网页上点 **Merge / Squash and merge** | GitHub 生成的提交 committer 是 `noreply@github.com`，**不在白名单**；`push main` 时 `check-authors.sh --all` 扫全历史直接判红 | 批次走本地总闸：`bash scripts/pre-merge.sh --branches feat/186-... feat/188-... --push`。脚本用 `zeek.zhao` 身份逐个 `merge --squash` 提交，全量校验通过才推 `main`；随后用 API/CLI 关闭 PR 并留评论说明由哪个 commit 合入 |
| 任务卡自己 `git push origin main` | `.githooks/pre-push` 拒绝；`DEVBOX_ALLOW_MAIN_PUSH=1` 是留给总闸与维护者单分支直推的例外 | 任务卡只推 `feat/*`；合批交给总闸，维护者直推前先确认身份与门禁 |
| 顺手改门禁文件里的过时注释 | `check-gate-files.sh` 拒绝合批 | `#226` / `#227` 由人改、人审，确需合批时显式 `--allow-gate-change` 并在 PR 写明为什么改判定标准 |
| 多卡同改 `40` / `41` / `12` / `ROADMAP` | 合批冲突；`pre-merge.sh` 默认停下来不解 | §2.2 规则 A：集成卡一次回写。**不要用 `--auto-resolve` 蒙过去**——历史上自动取 ours 曾静默把 77 条用例退回成骨架还全绿 |
