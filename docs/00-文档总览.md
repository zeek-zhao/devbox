## 1. 这一轮要解决的问题

现有工程已经把「语法 + 工程 + 用例」做得很扎实（9 轨道 / 794 例，含 E 类错误处理 135 例（9 轨 × 15）/ `v0.1.0`），
但每门语言的 `<lang>/docs/知识点清单.md` 只是 **L1–L4 用例 ID 的清单**，
回答的是「要练哪些点」，不回答：

- 真实工作里这个知识点**什么时候用、为什么用、不用会怎样**
- 遇到问题时**怎么定位、用哪个工具、看什么信号**
- 从写完代码到**能发布、能回滚、能被别人接手**，中间还差什么

参考 `D:\zeek\work\repo\sample\` 的指南体系（完全指南 / 开发指南 / 最佳实践 /
问题指南 / 调试技术与工具 / FAQ / 维护指南 / 用户指南），结合公开工程方法论，
本轮补齐**指南层**与**问题层**，并把优化点整理成问题清单与里程碑拆分，
另产一份给接手 AI 的协作规范。

## 5. 边界声明

- **只写文档**：不新增用例、不改 Dockerfile、不改 CI、不改 `<lang>/docs/知识点清单.md`。
  所有「要补什么」以编号条目落在 [40-问题清单](40-问题清单.md)，拍板后再实施。

  命令一律以本工程 `images/versions.env` 与实际脚本为准。
- **不改门禁文件**：`scripts/gate-files.txt` 列出的文件（含 CI、判定实现、Dockerfile、
  格式化配置）AI 不许自己改；里面过时的注释只登记、不顺手改，见 `Q-S-07` / `Q-S-08`。
- **公开仓纪律**：旧笔记含内部主机信息与流程细节，不随仓库分发；
  [60-AI工作指南](60-AI工作指南.md) 是脱敏后的协作规范，
  与维护者本地那份含凭证的会话交接单**内容不互相搬运**，见 [50](50-迁移对照与取舍.md)。
- **状态诚实**：`draft` 不写成已完成；「规划」不写成「已有」；远端未执行的动作
