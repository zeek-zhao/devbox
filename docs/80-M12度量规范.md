# M12 度量规范（四指标与 m12-traces schema）

> 对应任务卡 `M12-W2-01`（#275）。M12 六卡分工见 [ROADMAP](ROADMAP.md) 与
> [73-M11并发执行计划](73-M11并发执行计划.md) §12。本文定三件事：**只报哪 4 个指标**（§3）、
> 结构化留痕 `metrics/m12-traces/<run-id>.json` 的最小 schema（§2）、golden set 怎么回放（§4）。
> 落盘格式的操作版同见 `metrics/m12-traces/README.md`（与本卡独占文件成对）。
> 度量纪律与 [24-G3素材池](24-G3素材池.md) 一致：**数字只许来自可复跑的证据，禁止编造与估算占位。**

## 1. 度量原则（先于指标）

1. **只报 4 个指标**：M12 的正式报告只含 §3 的 M-1 到 M-4，其余探索性统计不进报告、不进看板；
2. **能用规则判的不交给主观判断**（[73](73-M11并发执行计划.md) §6）：每个数字必须附计算公式与数据出处；
3. **拿不到的数据一律写 `UNVERIFIED`，不许填 0**（§6）：0 是「测到了且为零」，`UNVERIFIED` 是
   「没测到」——用 0 占位会把 flake rate 与 cost 系统性拉低，制造「质量在变好」的假象；
4. 不改门禁文件：本文只定口径，度量不新增 CI 步骤；实现动作（如镜像源退避）归 `#264`。

## 2. trace schema：`metrics/m12-traces/<run-id>.json`

与 M11 verifier 的 `metrics/m11-traces/<run-id>.json` **同构**（[73](73-M11并发执行计划.md) §6 结构化留痕行：
spec 版本 / 模型与会话 / 命令与退出码 / 断言 / `UNVERIFIED` 项），在其五要素之上补
`rubric_version`、`classification`、`reviewed_at` 三个字段。文件名即 `run_id`（一 run 一文件）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `spec_version` | string | 任务卡规范版本，如 `v2`（[71-任务卡规范v2](71-任务卡规范v2.md)） |
| `rubric_version` | string | verifier rubric 版本号（§5 校准版本化），如 `m12-rubric-1` |
| `model` | string | 执行模型的标识；不可得写 `UNVERIFIED` |
| `session_id` | string | 会话标识（与 provider usage 记录对账的键）；不可得写 `UNVERIFIED` |
| `run_id` | string | 运行标识，等于文件名去 `.json`；CI run 或本地会话编号均可 |
| `head_sha` | string | 40 位 commit sha |
| `commands` | array of object | 元素形如 `{"cmd": string, "exit_code": number}`，只录真跑过的命令 |
| `assertions` | array of string | 每条断言对应一条验收判据（verifier 规则层的证据行） |
| `classification` | string | 本 run 的结论：`pass` / `fail` / `revise` / `escalate` / `UNVERIFIED` |
| `unverified` | array of string | 所有 `UNVERIFIED` 项的字段名与原因清单，无则空数组 |
| `owner` | string | 答案归属，格式 `名字 <邮箱>`（[75-文档健康规范](75-文档健康规范.md) §1） |
| `reviewed_at` | string | 最近复核日期 `YYYY-MM-DD`；未复核写 `UNVERIFIED` |

完整示例与落盘规则见 `metrics/m12-traces/README.md`。两条硬纪律与 [71](71-任务卡规范v2.md) §6 一致：
没跑过的一律写 `UNVERIFIED`，不许写「已验证」；`commands` 只录真跑的命令，不录「打算跑」的。

## 3. 四个指标（定义 / 公式 / 数据出处）

### M-1 flake rate（含三分类分布）

- **公式**：`flake rate = 首次结论为 infra_transient 的运行数 / 观察窗口内 push 触发的 CI 运行数`；
  报告必须同时附三分类分布（`infra_transient` / `real_regression` / `flaky_test` 各自的运行数）。
- **口径出处**：失败三分类与 flake rate 口径以 [78-CI失败分类规范](78-CI失败分类规范.md)（#272，同批先行合并）
  为**唯一真本**，本文只引用不复制全文——分母、分子、rerun 语义（rerun 通过 ≠ flaky 也 ≠ 稳定）
  均以其 §3 为准；若 `origin/main` 尚无 docs/78，以其 PR 分支文本为准，合并后自动生效。
- **数据出处**：GitHub Actions run 列表（按 `event=pull_request`→push 触发过滤窗口内 run）+
  各失败 run 的取证评论（首个实例为 run `42009114733`，取证链见 [73](73-M11并发执行计划.md) §9）。

### M-2 verifier↔人工关键子集一致率（附假通过 / 假拒绝）

- **公式**：`一致率 = 结论一致卡数 / 关键子集卡数`；同时单独报两个计数——
  **假通过数**（verifier 判 `pass` 而人工复判 `fail` / `revise`）与
  **假拒绝数**（verifier 判 `fail` / `revise` 而人工复判 `pass`）。
- **抽样**：从 verifier 已出结论的卡中抽关键子集，每批 ≥10% 且 ≥3 张（取大者）；子集构成写进报告。
- **数据出处**：verifier 报告的结构化结论列（[73](73-M11并发执行计划.md) §6）+ 维护者复判留痕（卡评论 / PR 描述）。
- **判读**：假通过比假拒绝危险——假拒绝只浪费一次返工，假通过会让坏产物进 `main`；一致率相同而
  假通过数更高的 rubric 变体应判劣。

### M-3 intervention-free completion

- **公式**：`无人干预完成卡数 / 观察窗口内派出的卡数`（分母含被摘出并发组、被 stop rule 打断的卡）。
- **「无人干预」判据**：从派单到合并，全程无 stop rule 触发、无 `Q-*` 问答、无人工修正提交；
  三者任一出现即计为「有干预」。
- **数据出处**：各卡 PR 描述的 execution trace 六字段（[71](71-任务卡规范v2.md) §6）与卡评论时间线；
  卡失败原因按 [78](78-CI失败分类规范.md)（#272）§7 的卡失败三分类（spec 不清 / 环境抖动 / 真实缺陷）
  归类附报——M11 的 19 张卡结果解读同样复用该口径。

### M-4 cost per accepted card

- **公式**：`Σ(accepted 卡的运行成本) / accepted 卡数`；accepted = PR 合入 `main` 且验收判据逐条有证据。
  同一卡多轮 run（含返工轮次）的成本累计到这张卡，**不许只算最后一轮**。
- **数据出处**：模型 provider 的 usage / 账单记录，按 `session_id` 归属到卡；
  **会话级成本拿不到时，本指标整项写 `UNVERIFIED`，不许用 0 或估算值占位**（§6）。

## 5. rubric 校准版本化

- **版本号**：rubric 判据文本或分值锚点一变即升版本，从 `m12-rubric-1` 起；版本号写进每条 trace 的
  `rubric_version` 字段，历史 trace 不回改；
- **触发重校准的两个条件**（任一发生即重跑）：**换模型**、**改判据**；
- **重校准动作**：抽 10%（至少 3 份）已判卷样本交维护者人工复判，登记**校准日期**与**一致性结论**
  （一致率、假通过数、假拒绝数）到卡评论；新版本号与校准结论写进当批 trace；
- **不触发不校准**：模型与判据都没动时 rubric_version 不变，不重复校准，避免校准本身变成形式。

## 6. UNVERIFIED 纪律：拿不到就不填 0

- 每个指标报告必须带「数据出处 + 截止时可取到的值」；取不到时在对应 trace 的 `unverified[]`
  里登记字段名与原因，报告正文同项写 `UNVERIFIED`；
- 典型场景：cost 数据源未接入 → M-4 整项 `UNVERIFIED`；会话标识缺失 → 该 trace 的
  `session_id` 写 `UNVERIFIED`；
- `UNVERIFIED` 不算失败，但**连续两个观察窗口仍 `UNVERIFIED`** 的指标必须在报告里附补数计划
  （谁接数据源、什么时候接）；
- 禁止的占位写法：`0`（伪装成测到了）、`约` / `估计`（估算值）、复制上一窗口的旧值
  （同 [75-文档健康规范](75-文档健康规范.md) §1「不抄旧值」）。

## 8. E 类示例执行留痕（trace 的可选扩展块，`e_example`）

> 对应任务卡 `M12-M-02`（#344）。E 类示例（`<track>/examples/E-*`，9 轨 × 15）回放时，
> 在 §2 的 trace JSON 上**追加一个可选顶层块 `e_example`**。设计约束：

- **向后兼容**：`e_example` 是可选字段——不含它的既有 trace（M11 六例 golden set 回放、
  文档卡判定等）依然是合法 §2 schema；读取方必须容忍缺失；
- **版本化**：带 `e_example` 的 trace 其 `rubric_version` 需 ≥ `m12-rubric-1` 且
  `spec_version` 写 `v2`；新增必填字段才升版本，本扩展不升；
- **与 CI 三分类对齐**：`e_example.verdict` 的枚举与取值语义同 [78](78-CI失败分类规范.md)
  三分类（`scripts/classify-ci-failure.sh` 的输出枚举），E 例 FAIL 时该 run 的
  `ci_failure` 分类结论必须能放进同一份报告而不自相矛盾。

### 8.1 `e_example` 字段表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `track` | string | 是 | 轨道名：`c/cpp/go/java/python/rust/shell/vue/db` 之一 |
| `example_id` | string | 是 | E 类目录名，如 `E-005-error-identity`（轨内唯一；跨轨同名 slug 是既定设计） |
| `category` | string | 是 | `E-` 后三位编号，如 `E-005`；对应「错误码与错误结构」等 15 个类别 |
| `model` | string | 是 | 所属错误处理模型：`errors-as-values` / `exceptions` / `result-algebra` / `effect-system`（[81-错误处理四模型与分类法](81-错误处理四模型与分类法.md) §2.5 对照表） |
| `replay_cmd` | string | 是 | 回放命令，契约 `TAG=latest scripts/run-example.sh <track> <ID>` |
| `verdict` | string | 是 | `pass` / `infra_transient` / `real_regression` / `flaky_test` / `UNVERIFIED`（语义同 [78](78-CI失败分类规范.md)） |
| `assert_results` | array of object | 是 | 元素形如 `{"assert": string, "pass": boolean}`；断言行取自 expected.txt / 清单判据列，逐条判 |
| `coverage` | string | 是 | `covered` / `pending` / `exempt`（[coverage-check.sh](../scripts/coverage-check.sh) 词表；E 类现全部 exempt） |
| `troubleshoot_ref` | string | 否 | 关联排查命令锚点，如 `<track>/docs/排查手册.md §2.5`；该轨无对应节可省略 |

### 8.3 校验命令

```bash
python3 -c "import json; d=json.load(open('<trace>.json')); \
  e=d['e_example']; assert e['verdict'] in ('pass','infra_transient','real_regression','flaky_test','UNVERIFIED'); \
  assert e['coverage'] in ('covered','pending','exempt'); \
  assert all(set(a)=={'assert','pass'} for a in e['assert_results'])"
```

### 8.4 与 golden set 的衔接

六例 E 类 golden set 回放（§9）每例落一份带 `e_example` 块的 trace；
`model` 字段的取值逐例对齐 [81](81-错误处理四模型与分类法.md) §2.5 九轨对照表。
