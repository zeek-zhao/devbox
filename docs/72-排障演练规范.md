## 1. 目录契约

```text
<lang>/examples/T-NNN-<slug>/
  run.sh          # 演练入口：依次调用至少两种工具（如 ASan / valgrind / gdb batch），串起全流程
  repro.sh        # 最小复现：稳定复现一次故障（编译有缺陷版本 + 触发），供重复演练与 CI 真跑
  assert.sh       # 断言：命中关键诊断行 + 退出码符合预期；连跑两次结论一致
  WALKTHROUGH.md  # 逐行判读文档（结构见 §4）
  challenge/      # faded 挑战档（可选目录，见 §4.3）：只给症状与工具，不给答案
```

- `T-NNN` 按轨道独立编号（`<lang>/examples/T-001-<slug>/` 各轨道自己的命名空间，不跨轨道共号）；
- **2026-11-12 起演练计入 `examples/` 目录计数：804 = 存量 659 + E 类 135 + 演练 10**。
  看板按 `<lang>/examples/` 直接子目录计数（[73](73-M11并发执行计划.md) §4 的「不计入」硬约束已由 #390 翻转取代），
  `docs/board-tracks.tsv` 增列 `shared` 轨（该轨无毕业项目，不增加毕业项目数，仍为 9）；
- **演练不是用例 runner 的比对对象**：`scripts/run-example.sh` 与 `db/scripts/run-example.sh` 的
  `--all` 枚举显式跳过 `T-*` 前缀（判定不放宽：普通用例仍逐个全跑；演练输出含地址/PID，
  按 §2 禁止逐字比对，故不适用 expected.txt 契约）；演练由 `.github/workflows/ci.yml`
  的 `labs` job 按 `*/examples/T-*/run.sh` 独占真跑；
- 每个演练目录必须带 `README.md`，含非空 `coverage: exempt` 理由——毕业项目 COVERAGE
  覆盖口径不适用于演练，`coverage-check.sh` 据此把演练判为豁免而非「未声明」；
- lab 产物（崩溃 core、日志）只写在容器/临时目录，不入库；入库的只有四文件（+ challenge/ + README.md）。

## 2. 断言方式

**允许**：关键诊断行匹配 + 退出码。例如命中 `ERROR: AddressSanitizer`、`definitely lost`、
`all goroutines are asleep - deadlock!` 这类**稳定出现**的诊断串。

**禁止**：逐字比对整段输出——地址、PID、耗时、路径在两次运行间必然不同，
逐字比对是「假失败」制造机。

最小 `assert.sh` 样板（真本，各 lab 照此扩展，不引外部依赖）：

```bash
#!/usr/bin/env bash
# 断言：关键诊断行命中 + 退出码符合预期。用法：bash assert.sh
set -uo pipefail
cd "$(dirname "$0")"

out="$(bash repro.sh 2>&1)"; rc=$?

fail=0
grep -q 'ERROR: AddressSanitizer' <<<"$out" || { echo "[assert] 未命中 ASan 诊断行"; fail=1; }
[ "$rc" -ne 0 ] || { echo "[assert] 预期非零退出码，实际 0（故障未被触发）"; fail=1; }

# 不稳定输出必须先归一化再断言（地址/PID/耗时 → 占位符）
norm="$(sed -E 's/0x[0-9a-f]+/0xADDR/g; s/pid [0-9]+/pid N/g' <<<"$out")"
[ -n "$norm" ] || fail=1

[ "$fail" = 0 ] && echo "ASSERT-PASS" || { echo "ASSERT-FAIL"; exit 1; }
```

- 断言失败必须让 `assert.sh` 退出非零——**lab 会被 W3 的 labs job 真跑，失败即红**；
- 退出码语义：`0` = 演练流程与断言全部符合预期；非零 = 复现失败或断言未命中（都是红的，不许吞）。

## 3. 素材纪律

与 [24-G3素材池](24-G3素材池.md) 完全一致，`S-NN` 编号直接引用：

1. **仓库已登记的已知问题**（ROADMAP `KI-*`、历史 issue）；
2. **可复现实验**：在对应镜像里人为构造，记录复现命令与真实报错；
3. **口径不一致**（文档与代码漂移）。

- WALKTHROUGH 里每个现象标注 `来源：S-NN`（或「类型②实验」+ 复现命令）；
- 禁止编造「典型现象」；工具在镜像里不存在或输出无法稳定断言 → 停，登记 `UNVERIFIED`，
  交维护者决定是否改选题（[73](73-M11并发执行计划.md) §5 stop rules）。

## 4. WALKTHROUGH.md 必含字段

### 4.1 固定结构

| 字段 | 要求 |
|---|---|
| 触发症状 | 可观察的现象（命令 + 输出片段），不写「程序出错了」 |
| 前 60 秒三条只读检查 | 成本从低到高；每条给「健康时看到什么 / 异常时看到什么」对照 |
| 互斥决策树 | 每个分叉是二选一，无死分支、无循环；指向下一步命令 |
| 逐行判读 | 对真实输出逐段解释：这行说明什么、下一步看哪 |
| 改动后验证 | 修复后跑什么确认修好（健康对照 + 断言转绿） |
| 停止 / 升级条件 | 哪些情况停下来交维护者（对齐 [73](73-M11并发执行计划.md) §5 stop rules） |
| `last verified` + `UNVERIFIED` 表 | 真跑日期；没验到的条目逐条列（判据 → 原因 → 谁来补验） |

### 4.2 D1 拍板：认知学徒双层

- **1 个 predict–observe–explain 点**：先让学习者书面预测输出 → 跑命令 → 解释落差；
- **至少 2 条「被否决的假设」**：把专家的排除过程写出来（假设 X → 看到什么就该信 X →
  实际看到 Y → 排除），不只给答案。

### 4.3 D1 拍板：faded 挑战档

`challenge/` 目录：只给触发症状与可用工具清单，**不给判读**；学习者按 §4.1 结构自己写一遍，
再与上层 WALKTHROUGH 对照。每轨道仍只做 1 个 lab，不扩到三档。

## 5. 与 CI 的关系

- 本轮 lab 的 CI 真跑由 W3 人工批次实现（`ci.yml` 增 `labs` job，[73](73-M11并发执行计划.md) §3）；
  在那之前，lab 的「真跑」证据由 verifier 手跑并贴进 `docs/74` 报告，**不假装有 CI**；
- lab 落盘前不加 `verify:` HTML 注释标记（会被 `check-docs.sh` 真跑）；
- 失败升级：同一验证命令连续两次失败 → 停，交维护者（[73](73-M11并发执行计划.md) §5）。
