## 2. 判定松紧不变的举证

**三条结构性保证：**

1. **既有 11 个 job 的 `runs-on` 与 step 名集合零变更**——只在三个 job 的**尾部追加**
   `if: failure()` 的收尾 step，失败路径多一个取证步骤，成功路径多一个 `skipped`，
   **job 结论不变**。
2. **新增 2 个 job 不参与依赖图**——无 `needs:` 指向别人、也不被别人 `needs:`，
   它们红了只红自己，不会因为「没跑」而把别的 job 连带判红或判绿。
3. **没有一处阈值被改**——`examples` 的 `--all`、`examples-db` 的目录总数守卫、
   `labs` 的 `[ "$fail" = 0 ] || exit 1`、`static` 的各条校验，逐行未动。

## 3. 跳过的两项：理由留档

### §3 `paths:` 过滤——跳过

`paths:` 的作用是「只改了某类文件就只跑相关 job」，本质是**省 runner**。
但本仓库最近若干批提交都是**「文档 + 脚本」混合**（例如 `#390` 同时改 `docs/*.md`
与 `scripts/run-example.sh`），一旦按 `paths` 过滤，`examples` / `labs` 这类
**真正会被脚本改动影响**的 job 反而会被跳过——**该跑的没跑**。

代价对比：省下来的是 runner 分钟（本仓库并发压力低，评分不计），
换来的是「脚本改了但用例没跑」的风险（一旦漏掉就是 `real_regression` 逃逸）。
**收益 << 风险，跳过。**

### §5 `concurrency` 扩到 push——跳过

扩到 push 的效果是「连续推 main 时取消前一个 run」。后果是我们这种
**A→B→C 串行推 main** 的节奏里，B 一推就把 A 的 run 取消，**A 的 CI 结论永远看不到**，
等于把「每批都验证」变成「只看最后一批」。

代价对比：省的是 runner 排队时间；换来的是**中间批次的验证结论丢失**。
与 [78](78-CI失败分类规范.md) §2.2「不得用重跑掩盖」同一精神——**不能为了省资源
而让结论不可见**。**跳过**，维持只在 `pull_request` 上取消。

## 4. 首次失败归类实证（docs/78 三分类首次应用）

「新门 + 老故障」的组合是否按规范处理。

| 项 | 值 |
|---|---|
| run | 43181723313（head `d0ff2d5`，`#341` 本体） |
| 失败 job | `examples-db` / 用例-db（job id 131059060562） |
| 失败用例 | 4 个：`E-001-conn-fail-retry`、`E-002-constraint-catch`、`E-003-deadlock-retry`、`E-004-rollback-savepoint` |
| 命中信号（原文） | `mysql Error Head "https://docker.m.daocloud.io/v2/library/mysql/manifests/8.4": ... net/http: TLS handshake timeout` |
| | `mongodb Error Head "https://docker.m.daocloud.io/v2/library/mongo/manifests/7": net/http: TLS handshake timeout` |
| | 另有 `Error response from daemon: received unexpected HTTP status: 500 Internal Server Error` |
| 机器分类 | `bash scripts/classify-ci-failure.sh` → `classification = infra_transient`，`signals.infra` 命中 7 行、`signals.code` 0 行 |

- artifact 上传成功（`Artifact ci-fail-43181723313-examples-db has been successfully uploaded! Final size is 207981 bytes`）

> 按 [78](78-CI失败分类规范.md) §2.2，**首次结论是 `failure`，重试转绿不折叠**。

## 5. 新门自身会不会误伤

两个新 job 都是**单 step、零依赖、只读**，误伤风险来自它们校验的产物本身。

| 风险 | 实际检查 |
|---|---|
| `docs-index` 误伤 | 只校验不生成；索引漂移时提示「本地跑 `bash scripts/build-doc-index.sh` 后提交」，不会让人无从下手。**已知摩擦点**：任何人改了 `docs/` 下带索引的文档而忘记重生成，这个 job 就会红——这是**设计意图**（`#339` 契约），不是 bug |
| `check-error-examples` 误伤 | 只校验 `E-0xx-*` 目录名与 README 的 `coverage: exempt` 理由非空；脚本零依赖（bash + coreutils），不装包、不联网 |
| 两者是否拖慢流水线 | 各 1 step、均在 `ubuntu-24.04` 上跑纯 bash，实际耗时在秒级；与 `static` 同类，不进 `needs:` 链条，不影响关键路径 |
