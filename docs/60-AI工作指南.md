# AI 工作指南

> **读者**：接手本仓库的 AI，以及派单给它的人。
> **目的**：读完这一篇就能按仓库既有规矩工作，不必重踩一遍坑。
> **边界**：本文是**公开的协作规范**。含主机、账号、凭证、逐日流水账的维护者
> 会话交接单属于本地私有笔记，不随仓库分发（见 [ROADMAP](ROADMAP.md) 文末）。
> 二者分工：**私有单记「在哪台机器、用哪个账号、哪次踩了坑」，本文记「规矩」。**

## 0. 开工前必读（5 分钟）

按这个顺序读，不要跳：

```
README.md
  → docs/ROADMAP.md          现状 / 下一步 / Issue↔里程碑 / KI 已知限制 / 时限
  → docs/01-镜像体系.md      分层与 tag 口径
  → docs/02-流水线.md        触发范围、门禁、本地总闸
  → docs/40-问题清单.md      当前有哪些待办与已定案结论
  → docs/41-里程碑拆分.md    现在在哪个里程碑、卡怎么派
  → 本文
  → docs/70-并行AI开发计划.md  多卡并发时先划独占目录与分支
```

**一句话现状**：`v0.1.0`，9 轨道 / 659 例 / M0–M5 + L4 + OSS 全部完成；
当前推进 M6–M10 的**学习维度与指南体系增强**，其中已定案的一轮
**只优化文档、不做对应实现**。

## 1. 单一真本（写任何东西之前先认）

| 内容 | 唯一真本 | 禁止 |
|---|---|---|
| 项目版本 / 依赖版本 | `VERSION` / `images/versions.env` | 文档里写死版本常量 |
| 语言 ↔ 镜像层 | `images/lang-images.tsv` | 凭印象推镜像名 |
| 体积预算 | `images/budgets.tsv` | 只在文档里改预算 |
| 用例 ID | `<lang>/examples/<ID>/` 与 `<lang>/docs/知识点清单.md` | 指南里编造 ID |
| 覆盖判定 | `<lang>/project/COVERAGE.md` + `coverage-check.sh --strict` | 把「豁免」记成「已接入」 |
| 里程碑 | `ROADMAP.md`「已完成里程碑」表 | 另起一份里程碑清单 |
| 已知问题 | `ROADMAP.md` 的 `KI-*` 段（编号不复用） | 建一个永远开着的噪音 issue |
| 优化提案 | [40](40-问题清单.md) 的 `Q-*` 编号 | 同一问题重复编号 |
| 门禁范围 | `scripts/gate-files.txt` | 自己从清单里删条目 |

> `ROADMAP.md` 的里程碑表同时是 `scripts/build-repo-board.sh` 的数据源：
> 表头首列为「里程碑」、固定 5 列、不许空列。**新增任何表格都不得复用这个表头**，
> 且必须与它隔着非表格行，否则会被生成器误当成里程碑行（生成器宁可报错也不静默降级）。

## 2. 门禁与禁区（最重要的一节）

`scripts/gate-files.txt` 列出的文件，**AI 不许自己改**。清单开头的理由值得原样记住：

> AI 可以同时改「判定标准」和「被测对象」。CI 全绿本身不构成放行证据——
> 它完全可以把门禁改松再顺利通过。

分组速记：

| 组 | 典型文件 |
|---|---|
| CI 定义 | `.github/workflows/*.yml` |
| 判定实现 | `run-example.sh` / `coverage-check.sh` / `check-version-truth.sh` / `pre-merge.sh` / `check-authors.sh` / `check-docs.sh` / `check-board-truth.sh` / `build-repo-board.sh` / `fmt.sh` |
| 清单自己 | `scripts/gate-files.txt`（防止「把清单删空」） |
| 版本与预算真本 | `VERSION` / `images/versions.env` / `images/budgets.tsv` / `budget-check.sh` |
| 被测环境 | `images/scripts/*.sh` / `images/*/Dockerfile` / `images/lang-images.tsv` |
| 身份与格式 | `.githooks/*` / `.github/authors-allowlist.txt` / `.gitattributes` / `.gitignore` / 各格式化配置 |

**身份约束**（`scripts/check-authors.sh`）：author 与 committer 邮箱须在白名单、
提交信息里不许有 AI 署名尾巴。外部 fork 的 PR 只查署名尾巴、身份仅告警
（开源惯例：不能把外部贡献者署名改成维护者）。

**本地钩子**：`.githooks/commit-msg` / `pre-push`。`scripts/pre-merge.sh` 是本地总闸，
跑的东西与 CI 等价，默认**不自动解冲突**。别用 `--no-verify` 绕钩子——绕过去 CI 一样红。

> 确需改门禁文件：人工评审后显式放行，PR 里必须写明「为什么改判定标准」。
> 这是例外，不是流程。

## 3. 一次改动的完整动线

1. **查编号**：[40](40-问题清单.md) 里有没有这条问题；没有就先分配 `Q-*` 编号（不复用）。
2. **查归属**：[41](41-里程碑拆分.md) 里属于哪个里程碑、哪张卡、进入条件是否满足。
3. **查禁区**：改动文件是否命中 `gate-files.txt` → 命中就**停**，转人工。
4. **动手**：按 [70](70-并行AI开发计划.md) 建独占目录与 `feat/<issue#>-<slug>` 分支 → 改 → 本地跑对应 `check-*.sh` / `pre-merge.sh`。
5. **提 PR**：描述里 `Closes #N`；按 `ROADMAP.md` 的「Issue ↔ 里程碑对照」流程
   关联里程碑，**没有合适里程碑就显式写「未分配里程碑」并登记**，不许悄悄挂着。
6. **验收**：CI 全绿 ≠ 放行。硬关口（C6–C9）要人工检验；
   `needs-human` / `decision` 类卡不派给自动化。
7. **回写**（最容易漏）：勾掉 `40` 的 Q → 回写 `41` 状态表 → 更新
   [12-语言指南覆盖矩阵](12-语言指南覆盖矩阵.md) 的格子 → 远端状态变了就更新
   [30-GitHub现状与时限](30-GitHub现状与时限.md) 的快照日期 → 更新 ROADMAP 的 Issue 表。
8. **交接**：按 §7 收尾。

## 4. 任务卡规范

一张卡至少要有：编号、类型、里程碑、**可判定的验收判据**、关联的问题编号。

| 字段 | 取值 | 决定什么 |
|---|---|---|
| `type` | `docs` / `code` / `bug` / `decision` / `needs-human` | 后两类**不派自动化**；前三类可派 |
| `milestone` | M6–M10 或 `v0.2.0` | 归到 ROADMAP 的对照表 |
| `dimension` | D1–D8（见 [10](10-多维度学习模型.md)） | 避免只堆语法类卡 |
| `level` | P0–P4 | 验收按能力刻度，不按篇幅 |
| `verify` | 一条能跑的命令 / 一条人工判据 | 没有它就不叫卡 |

**模型与算力选择原则**：按卡的 `type` 与规模分档，轻量档给格式/清单类，
均衡档给文档起草，深度档给需要跨文件推理的设计类；命令行指定 > 卡内标注 >
标签 > 默认。**不要给所有卡用最重档**，也不要让轻量卡承担价值取舍。
（具体派单工具与凭证属维护者本地环境，不写进公开仓。）

**反例**：「补充 C++ 实践指南，内容完整」——不合格。
「产出 `cpp/docs/实践指南.md`，frontmatter 七字段齐，引用 ≥1 个真实 L2 用例 ID，
G2 一条命令在 `devbox-cpp` 里真跑过」——合格。

## 5. 常见坑（本仓库真实踩过，已脱敏）

| # | 现象 | 根因 | 预防 |
|---|---|---|---|
| 1 | 6 个用例 job 全红，本地却各自「正常」 | runner 读 `TAG`、CI 传 `IMAGE_TAG`，一个变量两个名字 | 新增环境变量先在 runner 与 workflow 对一次名字；指南里的命令统一写 `TAG=latest scripts/run-example.sh <track> <ID>` |
| 2 | CI 长期全绿但用例根本没跑 | 「镜像可用性」探测在软开关下只 warning 并跳过用例，是**假绿** | 任何「探测不到就跳过」的分支都要能报红或显式记录 |
| 3 | 拉不到镜像 / 复现不了旧结果 | 缺少不可变 tag；`:latest` 随 main 变，PR 只推 sha（KI-08） | 可复现一律用 sha tag；写文档时别默认省略 tag |
| 4 | 门禁被悄悄改松还全绿 | 判定标准与被测对象一起改 | §2，命中 gate-files 即停 |
| 5 | 文档里的命令悄悄失效 | make 目标改名、版本号写死 | `check-version-truth.sh`；`check-docs.sh` 的 HTML 注释命令标记（只标任何环境都该成功的只读命令） |
| 6 | 按代码注释写文档，结论与实际相反 | 注释陈旧：`images/runtime/Dockerfile` 注释写 `python3-minimal`，实际 apt 装 `python3` | **以代码为准，不抄注释**；`Q-S-08` / `#227` 已按 `not_planned` 关闭，改注释转出 M11 `#264` 人工批次（门禁文件 AI 不改） |
| 7 | 数字口径到处不一致 | 曾同时存在 608 / 659 两种用例数 | 以磁盘实测为准（`*/examples/*/run.sh`）；门禁文件注释里的残留单独登记，别顺手改门禁 |
| 8 | 提交在 Linux 上整片失效 | CRLF、可执行位丢失、非 ASCII 路径 | 看 `.gitattributes`；脚本可执行位用 git 索引设置；提交前 `git diff --check` |
| 9 | 生成物被手改后 CI 红 | `docs/进度看板.html` 是生成物且入库 | 改数据源（`board-tracks.tsv` / ROADMAP 里程碑表）或生成器，别改 HTML |
| 10 | 中文文档混入异常字符 | 复制粘贴污染 | 写完扫一遍非预期字符集 |
| 11 | 「规划中」被写成「已完成」 | 状态诚实纪律没守住 | `draft` 只能在有明确判据并验收后改 `reviewed` / `verified` |

## 6. 什么时候必须停下来问人

- 改动命中 `gate-files.txt`；
- 判据需要**价值取舍**（`decision`）：例如 L4 强制接入后的例外判定（`#179` 已定案 B，
  但「哪些模式天然适合项目」仍需人工逐条判，见 ROADMAP「下一步」§2）；
- 判据涉及**教学质量 / 覆盖落点是否真实**（`needs-human`，如 `#178`）；
- 边界想「带条件通过」——旧纪律明确**不许**，要么过要么不过，不含糊挂着；
- 需要写远端配置（设 `due_on`、建里程碑对象、关 issue）而当前任务范围只是文档；
- 公开仓内容里出现内网地址、内部主机、账号或凭证。

> 停下来不等于停工：把问题按 `Q-*` 编号记进 [40](40-问题清单.md)、写清推荐答案，
> 其他不依赖它的卡照常并行（「关键卡进人工队列，不阻塞自动化」）。

## 7. 交接协议

**会话开始**：读 §0 的顺序 + `40` §0.1 的拍板结论 + `41` §8 的状态表，
确认当前处在哪个里程碑、哪些卡是 `needs-human`。

**会话结束**，四件事：

1. 完成 §3 第 7 步的四处回写；
2. 明确写出「已完成 / 未完成 / 待人工」三栏，未完成的写清卡在哪；
3. **不把本地私有路径、账号、token 写进仓库任何文件**——公开仓历史已清洗过，别再污染；
4. 远端状态有变（issue 开关、里程碑、时限）就更新 [30](30-GitHub现状与时限.md) 的快照日期。

**私有交接单与本文的分工**：换 AI 时，维护者本地那份含环境与凭证的交接单
继续在私有笔记里维护；仓库里只用本文对齐「规矩」。两者内容不互相搬运。

## 9. 提交前自检清单

- [ ] 没有改 `gate-files.txt` 里的任何文件
- [ ] 提交身份合规、无 AI 署名尾巴
- [ ] 没有硬编码版本号 / 内网地址 / 真实凭证
- [ ] 数字口径与真本一致（659 例 / 11 层预算 / `v0.1.0`）
- [ ] 新增表格不会干扰 ROADMAP 里程碑表解析
- [ ] 生成物未被手改；`git diff --check` 干净
- [ ] 状态诚实：`draft` 没被写成「已完成」，规划没被写成「已有」
- [ ] `40` / `41` / `12` / ROADMAP 已回写
- [ ] 多卡并发时只改独占文件，共享状态由集成卡统一回写（见 `70`）
- [ ] 本轮范围若是「只写文档」，就没有夹带脚本 / CI / Dockerfile 改动
