# CI 增强规格（给 #264 的施工图）

> 对应任务卡 `M12-CI-04`（#340）。本文是给维护者的施工图：把 M12-CI 的增强需求拆成
> **可直接粘贴的 job/step 片段**，每条标注「改了哪个判定标准、为什么、如何回滚、
> 不改什么算绿」。**本文不改 `ci.yml`、不执行部署**——片段的落盘与接入全部归
> `#264` 人工批次，由维护者逐条放行（`--allow-gate-change` 走门禁评审）。
>
> 通用施工规则：
> 1. 片段中 `actions/<name>@<pinned-full-sha>` 粘贴前必须替换为真实完整 SHA
>    （`git ls-remote https://github.com/actions/<name> <tag>` 获取），**禁止用分支名/tag 悬浮引用**；
> 2. 每接一条跑一次其「验收命令」，红了先回滚该条（`git revert` 单条提交），不带病叠加；
> 3. 所有片段只**新增** job/step 或过滤条件，不删改既有判定步骤——存量判定标准一个都不动。

## 1. `docs-index` job（索引保鲜门）

**改了什么**：新增 job，不改任何既有 job。**为什么**：[docs/INDEX.md](INDEX.md) 与
[INDEX-by-example.md](INDEX-by-example.md) 的保鲜契约是「脚本生成禁手写」（#333/#334/#339），
当前靠人自觉，接入门后手改索引会在 CI 红掉。**回滚**：删除该 job 即回滚，索引文件不受影响。

```yaml
jobs:
  docs-index:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<pinned-full-sha> # v4，粘前替换真实 SHA
      - name: 校验三层索引与仓库实况一致
        run: bash scripts/build-doc-index.sh --check
```

**验收命令**：`bash scripts/build-doc-index.sh --check`（本地先行，退出码 0）。
**不改什么算绿**：该 job 红仅当索引与实况不一致；既有 job 的绿不受它影响——
它没有任何 `needs:` 依赖，也不被别人 `needs:`。

## 2. `check-error-examples` job（E 类契约门）

**改了什么**：新增 job。**为什么**：E 类 135 例的契约（每轨 ≥15、类别覆盖、exempt 理由非空）
目前只在卡验收时查过一次，没有常设门。**回滚**：删 job 即回滚。

```yaml
jobs:
  check-error-examples:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<pinned-full-sha> # v4，粘前替换真实 SHA
      - name: E 类示例契约校验
        run: bash scripts/check-error-examples.sh
```

**验收命令**：`bash scripts/check-error-examples.sh`（#337 产出，退出码 0）。
**不改什么算绿**：脚本零依赖（bash + coreutils），runner 无需装任何东西；
它只读 `*/examples/`，不改任何文件。

## 3. `paths:` 过滤（纯文档提交跳过用例矩阵）

**改了什么**：给**用例矩阵 job** 追加 `paths:` 过滤（不改判定逻辑，只改触发条件）。
**为什么**：纯文档提交打挂 db job 的 infra 噪声已发生多次（[73](73-M11并发执行计划.md) §9、
[78](78-CI失败分类规范.md) §1）；注意这只省资源，**失败分类仍按 docs/78 走，不因 paths 豁免改判**。
**回滚**：删掉 `paths:` 块即恢复全量触发。

```yaml
jobs:
  examples:
    strategy:
      matrix:
        lang: [c, cpp, go, java, python, rust, shell, vue]
    paths:
      - "<lang>/**"
      - "shared/**"
      - "scripts/run-example.sh"
      - ".github/workflows/ci.yml"
```

**验收命令**：推一个只改 `docs/*.md` 的提交，确认 `examples` job 显示 skipped，
其余门（格式化/静态检查/COVERAGE）仍跑。**不改什么算绿**：既有 job 的判定步骤一字未动；
`paths` 只影响「跑不跑」，不影响「怎么判」。

## 4. action 固定 SHA（供应链收敛）

**改了什么**：把 `ci.yml` 里所有 `uses:` 从 tag/分支改为完整 SHA + 注释原 tag。
**为什么**：防 action 仓库被投毒后 tag 漂移；学习仓库收益低但成本也低，一次 sed 的事。
**回滚**：整体 revert 单条提交。

```yaml
steps:
  - uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2（示例，粘前核对最新）
  - uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4（示例，粘前核对最新）
```

**验收命令**：`grep -nE "uses: .*@[^ ]+" .github/workflows/ci.yml | grep -vE "@[0-9a-f]{40}"` 无输出
（全部已是 40 位 SHA）。**不改什么算绿**：SHA 是同一 commit 的另一种引用，行为零变化——
接完后首个 run 与上一 run 的 job 列表与结论应当一致。

## 5. `concurrency` 扩展到 push（省 runner，不省判定）

**改了什么**：现有 `concurrency` 若只覆盖 `pull_request`，扩展到 push 触发（同分支新 push 取消旧 run）。
**为什么**：连续 squash 推 main 时旧 run 空烧。**回滚**：删 `concurrency` 块。

```yaml
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'push' }}
```

**不改什么算绿**：PR 上不取消（`cancel-in-progress` 仅 push 为真），PR 判定节奏不变；
被取消的 run 结论是 `cancelled`，**不计入失败**，也不进 flake rate 分子分母
（[78](78-CI失败分类规范.md) §3 分母只认「push 触发的运行」——被取消的 run 没跑完，不算一次运行）。

## 6. 失败日志 artifact（取证落盘）

**改了什么**：给用例 job 追加收尾 step，失败时上传日志。**为什么**：GitHub 日志 90 天过期，
[docs/87](87-CI失败取证规范.md) §2 的首次失败留档需要 artifact 承载。**回滚**：删 step。

```yaml
steps:
  - name: 失败日志留档（首次失败取证，docs/87 §2）
    if: failure()
    uses: actions/upload-artifact@<pinned-full-sha> # v4，粘前替换真实 SHA
    with:
      name: ci-fail-${{ github.run_id }}-${{ matrix.lang }}
      path: |
        **/*.log
        scripts/last-failed-grep.txt
      retention-days: 30
      if-no-files-found: ignore
```

**不改什么算绿**：`if: failure()` 只在失败时触发；成功 run 多一个 skipped step，结论不变。

## 7. `$GITHUB_STEP_SUMMARY`（失败五要素进 summary）

**改了什么**：同上收尾 step 追加 summary 写入。**为什么**：[docs/87](87-CI失败取证规范.md) §3
的五要素契约（job/分类/信号/留档/重试）要有落点。**回滚**：删 step。

```yaml
steps:
  - name: 写入失败取证摘要（docs/87 §3 五要素）
    if: failure()
    run: |
      {
        echo "## CI 失败取证（run ${{ github.run_id }}）"
        echo "- **job / step**：${{ matrix.lang }} 用例 / 失败步"
        echo "- **分类**：UNVERIFIED（由 scripts/classify-ci-failure.sh 离线判定后补）"
        echo "- **命中信号**：见上方日志，取证按 docs/87 §1 两跳命令"
        echo "- **留档**：ci-fail-${{ github.run_id }}-${{ matrix.lang }}；**移除条件**：UNVERIFIED"
        echo "- **重试**：未重试"
      } >> "$GITHUB_STEP_SUMMARY"
```

**不改什么算绿**：summary 是纯附加输出，不参与任何 `if:` 判定与退出码——写不写都不改变 job 结论。

## 8. nightly 定时（flake rate 观察窗）

**改了什么**：新增 schedule 触发（或独立 nightly workflow），每日一次全量跑。
**为什么**：[docs/80](80-M12度量规范.md) M-1 的观察窗需要稳定的分母来源； nightly 结果**不计入**
push 分母（[78](78-CI失败分类规范.md) §3），只用于提前暴露环境劣化。**回滚**：删 schedule 块。

```yaml
on:
  schedule:
    - cron: "17 20 * * *" # 每日 UTC 20:17（错开整点高峰；≈ 北京 04:17）
```

**不改什么算绿**：nightly 红不阻塞任何 PR/总闸（无 `Required` 检查、无 `needs` 挂钩）；
其结论仅进 M12 度量与 [83-排障总入口](83-排障总入口.md) §1 的分诊素材。

## 9. 明确不做（学习仓库偏重，做了是负资产）

| 项 | 不做的理由 |
|---|---|
| OpenSSF Scorecard | 面向对外发布的供应链评级，本仓不发布制品、评分主要项（依赖更新 PR、签名发布）无对象 |
| CodeQL / SAST | 学习用例以「教学最小可复现」为第一纪律，安全扫描的告警噪音会淹没有效门禁信号 |
| 依赖扫描（Dependabot/Snyk） | 用例依赖锁在镜像内、刻意使用旧 API 展示错误处理，自动升级会破坏 E 类预期输出契约 |

以上三项若未来仓库性质变化（如发布制品），由维护者另立卡再议，本批不接。

## 10. 接入顺序建议（给 #264）

`4（SHA 固定）→ 1/2（新增 job）→ 6/7（失败取证）→ 3/5（触发面收敛）→ 8（nightly）`。
先做行为零变化的（4），再做纯新增的（1/2/6/7），最后才动触发面（3/5/8）——
每步之间跑一轮 fast 档全绿再进下一步，出问题归因面最小。
