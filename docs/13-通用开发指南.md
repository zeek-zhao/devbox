# 通用开发指南（T0 骨架）

> 本文是 **T0 单一真本**（`Q-G-01` 定案，落点见 [41-里程碑拆分](41-里程碑拆分.md) §2）：
> 跨语言通用的开发动线——runner、本地检查、CI、门禁、提交、发版回滚——全部集中在这里。
> **各语言的 `开发指南.md`（G2）只写本轨道差异并链接回本文，不复制这些段落。**
> 语言特有内容（编译器行为、构建系统、调试器）归各轨道 G2/G4。

## 1. 用例 runner：`scripts/run-example.sh`

> README 结构与错误对照格式见本节三文件契约；历史覆盖率由 [D-10](86-度量口径.md) 观察，不作为阻断门槛。

全部用例的唯一入口。每个用例目录必须满足**三文件契约**：

| 文件 | 要求 |
|---|---|
| `run.sh` | 必须存在；自己负责编译与运行，只往 stdout 打业务输出 |
| `expected.txt` | 期望输出；逐行精确，忽略行尾空白与首尾空行 |
| `README.md` | 新增或本次改写的标准用例，必须包含下列四个 H2；历史用例由 D-10 渐进盘点，不因缺段失败 |

README 四段为 `## 考点`（要学会什么）、`## 易错点`（典型错误与后果）、`## 复现`（可复制的命令和可观察结果）、`## 延伸`（迁移、边界或后续阅读）。检查器只读精确规范化的 H2，不匹配正文或子串；历史别名仅接受 `考点说明`、`复现命令`、`运行`、`怎么跑`、`延伸阅读`。旧标题 `契约` / `判据` 只有在该段包含可复制的单例 runner 命令 `TAG=... scripts/run-example.sh <track> <ID>` 时才作为「复现」命中；部署契约或只写验收条件不算。`现象` 不等价于「考点」。

**错误对照（#400）**：需要让读者观察失败与正确处理差异时，把对照写在 `易错点` 中，使用固定机器可读格式 `antipattern=<name> bad=<value> good=<value>`，并将该行纳入 `expected.txt`。错误/失败值是确定的 stdout 期望数据；`run.sh` 必须捕获并展示它们，最终仍以退出码 0 结束。不得让预期错误码、panic 或非零退出逃逸到 runner，否则会被判为真实失败。示例见 E-002、E-005、E-009、E-012、E-014。

常用调用（命令契约统一写 `TAG=latest`，见下）：

```bash
TAG=latest scripts/run-example.sh <track> <ID>     # 跑单个用例
TAG=latest scripts/run-example.sh <track> --all    # 跑整门语言
scripts/run-example.sh <track> --list              # 列出该轨道全部用例 ID
TAG=latest scripts/run-example.sh cpp L0-hello --keep   # 保留容器，便于 docker exec 复现
```

**`TAG` 与 `IMAGE_TAG` 的坑**：runner 读 `TAG`，CI 传 `IMAGE_TAG`，两者是同一个值的两个
名字（历史教训：名字不一致导致过整片用例 job 全红而本地各跑各的都「正常」）。
写文档、敲命令统一用 `TAG=`；本地已有自建镜像时把 `TAG` 换成 `local`。

**失败时先看哪里**：

1. runner 的最后一段输出——它会指出是编译失败、运行超时还是期望输出不匹配；
2. `--keep` 保留容器后 `docker exec` 进去看现场；
3. 镜像拉不到（`probe` job 也红）→ 是镜像问题不是代码问题，见 §4。

## 2. 本地检查与总闸

改完代码/文档，按改动类型跑对应检查（全部从仓库根执行）：

| 改动 | 检查 |
|---|---|
| 语言用例 / 项目代码 | `TAG=latest scripts/run-example.sh <track> <ID>`；格式化 `bash scripts/fmt.sh --check --lang <track>` |
| 覆盖表 / 毕业项目 | `bash scripts/coverage-check.sh --strict` |
| 文档 | `bash scripts/check-docs.sh`、`bash scripts/check-version-truth.sh` |
| 看板数据源 | `bash scripts/build-repo-board.sh` 后 `git diff` 必须为空（生成物不许手改） |
| 提交前 | `git diff --check`（空白错误）；提交身份见 §6 |

**本地总闸 `scripts/pre-merge.sh`** 是合并前的等价全量校验（与 CI 同一套）：

```bash
bash scripts/pre-merge.sh --branches feat/<本卡分支>            # 演练，不推
bash scripts/pre-merge.sh --branches feat/a feat/b --skip-examples --push   # 纯文档批次的快速合批
```

要点：默认**不自动解冲突**——历史上 `--auto-resolve` 曾静默把 77 条 db 用例退回骨架还全绿；
冲突就停下来人工看。多卡并发的目录/分支/合批纪律见 [70-并行AI开发计划](70-并行AI开发计划.md)。

## 3. 门禁与禁区

`scripts/gate-files.txt` 列出的文件，自动化**不许自己改**。完整清单与分组见
[60-AI工作指南](60-AI工作指南.md) §2。速记：CI 定义、判定实现脚本、清单本身、
版本与预算真本、镜像定义、身份与格式配置。

- 动手前先 `git diff --name-only origin/main` 对照清单；**命中即停**，转人工评审；
- 确需改判定标准：人工评审后显式放行（总闸 `--allow-gate-change`），PR 里必须写明
  「为什么改判定标准」。这是例外，不是流程；
- 别用 `--no-verify` 绕本地钩子——绕过去 CI 一样红。

## 4. CI：全量流水线

所有触发（PR / push main / push tag / 手动）都跑**同一套全量**，约 20–25 分钟。
Job 构成与分工见 [02-流水线](02-流水线.md)，速查：

| Job 组 | 挡什么 |
|---|---|
| `static` | shellcheck、用例契约、版本真本、文档命令、tag 与 VERSION 一致 |
| `authors` | 提交身份白名单、AI 署名尾巴 |
| `coverage` | 覆盖表与项目代码自洽（`--strict`，不允许 pending） |
| `probe` | 镜像是否存在 |
| `fmt` × 8 / `examples` × 8 | 八门语言格式化 / 全部用例（fail-fast: false） |
| `examples-db` | db 轨道（自起 Compose 栈，项目名固定 `devbox-db`） |
| `shared` / `release` | shared 库自测与 README 索引 / release 工具自测 |
| `images` | 镜像重建 + 体积预算（fork PR 跳过，平台约束非省测） |

**红灯定位顺序**：先看哪个 job 红 → `static`/`authors`/`coverage` 红不用拉镜像就能复现
（对应 §2 的本地检查）→ `fmt`/`examples` 红，本地用同一 `TAG` 复跑该轨道 →
`probe` 红说明镜像没建，不是代码问题。

**镜像标签策略**：CI 对每个 PR 只推 `sha-<commit>` 标签，不推 `:latest`；
`:latest` 随 main 变（KI-08），可复现场景一律用 sha tag。同仓并发 PR 曾因互相覆盖
被测镜像踩过坑（历史 issue `#184`）。

## 5. 提交

- **身份**：author 与 committer 都必须在 `.github/authors-allowlist.txt` 白名单内
  （当前只有 `zeek.zhao <zeek.zhao@foxmail.com>`）；外部贡献者身份规则见 60 §2；
- **提交信息**：Conventional Commits（`docs:` / `fix:` / `feat:` …），标题要有信息量；
  **禁止 AI 署名尾巴**（`Co-authored-by: …` / `Generated with …`，commit-msg 钩子会拒）；
- **分支**：只推 `feat/<issue#>-<slug>`；直推 main 会被 pre-push 钩子拒绝；
- **目录纪律**：多卡并发时一卡一个独立克隆目录、一个分支，只改本卡的独占文件
  （共享文件由集成卡统一回写），见 [70](70-并行AI开发计划.md) §2.2。

**PR 约定**：目标 `main`；描述里写 `Closes #N` 关联任务卡；按 ROADMAP 的
「Issue ↔ 里程碑对照」关联所属里程碑，没有合适里程碑就显式写「未分配里程碑」并登记。

**合并**：不用网页合并按钮（GitHub 生成的 committer 不在白名单，会把 `check-authors.sh`
判红）。走本地总闸逐分支 squash、全量绿后推 main，再关 PR 并留评论说明由哪个 commit 合入。

## 6. 发版与回滚

- `VERSION` 是版本唯一真本，与 git tag 逐字一致（tag 触发的流水线会校验，`static` job 也查）；
- 依赖版本真本是 `images/versions.env`：文档里引用版本一律写变量名（如 `${GO_VERSION}`），
  不写字面量——否则 `check-version-truth.sh` 红，且升级时文档集体过期；
- 镜像体积预算在 `images/budgets.tsv`，CI 硬卡；
- **回滚**：按 tag 回退——把部署/复现基准指回上一个 `v*` tag（或对应的 `sha-<commit>` 镜像）；
  main 上的回退提交同样走 feat 分支 + PR + 总闸流程。
