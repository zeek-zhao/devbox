## 3. 派单 SOP 摘要（全文见 [70](70-并行AI开发计划.md) §5 与 [73](73-M11并发执行计划.md) §5）

1. 取最新 `origin/main` → 2. 完整克隆到 `~/work/devbox/<issue#>-<slug>/` →
3. `git switch -c feat/<issue#>-<slug>` → 4. 只改独占文件 → 5. 本地跑对应检查 →
6. PR（`Closes #N` + 里程碑 + 执行留痕）→ 7. **verifier 判卷**（不是 implementer 自评）→
8. 批次末总闸 squash 合并；`decision` / `needs-human` 不派自动化。

## 4. 状态更新约定

- 谁：维护者，或其授权的执行自动化（在 PR/评论留痕）；
- 何时：卡进入下一状态时即时更新；批次合批后核对一遍全表；
- 一致性：本文与远端 issue/PR 实际状态冲突时，**以远端为准**并当次修正本文（快照纪律同 [30](30-GitHub现状与时限.md) §0）。
