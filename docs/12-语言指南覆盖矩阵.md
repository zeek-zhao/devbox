## 4. 别按 45 篇平均用力：三层复用策略

如果 9 门语言各写一套五类指南，会有大量重复（「怎么跑用例」「怎么看 CI 红」
「格式化怎么调」每门都一样）。按**可复用度**分三层：

### T0　跨语言通用骨架（写 1 份，9 门引用）—— `Q-G-01` 已定案

| 内容 | 落在哪类 | 为什么通用 |
|---|---|---|
| 镜像 / tag / `run-example.sh` 用法 | G2 | 所有轨道共用同一 runner |
| 格式化、lint、CI 红灯定位 | G2 G4 | `Makefile` 与 `scripts/` 统一入口 |
| 提交身份、门禁文件、PR 约定 | G2 G5 | 仓库级规则，与语言无关 |
| 「本地能跑线上不行」的通用排查路径 | G3 G5 | D5 方法论跨语言一致 |
| 发版 / 回滚通用流程 | G2 G4 | 见 [20-开发发布增强](20-开发发布增强.md) |

> **定案**：T0 集中在 `docs/13-通用开发指南.md` **单文件**，各语言 G2 只写「本轨道差异」
> 并链过去，**不复制**。文件本体是 M6-03 的实施产物，本轮只定落点。
> 这么做还有一个好处：runner 的 `TAG` / `IMAGE_TAG` 这类跨语言坑只需在一处写对。

### T1　每语言最小集（9 × 3 = 27 篇）—— `Q-G-02` 已定案

优先做 **G2 开发指南 / G4 工具指南 / G5 FAQ**——这三篇解决「上手卡住」的成本最低、
复用 T0 最多。G1 实践指南与 G3 问题指南需要真实踩坑素材，放在 M8。

### T2　语言特有的深水区（按轨道挑重点）

| 轨道 | 最该先写的 G1/G3 主题（举例，非穷举） |
|---|---|
| C | 指针/生命周期、未定义行为、ABI 与链接、内存越界定位 |
| C++ | RAII 与移动语义的误用、ODR、模板编译错误阅读、ASan/UBSan |
| Go | goroutine 泄漏、channel 死锁、context 传播、逃逸与 GC、module 版本 |
| Rust | 所有权/借用诊断、`unwrap` 治理、生命周期报错阅读、异步运行时选择 |
| Shell | quoting 与 word splitting、`set -euo pipefail` 陷阱、可移植性、幂等 |
| Python | 虚拟环境与依赖锁定、可变默认参数、GIL 与并发模型、打包发布 |
| Java | JVM 内存/GC、类加载、异常与资源关闭、构建工具与制品 |
| db | 事务隔离、索引与执行计划、迁移与回滚、连接池 |
| Vue | 响应式边界、组件通信、构建产物与部署路径、状态管理取舍 |

> 这些主题来自 sample 各语言「问题指南 / 调试技术与工具 / 最佳实践」的章节体系
> 与公开生产实践资料，是**候选项**；具体取舍按本工程用例实际覆盖来定（`Q-G-05`）。
> G3 的素材来源已由 [11](11-知识点清单增强规范.md) §7.2 的「素材池」给出默认（`Q-G-10`）。

## 5. 排期优先级（已按拍板结论定案）

| 波次 | 内容 | 产出 | 依赖 |
|---|---|---|---|
| W1（M6-01~04） | 模板定稿 + T0 落点 + 范围定案 | 规范文档（**本轮已完成**）+ 落点定案 | 无 |
| W2（M6-05） | 样板轨道 C++ 的 **5 篇全量** | 验证 [11](11-知识点清单增强规范.md) 模板可用 | W1 |
| W3（M7） | 其余 8 门的 G2/G4/G5 | **24 篇最小集** | W2 的 C6 通过；db 另需 `Q-G-07` |
| W4（M8） | 各语言 G1/G3 | 18 篇，按 §4 深水区挑重点 | 真实排查素材积累 |

**篇数口径（别再算错）**：

```
最小集 27 篇 = C++ 的 G2/G4/G5（3）+ 其余 8 轨 × 3（24）
M6 的 C++ 全量 5 篇 = 上面 3 篇 + C++ 的 G1/G3（2）
M6 + M7 实际文件数 = 5 + 24 = 29 篇
M8 再补 16 篇（其余 8 轨 × G1/G3） → 全量 45 篇
```

**为什么 W2 先做 C++ 全量**：与 [ROADMAP](ROADMAP.md) 里「M2 是最硬关口，
产出的是模板」同理——指南也是模板，先把一份写对，再复制八遍。
`Q-G-04` 已于 2026-11-05 第八轮由 #221 拍板**取 C++ 全量**（`cpp/docs/` 7 份齐，七轨复制无返工）。

## 6. 验收口径

- 矩阵的「已补」判定：文件存在 **且** frontmatter **七字段**齐 **且**
  `examples` 里至少 1 个真实用例 ID（见 [11](11-知识点清单增强规范.md) §2.1）
- 不接受「建了空文件」或「从 sample 复制粘贴」算完成
- 每完成一格：回写本矩阵 → 勾掉 [40](40-问题清单.md) 对应 `Q-G-*` 编号 →
  回写 [41](41-里程碑拆分.md) §8 状态表
- 未做的格必须标理由（如「待 M8」「缺真实素材」「db 编号体系未定」），不许静默空着

## 7. 与模板优化的关系

`Q-G-03` 定稿时采纳的 9 条优化（见 [11](11-知识点清单增强规范.md) §7）里，
**O2（章节分三档）与 O3（命令契约）直接影响本矩阵**：

- O2 让 27 篇最小集能只写「必填章节」就验收，不必等 G1/G3 的素材；
- O3 让 9 门语言的 G2/G4 命令写法统一，T0 只需维护一份正确示例；
- O1（`examples` 字段）让 §6 的「已补」判定可以机器校验，不用靠人 grep 正文。
