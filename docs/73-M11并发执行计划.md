## 0. 一句话模型

**一张卡 = 一个完整克隆目录 + 一个 `feat/<issue#>-<slug>` 分支 + 一个 PR + 一条 verifier 结论。**
批次内各卡只改自己的独占文件 → 可以全部同时拉；批次末由本地总闸一次 squash、跑全量、推 `main`。
并发的敌人从来不是 CPU，是**共享文件、合并身份，以及作者给自己判卷**。

## 4. 文件三类（并发能否成立的关键）

| 类别 | 文件 | 谁改 / 何时 |
|---|---|---|
| **独占**（可并发） | `docs/71` · `docs/72` · `cpp/labs/` · `<lang>/labs/` · `docs/74` | 各卡自己的 PR |
| **共享**（禁止并发改） | `ROADMAP` · `30` · `41` · `12` · `00` · 本文 §3 批次状态 | `#266` 集成回写卡，一批合并完一次串行改 |
| **门禁**（AI 不改） | `scripts/gate-files.txt` 命中一切：`.github/workflows/*.yml`、`run-example.sh`、`check-docs.sh`、`check-board-truth.sh`、`build-repo-board.sh`、Dockerfile、钩子、格式化配置 | `#264` 人工批次；PR 写理由 + 显式放行 |

四条规则沿用 [70](70-并行AI开发计划.md) §2.2：

- **A**：任务卡 PR 不碰共享文件，状态回写由集成卡在批次末尾一次做完。
- **B**：某卡确实必须改共享文件 → 从并发组摘出来，排在该批最后串行。
- **C**：新增表格首列别用「里程碑」作表头，且与 ROADMAP 的里程碑表隔着非表格行，否则看板生成器会误认。
- **D**：`docs/*.md` 里能触发文档校验的 HTML 注释标记会被真跑；**只标任何环境都该成功的只读命令**，新文档不写无把握的标记。本轮 lab 的 CI 真跑走 W3 的 labs job，不靠注释标记。

**lab 的落点是硬约束**：看板按 `<lang>/examples/` 直接子目录计 659，`run-example.sh` 只认这个路径。
lab 一律放 `<lang>/labs/`，**绝不塞进 examples/**，否则计数、徽章、ROADMAP 口径全线漂移。

## 5. 单卡 SOP（在 [70](70-并行AI开发计划.md) §5 八步之上加三条）

1. 读卡正文九栏，确认 `kind` 不是 `decision` / `needs-human`；有硬前置先查。
2. 查 GATE 与批次放行记录；W2 查 `#255` 的人工判定评论。
3. 独立完整克隆到 `~/work/devbox/<issue#>-<slug>/`（容器里 `git worktree` 的 `.git` 绝对路径常不可达，不用）。
4. 从**最新 `origin/main`** 建 `feat/<issue#>-<slug>`，不基于别人的 PR 分支。
5. 只改独占文件；本地跑对应检查（`git diff --check`、`check-docs.sh`、`check-board-truth.sh`、lab 的 `assert.sh`）。
6. **执行留痕**：PR 里贴 `run_id` / `files_changed` / `commands_run` / `tests_passed` / `risk_notes` / `review_needed`；没跑过的写 `UNVERIFIED`。
7. **stop rules**：碰门禁文件、凭证、范围外、连续两次验证失败、判据有歧义 → 停并问人，不自行发挥。
8. 提交：Conventional Commits、身份 `zeek.zhao <zeek.zhao@foxmail.com>`、无 AI 署名尾巴、LF。
9. 推分支 → 开 PR（`Closes #N` + 里程碑）→ CI 全绿 → 交给 verifier，不是直接进合并队列。

## 6. verifier 判据（`#265`）

implementer 不该给自己判卷。verifier **不写任何被验产物**，只产出 `docs/74` 报告：

| 层 | 判什么 | 结论形式 |
|---|---|---|
| 规则优先 | 文件齐不齐、命令退不退出、断言命中没命中、frontmatter 字段全不全、素材编号有没有引用 | 机械判定，给命令与输出；**能用规则判的不交给主观判断** |
| rubric | 教学价值、输出判读是否讲清、决策树有没有死分支 | 3–6 维、1–5 分，每维给 1/3/5 分锚点；抽 10% 交维护者人工校准 |
| 结构化结论 | 逐卡一行 | `pass` / `fail` / `revise` / `escalate` + 证据引用 + `UNVERIFIED` 项 |
| 交叉一致性 | 命令契约（`TAG=latest`）、用例 ID 真实性、`S-NN` 素材引用、同批指南之间有无互相矛盾的结论 | 矛盾即 `revise`，指明卡号 |
| 回归基准 | `golden set` | W1 样板 + 至少 2 个 W2 lab，作为后续回放基线 |

## 7. 合并纪律（本计划最容易翻车的一节）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 网页点 Merge / Squash | 生成 `noreply@github.com` committer，`check-authors.sh --all` 扫全历史判红 | 本地总闸 `bash scripts/pre-merge.sh --branches feat/253-... ... --push` |
| 任务卡直推 `main` | `.githooks/pre-push` 拒绝 | 只推 `feat/*`；`DEVBOX_ALLOW_MAIN_PUSH=1` 是给总闸与维护者的例外 |
| 顺手改门禁注释 | `check-gate-files.sh` 拒绝合批 | 全部攒进 `#264`，人工评审 + `--allow-gate-change` |
| 多卡同改共享状态 | 合批冲突；`--auto-resolve` 曾静默把用例退回骨架还全绿 | 规则 A：集成卡一次回写；**不要用自动解冲突蒙过去** |
| 合并后忘了关 issue / PR | 明账失真，`30` 快照与远端不符 | 推 `main` 后逐条关、更新快照日期 |

**合并判据（四条全满足）**：① 该 PR 的 CI 全量绿；② 相对 `origin/main` 未触碰门禁文件（W3 除外且已人工放行）；
③ 独占文件与同批其他 PR 无重叠；④ verifier 结论为 `pass`，验收判据逐条有证据。
**CI 全绿 ≠ 放行**；硬关口 C6 / W1 样板判定 / GATE 的人工结论另算。

## 8. 一个批次「做完」的定义

- [ ] 批内每个 PR 的 CI 全量绿，且门禁检查相对基线无意外命中
- [ ] 总闸 `pre-merge.sh --branches <本批分支...> --push` 通过并推上 `main`
- [ ] PR / issue 已关，里程碑 open/closed 数与远端 API 一致
- [ ] verifier 报告已出，无 `fail`，`UNVERIFIED` 逐项有主
- [ ] 共享状态由 `#266` 一次回写；`build-repo-board.sh` 后 `git diff` 为空（**必须在 Linux 跑**，Windows Git Bash 会写坏生成物）
- [ ] `30` 快照日期已更新；本文 §3 批次状态已勾；硬关口的人工记录写进对应 issue

## 9. 已踩过的坑（本轮新增）

- GitHub 建里程碑时 `due_on` **必须是 datetime**，但 `2026-12-02T00:00:00Z` 会落库成 `2026-12-01`；
  建完立刻用纯日期 `2026-12-02` PATCH 修齐（M0–M5 已验证）。
- **PR 与 issue 共用一套编号**：`issues` API 查到的最大号是 `#230`，但 PR `#252` 已经占号，
  新卡实际从 `#253` 起。批量建卡前要连 PR 一起查最大号。
- REST API 建卡**跳过 issue 表单**：模板写得再好也不会自动生效，正文必须镜像表单的 `###` 标题。
- 表单里的 label 若不存在会被**静默丢弃**，所以 `agent_task.yml` 不预置标签，按卡类型在 API 里显式传。
- db 栈 compose 项目名固定 `devbox-db`，多卡同时起会互相顶掉；`#263` 单独串行验证。
- `docs/*.md` 里能触发校验的注释标记会被逐条真跑，只放任何环境都该成功的只读命令。
