## 🚀 使用方法

### 1. 创建符合规范的提交

```bash
# feat: 新功能 (会升级 minor 版本)
git commit -m "feat: 添加新功能"

# fix: Bug修复 (会升级 patch 版本)
git commit -m "fix: 修复某个问题"

# BREAKING CHANGE: 破坏性更新 (会升级 major 版本)
git commit -m "feat: 重构API

BREAKING CHANGE: API接口完全重构"
```

### 2. 发布新版本

```bash
# 自动根据提交确定版本类型
npm run release

# 强制发布特定版本
npm run release:patch   # 0.0.1 -> 0.0.2
npm run release:minor   # 0.0.1 -> 0.1.0
npm run release:major   # 0.0.1 -> 1.0.0
```

### 3. 推送到远程仓库

```bash
git push --follow-tags origin master
```

## � 核心概念详解

### 1️⃣ Bump (版本号升级)

**Bump** 是指自动升级项目版本号的过程。standard-version 会：
- 分析自上次发布以来的所有 git commits
- 根据 commit 类型确定版本号升级策略
- 更新 `package.json` 和 `package-lock.json` 中的 version 字段

**版本号格式**: `MAJOR.MINOR.PATCH` (例如: `1.2.3`)

```bash
# Bump 发生在执行 npm run release 时
npm run release
# ✔ bumping version in package.json from 0.0.0 to 0.0.1
```

### 2️⃣ Changelog (变更日志)

**Changelog** 是记录项目所有重要变更的文档 (`CHANGELOG.md`)。

**自动生成过程**:
1. 读取自上次 tag 以来的所有 commits
2. 按类型分组 (feat, fix, docs 等)
3. 生成格式化的 markdown 文档
4. 添加版本号、日期和对比链接

**示例结构**:
```markdown
### [0.0.1](///compare/v0.0.0...v0.0.1) (2025-11-11)

### ✨ Features | 新功能
* 添加求幂运算功能 0c6ca83

### 🐛 Bug Fixes | Bug 修复
* 修复减法运算类型转换问题 da913f8
```

### 3️⃣ Commit (提交规范)

**Commit** 遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范。

**标准格式**:
```
<type>(<scope>): <subject>

<body>

<footer>
```

**详细说明**:
- `type`: 提交类型 (必填)
- `scope`: 影响范围 (可选)
- `subject`: 简短描述 (必填)
- `body`: 详细说明 (可选)
- `footer`: 备注信息，如 BREAKING CHANGE (可选)

**示例**:
```bash
# 简单格式
git commit -m "feat: 添加用户登录功能"

# 带 scope
git commit -m "fix(auth): 修复 token 过期问题"

# 完整格式
git commit -m "feat(api): 重构用户API

- 使用 RESTful 风格
- 添加参数验证
- 优化错误处理

BREAKING CHANGE: API路径从 /user 改为 /api/users"
```

### 4️⃣ Tag (版本标签)

**Tag** 是 Git 中标记特定提交点的引用，用于版本管理。

**自动创建**:
```bash
# standard-version 会自动创建 tag
npm run release
# ✔ tagging release v0.0.1
```

**查看所有 tags**:
```bash
git tag
# v0.0.0
# v0.0.1
```

**查看 tag 详情**:
```bash
git show v0.0.1
```

**推送 tags 到远程**:
```bash
# 推送所有 tags
git push --tags

# 推送特定 tag
git push origin v0.0.1

# 推送代码和 tags (推荐)
git push --follow-tags origin master
```

## 🔄 Standard-Version 完整流程

当你运行 `npm run release` 时，standard-version 会执行以下步骤：

```
1. 📖 读取 Git History
   ↓ 分析自上次 tag 以来的所有 commits
   
2. 🔢 确定版本类型 (Bump)
   ↓ 根据 commit 类型决定升级 major/minor/patch
   
3. 📝 更新版本号
   ↓ 修改 package.json 和 package-lock.json
   
4. 📋 生成/更新 CHANGELOG.md
   ↓ 添加新版本的变更记录
   
5. 💾 创建 Release Commit
   ↓ git commit -m "chore(release): x.x.x"
   
6. 🏷️ 创建 Git Tag
   ↓ git tag -a vx.x.x
   
7. ✅ 完成
   ↓ 提示推送命令
```

## �📊 版本规则

根据提交类型自动升级版本号：

| 提交类型 | 版本升级 | 示例 | 说明 |
|---------|---------|------|------|
| `fix:` | patch | 0.0.0 → 0.0.1 | Bug 修复 |
| `feat:` | minor | 0.0.0 → 0.1.0 | 新功能 |
| `BREAKING CHANGE:` | major | 0.0.0 → 1.0.0 | 破坏性变更 |
| `perf:` | patch | 0.0.0 → 0.0.1 | 性能优化 |
| `chore:`, `docs:`, 等 | - | - | 只记录到 CHANGELOG |

## 🎯 Commit 类型说明

| Type | 说明 | Bump | 示例 |
|------|------|------|------|
| `feat:` | 新功能 | minor | `feat: 添加用户注册功能` |
| `fix:` | Bug 修复 | patch | `fix: 修复登录验证错误` |
| `docs:` | 文档更新 | - | `docs: 更新 API 文档` |
| `style:` | 代码格式调整 (不影响功能) | - | `style: 格式化代码` |
| `refactor:` | 代码重构 (不修复bug也不添加功能) | - | `refactor: 重构用户模块` |
| `perf:` | 性能优化 | patch | `perf: 优化查询性能` |
| `test:` | 测试相关 | - | `test: 添加单元测试` |
| `build:` | 构建系统或外部依赖 | - | `build: 升级 webpack 版本` |
| `ci:` | CI 配置文件和脚本 | - | `ci: 添加 GitHub Actions` |
| `chore:` | 其他修改 (不修改 src 或 test) | - | `chore: 更新 .gitignore` |
| `revert:` | 回退之前的 commit | - | `revert: 回退 feat: xxx` |

**特殊标记**:
- `BREAKING CHANGE:` 在 footer 中表示破坏性变更 → **major** bump
- `!` 在 type 后表示破坏性变更，如 `feat!:` → **major** bump

## ⚙️ 配置文件说明 (.versionrc.js)

```javascript
module.exports = {
  // 定义 commit 类型和对应的 CHANGELOG 分类
  "types": [
    { "type": "feat", "section": "✨ Features | 新功能" },
    { "type": "fix", "section": "🐛 Bug Fixes | Bug 修复" },
    // ... 更多类型
  ],
  
  // 跳过某些步骤的配置
  skip: {
    bump: false,      // false = 执行版本升级
    changelog: false, // false = 生成 CHANGELOG
    commit: false,    // false = 创建 release commit
    tag: false        // false = 创建 git tag
  },
  
  // 需要更新版本号的文件
  bumpFiles: [
    { filename: 'package.json', type: "json" },
    { filename: 'package-lock.json', type: "json" }
  ]
}
```

**配置项详解**:

- **types**: 定义哪些 commit 类型会出现在 CHANGELOG 中
  - `type`: commit 类型
  - `section`: CHANGELOG 中的分组标题
  - `hidden: true`: 不在 CHANGELOG 中显示

- **skip**: 控制跳过哪些步骤
  - `bump: true` → 不升级版本号
  - `changelog: true` → 不生成 CHANGELOG
  - `commit: true` → 不创建 commit
  - `tag: true` → 不创建 tag

- **bumpFiles**: 指定需要更新版本号的文件列表

- **packageFiles**: 读取当前版本号的文件

## 🛠️ 高级用法

### 预发布版本

```bash
# 发布 alpha 版本
npm run release -- --prerelease alpha
# 0.0.1 -> 0.0.2-alpha.0

# 发布 beta 版本
npm run release -- --prerelease beta
# 0.0.1 -> 0.0.2-beta.0
```

### 指定版本号

```bash
# 直接指定版本号
npm run release -- --release-as 2.0.0
```

### 干运行 (不实际执行)

```bash
# 查看会发生什么，但不实际修改文件
npm run release -- --dry-run
```

### 首次发布

```bash
# 首次发布，不升级版本号
npm run release:first
# 或
npm run release -- --first-release
```

## 🔍 常见问题

### 1. 如何撤销一次 release?

```bash
# 删除最新的 tag
git tag -d v0.0.1

# 撤销最后一次 commit
git reset --hard HEAD~1

# 如果已推送到远程
git push origin :refs/tags/v0.0.1
git push -f origin master
```

### 2. 如何跳过某些步骤?

在 `.versionrc.js` 中配置 `skip` 选项，或使用命令行参数：

```bash
# 只生成 CHANGELOG，不升级版本
npm run release -- --skip.bump
```

### 3. 如何自定义 CHANGELOG 格式?

修改 `.versionrc.js` 中的 `types` 配置：

```javascript
{
  "type": "feat",
  "section": "🎉 新功能",  // 自定义标题
  "hidden": false          // 是否隐藏
}
```
