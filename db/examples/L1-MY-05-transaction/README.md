
# L1-MY-05-transaction · 事务与隔离级别

## 考点
- 两个独立连接演示 `REPEATABLE READ` 快照读不会看到对方已提交的新值。
- `SELECT ... FOR UPDATE` 是当前读，可见另一会话已提交的值。
- 回滚本会话的后续修改，验证 `ROLLBACK` 不改变已提交结果。

## 为什么这么写
必须用两个真实客户端连接才能制造提交并发；单连接顺序执行不能证明快照可见性。数据只输出固定业务值，不输出时间或连接信息。

## 易错点
- 第一次普通 `SELECT` 建立快照后，第二连接必须先提交，才能区分快照读和当前读。
- 两个连接都显式关闭，避免遗留未提交事务影响重跑。
