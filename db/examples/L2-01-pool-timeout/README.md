
# L2-01-pool-timeout · 连接池与超时

## 考点

- 应用侧池上限与数据库 `max_connections` 是不同层级的限制。
- 池占满时，第三个申请者在固定超时后被拒绝。
- 释放租约后连接可再次借出并成功执行查询。

## 为什么这么写

池由两个真实 PostgreSQL 连接和有界队列实现，只持有两个连接，不冲击共享实例连接上限；固定队列超时并只输出行为，不输出易抖动的等待耗时。

## 易错点

- 不要通过耗尽共享 PostgreSQL 的 `max_connections` 测试池上限。
- 连接获取超时必须发生在池层；服务器连接拒绝是另一类错误。
- 所有连接在 `finally` 中关闭，避免用例自身制造连接泄漏。

## 依赖服务

`postgres`

## 命名空间

`db_l2_01_pool_timeout`
