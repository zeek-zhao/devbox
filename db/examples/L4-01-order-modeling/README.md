
# L4-01-order-modeling · 订单模型建模

## 考点
- 订单头和明细用主键/外键表达一对多关系，明细行而非订单头保存数量和成交单价。
- 与实时关联商品当前价对照，证明历史金额快照不会随商品改价而变化。
- 固定商品业务键与订单业务键，避免把自增 ID 当作演示输出。

## 为什么这么写
明细保存下单时 `unit_price`，同时保留 `product_id` 供商品关联；实时商品价格只作为对照，不能代替成交快照。状态使用受限枚举，展示订单状态集合。

## 易错点
- 只存 `product_id` 并在报表时取当前价，会把旧订单金额改写成新售价。
- 仅在订单头存总金额，无法解释多商品订单的行级金额。
