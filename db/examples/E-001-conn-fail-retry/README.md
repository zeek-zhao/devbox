## 主题映射

语言轨错误处理 E 段「可重试错误的分类与重试预算」（`E-010-retry-backoff`）主题的 db 轨落地：
连接失败按错误码分类——环境类（2003 连接拒绝）可重试，凭证类（1045 拒绝访问）不可重试。

## 现象

同一个 `pymysql.connect` 失败可能是两种完全不同的问题：端口没人监听（服务没起 / 网络不通）
和密码错误。不分类的调用方要么对「密码错了」重试三次白白放大故障，要么对「服务没起」
一次就放弃。本例对 2003 按预算重试 3 次后放弃，对 1045 直接归为不可重试。

## 复现命令

```bash
bash db/scripts/run-example.sh db E-001-conn-fail-retry
# 或单独跑断言：
bash db/examples/E-001-conn-fail-retry/assert.sh
```

## 期望输出

与 expected.txt 逐行一致：3 次重试各打一行 `attempt=N err=2003 ...`，错误口令
`err=1045 class=credentials retryable=no`，最后正确连接 `connect_ok=1`，
每次尝试（含成功）都记入 conn_log（`log_rows=4`）。

## 为什么这样处理

- 分类挂在「错误码」上而不是报错文本上：`e.args[0]` 是稳定契约，报错文案不是。
- 重试预算写在调用点（3 次），重试之间是同一种环境类错误；预算耗尽就放弃，
  不许无限重试。
- 凭证类错误（1045）一次都不重试：重试不会修好密码，只会把锁账号 / 触发风控的
  风险放大。

## 反例

- `except: retry()` 不看错误码——对 1045 也重试，等于用重试把凭证问题放大成锁定。
- 吞掉重试预算耗尽后的异常继续往下走——调用方拿到的是「假装成功的失败」。
- 用报错文本做子串匹配（`"refused" in str(e)`）——文案随版本 / 语言漂移，码不会。
