# db 排查手册（troubleshooting）

> 按「症状 → 排查命令 → 判据 → 修复」组织的手册。§2 是错误处理章，含
> §2.1–§2.15 共 15 节，逐节对应 `db/examples/E-001..E-015`（各例 README 的
> `coverage: exempt` 注释指向本手册错误处理章）。
> §3、§4 是路由章：事务/锁与工程问题的入口指向既有指南与 lab。
> db 轨道自带 runner：命令在宿主上执行、经 `docker compose exec` 进 `toolbox`
> 连各库（真本 `db/README.md`）。本手册全部排查命令已于 2026-11-11 在本机
> db 栈内真跑核对；写法纪律见 [docs/72-排障演练规范](../../docs/72-排障演练规范.md)
> （现象禁止编造，只许来自真跑或已登记问题）。

## 1. 使用方法

1. 栈没起先起栈：`db/scripts/up.sh` + `db/scripts/wait-ready.sh`（都幂等）。
2. 按症状在本手册定位到节；每节给一条可直接执行的排查命令与判据输出。
3. 判据不成立 → 按该节「修复」处理；判据成立但问题仍在 → 走该节给出的关联文档。
4. 「怎么写对」的设计问题走 [实践指南](实践指南.md) / [问题指南](问题指南.md)。

## 2. 错误处理章（对应 E-001..E-015）

### 2.1 连接失败：重试还是放弃（E-001-conn-fail-retry）

- 症状：connect 抛异常统一重试——密码错了也重试三次放大故障；或服务没起却一次放弃。
- 排查命令：`bash db/scripts/run-example.sh db E-001-conn-fail-retry`
- 判据：2003 三次重试后 `retry_budget_exhausted=yes`；1045
  `class=credentials retryable=no` 立即放弃；修正后 `connect_ok=1`、`log_rows=4`。
- 修复：先按错误码分类（2003 环境类可重试 / 1045 凭证类不可重试），
  重试带预算。详见 E-001 README。

### 2.2 约束违反混为一谈（E-002-constraint-catch）

- 症状：所有 `MySQLError` 统一重试或统一报错，分不清 email 重复（换个值）
  与 age 为负（调用方 bug）。
- 排查命令：`bash db/scripts/run-example.sh db E-002-constraint-catch`
- 判据：`dup_email err=1062 class=unique retryable=no`、`negative_age err=3819
  class=check retryable=no`、`orphan_order err=1452 class=foreign_key retryable=no`、
  `delete_parent err=1451`；修正数据后 `insert_ok rows=1`。
- 修复：按 errno 逐类归因给不同动作，重试不会修好数据错误。
  详见 E-002 README。

### 2.3 死锁 1213 的受害者与重试范围（E-003-deadlock-retry）

- 症状：并发更新收到 1213，不知道谁被回滚、该回滚多少、重试会不会再撞。
- 排查命令：`bash db/scripts/run-example.sh db E-003-deadlock-retry`
- 判据：`deadlock err=1213 victim=b retryable=yes`、`a_committed=yes`、
  `retry attempt=2 ok=yes`；重试后三个 final 余额与串行执行一致。
- 修复：1213 整体回滚重试（锁成本高的会话通常存活）；最终状态以
  串行口径校验。详见 E-003 README。

### 2.4 保存点与 PG 事务中止态（E-004-rollback-savepoint）

- 症状：批量写入一条失败——MySQL 里误把前面已成功的行一起回滚；
  PG 里继续发语句吃 `25P02`。
- 排查命令：`bash db/scripts/run-example.sh db E-004-rollback-savepoint`
- 判据：MySQL `violation err=1062 rollback_to=sp1`、`rows_after_rollback_to=2`、
  `rows_final=3`；PG `pg_after_error err=25P02 class=aborted_txn`、
  `pg_without_savepoint rows_committed=0`、`pg_with_savepoint rows_committed=2`。
- 修复：MySQL 用 `ROLLBACK TO SAVEPOINT` 只丢弃出错后段；PG 在错误前打
  `SAVEPOINT` 并 `ROLLBACK TO`，否则必须整体 `ROLLBACK` 重来。
  详见 E-004 README。

### 2.5 不报错的丢失更新（E-005-isolation-lost-update）

- 症状：两个会话各 +10/+5，最终值少一次写入，全程没有任何报错。
- 排查命令：`bash db/scripts/run-example.sh db E-005-isolation-lost-update`
- 判据：`final_value=105 expected_value=115 lost_update=yes`；
  `SELECT ... FOR UPDATE` 修复后 `for_update_timeout err=1205
  class=contention retryable=yes`、`retry_final=125`。
- 修复：读改写路径用当前读 + 行锁（FOR UPDATE）；1205 归因为 contention
  可重试。同主题实机演练见
  [T-001-slow-query-repeatable-read](../labs/T-001-slow-query-repeatable-read/WALKTHROUGH.md)。
  详见 E-005 README。

### 2.6 连接配额耗尽 1226（E-006-conn-limit-exhaust）

- 症状：1226 被当环境类错误重试——但容量不释放，重试一万次还是 1226。
- 排查命令：`bash db/scripts/run-example.sh db E-006-conn-limit-exhaust`
- 判据：`lease_exceeded err=1226 class=capacity action=shed`、
  `release conn=1 freed=yes`、`retry lease ok=yes`。
- 修复：1226 归为容量类，动作是让路（释放/归还连接）后再取，
  不是盲目重试。详见 E-006 README。

### 2.7 超时后事务还活着（E-007-query-timeout）

- 症状：1205 之后以为「超时=回滚完事」继续跑，后续语句带着
  没打算提交的旧事务上下文。
- 排查命令：`bash db/scripts/run-example.sh db E-007-query-timeout`
- 判据：`stmt_timeout err=3024 class=timeout action=shrink`、
  `lock_timeout err=1205 class=timeout retryable=yes`、
  `victim_txn_alive id2=100`（连接未断、事务未回滚）；显式回滚后重试全绿。
- 修复：区分语句超时（3024，动作是缩查询）与锁等待超时（1205，
  动作是先显式 ROLLBACK 再重试）。同主题实机演练见
  [T-001-slow-query-repeatable-read](../labs/T-001-slow-query-repeatable-read/WALKTHROUGH.md)。
  详见 E-007 README。

### 2.8 权限拒绝的方向性错误（E-008-permission-denied）

- 症状：把 1142/1044 当「连接坏了」重试，或当「数据库挂了」告警。
- 排查命令：`bash db/scripts/run-example.sh db E-008-permission-denied`
- 判据：`insert_denied err=1142 class=permission retryable=no`、
  `grant_fixed insert_ok=1`、`revoked err=1142 closed=yes`、
  `no_db_access err=1044 class=permission retryable=no`（connect 阶段就报）。
- 修复：权限类不可重试；修复路径是 GRANT 或改账号，不是重连。
  详见 E-008 README。

### 2.9 乱码落库与 1366（E-009-charset-mojibake）

- 症状：多字节文本双重编码落库（HEX 指纹不符）但不报错；latin1 列直接 1366。
- 排查命令：`bash db/scripts/run-example.sh db E-009-charset-mojibake`
- 判据：`utf8_write hex=E4BDA0E5A5BD char_len=2`、
  `mojibake_stored hex=C3A4C2BD...`、`mojibake_read ... char_len=6`、
  `column_latin1 err=1366 class=charset retryable=no`、
  `fixed roundtrip=yes hex_match=yes`。
- 修复：连接、客户端、列字符集三方对齐 utf8mb4；用 HEX 指纹做写入后校验；
  1366 拒写比静默截断好。详见 E-009 README。

### 2.10 NULL 让结果静默变错（E-010-null-semantics）

- 症状：COUNT(*) 与 COUNT(列) 对不上、SUM 变 NULL 传染总账、
  `= NULL` 与 `NOT IN (… NULL)` 恒不匹配——全程无报错。
- 排查命令：`bash db/scripts/run-example.sh db E-010-null-semantics`
- 判据：`count rows=5 amount_non_null=2`、`south_sum_is_null=yes
  south_sum_coalesced=0`、`eq_null_matches=0 is_null_matches=2`、
  `not_in_trap=0 not_in_fixed=3`。
- 修复：计数明确用哪一列；聚合外套 `COALESCE`；NULL 判等只用
  `IS [NOT] NULL`；`NOT IN` 子查询里排除 NULL。详见 E-010 README。

### 2.11 迁移卡在半套状态（E-011-migration-partial-fail）

- 症状：迁移失败后列留在库里、回填没跑；直接重跑在加列步骤撞 1060。
- 排查命令：`bash db/scripts/run-example.sh db E-011-migration-partial-fail`
- 判据：`migration_failed err=1072 rollback_done=yes`（DML 回了）、
  `partial_applied last_login_column=yes`（DDL 残留）、`backfill_committed=0`、
  幂等重跑 `duplicate_column err=1060 handled=idempotent`、`backfill_committed=2`。
- 修复：每步幂等（先查 information_schema 再 DDL）；警惕 DDL 前后的
  隐式提交——回填别混进 DDL 同一「事务」。详见 E-011 README。

### 2.12 唯一键竞态的报错时机（E-012-upsert-race）

- 症状：并发插同一唯一键，后者阻塞到前者提交才拿到 1062；
  赢家回滚时同一方反而插入成功——成败不由自己决定。
- 排查命令：`bash db/scripts/run-example.sh db E-012-upsert-race`
- 判据：`race_commit err=1062 action=adopt_existing`（采纳既有行）、
  `race_rollback loser_ok=yes`、`upsert_concurrent qty=110 lost_update=no`。
- 修复：竞态收口用 `INSERT ... ON DUPLICATE KEY UPDATE`（或先 adopt
  既有行），把「撞键」当正常分支而不是异常。详见 E-012 README。

### 2.13 备份不完整被误读（E-013-backup-corrupt-detect）

- 症状：截断的备份恢复时报 1064，被当成「SQL 写错了」排查半天。
- 排查命令：`bash db/scripts/run-example.sh db E-013-backup-corrupt-detect`
- 判据：`tail_marker good=yes bad=no`（恢复前就能发现截断）、
  `corrupt_restore stmts_done=17 err=1064 detected=yes`、
  `good_restore rows=3 checksum_match=yes`。
- 修复：恢复前先查尾部 `Dump completed` 标记；恢复后用
  `CHECKSUM TABLE` 对源表校验。详见 E-013 README。

### 2.14 外键级联的静默丢失（E-014-fk-cascade-trap）

- 症状：RESTRICT 下删父行报 1451 是护栏；CASCADE 下同一句 DELETE
  「成功」，子行无声消失——没有错误码、没有警告、没有回滚机会。
- 排查命令：`bash db/scripts/run-example.sh db E-014-fk-cascade-trap`
- 判据：`delete_parent err=1451 class=foreign_key action=handle_children`、
  `explicit_two_step orders_left=0 customer_gone=yes`、
  `cascade_delete invoices_before=2 invoices_after=0 silent_loss=yes`。
- 修复：删有子行的父行走显式两步（同事务先处理子行）； CASCADE 只用在
  真正想要「随父消失」语义的关系上。详见 E-014 README。

### 2.15 autocommit + 吞错 = 半套落库（E-015-antipattern-swallow）

- 症状：转账两条 UPDATE 在 autocommit 下第一条已提交、第二条被
  `except: pass` 吞掉，函数正常返回，钱无声蒸发。
- 排查命令：`bash db/scripts/run-example.sh db E-015-antipattern-swallow`
- 判据：反模式侧 `antipattern sum=170 lost=30 reported=no`；
  正例侧 `handled err=1264 rollback=yes reported=yes`、
  `handled sum=200 lost=0 consistent=yes`。
- 修复：多语句业务动作显式开事务；`except: pass` 禁止；失败即整体
  回滚并上报。详见 E-015 README。
