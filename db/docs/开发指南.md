# db 开发指南（G2）
> 本文只写 db 轨道的差异；跨语言通用动线（runner、CI、门禁、提交纪律）以
> [13-通用开发指南](../../docs/13-通用开发指南.md) 为单一真本，不在此复制。
> 练什么看[知识点清单](知识点清单.md)，工程事实速查看[工程参考](工程参考.md)，
> 排错看[排查手册](排查手册.md)。

## 1. 环境与启动

- db 轨**不是单容器**：MySQL / PostgreSQL / MongoDB / Redis 四库 + `toolbox`
  客户端容器由 `db/docker/docker-compose.yml` 编排（SQLite 直接内置在 toolbox 里）。
  编排文件是**共享契约**：用例卡不改它，需要额外实例时用现成 profile
  （`multi` 主从多实例 / `cluster` Redis 三节点 / `tls` 自签证书），见该文件头注释。
- 五库版本号只写在 compose 文件里（`mysql:8.4` / `postgres:16-alpine` / `mongo:7` /
  `redis:7-alpine`），**不进 `images/versions.env`**——db 不参与六门语言的镜像分层，
  版本真本就是 compose 本身（改版本 = 改 compose = 共享契约变更，须单独评审）。
- Docker Hub 直连不通时默认走 `docker.m.daocloud.io/library/` 前缀；
  换源用环境变量 `DB_IMAGE_PREFIX` 覆盖，不要改 compose 字面量。
- 不挂数据卷：每次 `up` 都是干净的库，用例自己管自己的命名空间（库/表名约定见
  [工程参考](工程参考.md) §4）。
- 标准启动顺序（缺一不可，`run.sh` 直接连库会在就绪前假失败）：

```bash
cd <仓库根>
db/scripts/up.sh            # 起五库 + toolbox（首次会构建 toolbox 镜像）
db/scripts/wait-ready.sh    # 等全部服务真的能接受查询（不是「容器起来了」）
```

- `wait-ready.sh` 的探针就是五条真实查询（mysql / psql / redis-cli / pymongo /
  sqlite3），超时默认 `${DB_WAIT_TIMEOUT:-180}` 秒。CI 的 `用例-db` job 与
  labs job 里的 db 演练都走同一套 up → wait → 跑 → down 动线。

## 2. 目录结构与各文件职责

```
db/
├── examples/<ID>/        # 教学用例（编号体系独立，见 知识点清单.md）
│   ├── run.sh            # 跑在宿主上，经 docker compose exec 进 toolbox 连库
│   ├── expected.txt      # 期望输出，逐行精确（与语言轨同契约）
│   └── README.md         # 考点说明
├── project/              # 毕业项目：跨五库的「带缓存的订单服务」
├── scripts/              # 轨道 runner：up / wait-ready / run-example / status / down
├── docker/               # docker-compose.yml（共享契约）+ 相关构建物
└── docs/                 # 本指南层文档
```

- 编号体系（`Q-G-07` 裁定**保持独立、不强行对齐**语言轨的 `L[0-4]-NNN`）：
  `L1-<库前缀>-NN`（五库 × 8，如 `L1-MY-01-create-and-types`）、
  `L2-NN` / `L3-NN` / `L4-NN`（跨库主题两位编号，如 `L2-01-pool-timeout`）、
  `E-0NN`（错误处理 15 例）、`T-001`（排障演练，不计入用例 runner）。
  写文档引用用例时**照抄目录 ID**，不要把语言轨的 `KP-` 前缀搬进来。

## 3. 一条命令跑通

```bash
cd <仓库根>
db/scripts/up.sh && db/scripts/wait-ready.sh
db/scripts/run-example.sh db L1-MY-01-create-and-types
```

预期：runner 确认栈已就绪，`docker compose exec` 进 `toolbox` 真连 MySQL 执行，
stdout 逐行比对 `expected.txt`，末尾打印 `PASS`。列全部用例：
`db/scripts/run-example.sh db --list`；跑整门：
`db/scripts/run-example.sh db --all`（先 up + wait-ready）。

失败时先看哪里：

1. `db/scripts/status.sh`——五个服务是否都 Up、toolbox 是否在跑；
2. runner 最后一段输出——区分「服务未就绪」「连接被拒」「期望输出不匹配」；
3. 镜像拉取失败（daocloud TLS 超时）是**外部镜像源抖动**，按
   [78-CI失败分类规范](../../docs/78-CI失败分类规范.md) 走 `infra_transient`，
   不要改用例「修」它（历史判例见 `docs/73` §9）。

## 4. 改动循环：改 → 验证 → 提交

```bash
# 1) 改用例或 db/project/ 代码
# 2) 单个用例验证（栈必须已就绪）
db/scripts/run-example.sh db L2-01-pool-timeout
# 3) 毕业项目端到端（栈须已就绪；源码临时送入 toolbox 执行，不动共享栈）
bash db/project/run.sh
# 4) 格式检查：db 轨脚本属 shell 文件，走统一 fmt 门
bash scripts/fmt.sh --check
# 5) 提交：身份白名单、Conventional Commits——纪律见 T0 §5
git add <文件> && git commit
```

要点：

- db 用例**幂等**是硬要求：不挂数据卷意味着每次 up 都是干净的库，
  但同一次 up 内重跑用例必须得到同一输出（自建库/表/键空间，命名空间带用例 ID）。
- 改 `db/docker/docker-compose.yml` 属于共享契约变更，用例卡无权改动；
  需要新服务/新实例先看现成 profile 是否已覆盖（multi / cluster / tls）。
- 事务、隔离级别类用例对「等待就绪」敏感：连接失败先怀疑栈没起或没等到位，
  再怀疑用例本身（[排查手册](排查手册.md) §1 有完整决策树）。

## 5. 调试入口

保留现场：`db/scripts/up.sh` 起的栈在用例失败后**不会**自动销毁（这点与语言轨的
`--keep` 不同），直接 `docker compose -f db/docker/docker-compose.yml exec toolbox bash`
进容器手动复现；`db/scripts/status.sh` 看五库健康；`db/scripts/down.sh` 收尾。
更多排错路径见 [排查手册](排查手册.md)。
