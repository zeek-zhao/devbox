## 1. 工程全景表

| 域 | 事实 | 真本出处 |
|---|---|---|
| 服务编排 | `docker compose -f db/docker/docker-compose.yml`，默认四库 + toolbox；project 名 `devbox-db` | `db/docker/docker-compose.yml` |
| MySQL | `${DB_IMAGE_PREFIX:-docker.m.daocloud.io/library/}mysql:8.4`，root 密码 `devbox`，utf8mb4 + 慢查询日志开启 | compose `services.mysql` |
| PostgreSQL | `postgres:16-alpine`，账号 `devbox/devbox`，库 `devbox` | compose `services.postgres` |
| MongoDB | `mongo:7`，root `devbox/devbox`（authSource=admin） | compose `services.mongodb` |
| Redis | `redis:7-alpine`，密码 `devbox` | compose `services.redis` |
| SQLite | 无独立服务，内置在 toolbox 镜像里 | `db/scripts/wait-ready.sh` 探针 |
| toolbox | `${DB_TOOL_IMAGE:-ghcr.io/zeek-zhao/devbox-tool:local}`，带 mysql/psql/redis-cli/pymongo/sqlite3 客户端 | compose `services.toolbox` |
| 额外实例 | profile：`multi`（mysql2 主从）/ `cluster`（Redis 三节点）/ `tls`（自签 CA） | compose 文件头注释 |
| 镜像源 | 默认 daocloud 前缀；换源用 `DB_IMAGE_PREFIX`，不改 compose 字面量 | compose 头注释 |
| 用例计数 | `db/examples/` 93 个目录 = L 系 77（L1 40 + L2 15 + L3 12 + L4 10）+ E 系 15 + T-001 演练 1 | `ls db/examples \| wc -l` |
| 版本真本 | db 五库版本字面量**只写在 compose 里**，不进 `images/versions.env`（db 不参与语言镜像分层） | compose 本身；改版本 = 共享契约变更 |

## 2. runner 与命令入口

db 轨自带 runner，根 `scripts/run-example.sh` 一行不改（`Q-G-07`：编号与契约都独立）：

| 动作 | 命令 | 说明 |
|---|---|---|
| 起栈 | `db/scripts/up.sh` | `docker compose up -d --build`；`--profile <p>` 加实例 |
| 等就绪 | `db/scripts/wait-ready.sh` | 五条真实查询探针，`${DB_WAIT_TIMEOUT:-180}`s 超时 |
| 看健康 | `db/scripts/status.sh` | 五库 + toolbox 状态速查 |
| 单个用例 | `db/scripts/run-example.sh db L1-MY-01-create-and-types` | run.sh 跑宿主，经 compose exec 进 toolbox 连库 |
| 整门 | `db/scripts/run-example.sh db --all` | 77 个用例全跑（T-001 演练由 CI labs job 专跑） |
| 收尾 | `db/scripts/down.sh` | 手动销毁栈；runner 失败后**不会**自动 teardown，便于留现场 |
| 毕业项目 | `bash db/project/run.sh` | 端到端：下单 → 缓存 → 报表 → 日志 → 快照（不动共享栈） |

与语言轨的两点差异：①用例 `run.sh` 跑在**宿主**（不是一次性容器）；②栈是**有状态**的，
所以「幂等」由用例自己保证（独立命名空间 + 重跑先清理本项目数据），不靠容器即弃。

## 4. 用例编写约束（写新用例前必读）

- run.sh 跑宿主、`docker compose exec` 进 toolbox 执行客户端命令；stdout 确定、
  幂等可重跑（独立命名空间，命名带用例 ID，如 MySQL 库 `db_<id>`、Redis 前缀 `db_<id>:`）。
- 不挂数据卷：栈重启即全清，用例不得依赖「上一次跑留下的数据」。
- 等待策略用 `wait-ready.sh` 同款探针思路（真查询），**禁止 sleep 后假装查到了**。
- compose 是共享契约：用例卡不改编排文件；需要新实例先查现成 profile。
- 版本/镜像源一律走 compose 变量（`DB_IMAGE_PREFIX` / `DB_TOOL_IMAGE`），
  不在用例里写死镜像地址。
- 真实历史教训：daocloud 镜像源 TLS 超时曾连续打红 `用例-db`，定档
  `infra_transient`、不改用例（判例与取证见 `docs/73` §9、[docs/78](../../docs/78-CI失败分类规范.md)）。

## 5. 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `DB_IMAGE_PREFIX` | 五库镜像的 registry 前缀 | `docker.m.daocloud.io/library/` |
| `DB_TOOL_IMAGE` | toolbox 镜像 | `ghcr.io/zeek-zhao/devbox-tool:local` |
| `DB_WAIT_TIMEOUT` | wait-ready 总超时秒数 | `180` |
