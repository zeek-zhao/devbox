# db 实践指南（G1）

> 回答「什么时候该怎么用数据库轨道的用例练什么」：把 77 条用例放进真实任务视角。
> 语法细节归 G2/用例 README；排查路径归 G3（[问题指南](问题指南.md)）；命令速查归 FAQ。

## 1. 适用边界（什么时候用 / 什么时候别用）

**适用**：

- 建立跨库的通用直觉：同一件事（建模、索引、事务、迁移、备份）在 MySQL / PostgreSQL / MongoDB / Redis 里各自的形态——用例按 `L1-<库>-NN` 组织，同层横向对比；
- 工程能力（L2）：连接池超时（`L2-01-pool-timeout`）、慢查询（`L2-02-slow-query`）、索引失效（`L2-03-index-not-used`）、事务边界与死锁（`L2-04-txn-boundary-deadlock`）、schema 迁移（`L2-08-schema-migration`）、锁等待（`L2-13-lock-wait`）；
- 专题纵深（L3/L4）：复制、分片、缓存模式、数据建模（`L4-01-order-modeling` 等）。

**别用**：

- 当生产运维手册：本轨道是教学环境，口令固定、数据可随时重建（[SECURITY](../../SECURITY.md) 与 ROADMAP `KI-06` 的显式取舍）；
- 当某个具体版本的官方文档：行为以各库真本为准，用例判据只保证「输出里出现什么」，不穷举边界；
- 练 SQL 语法本身：语法不是考点，考点是「判据」一栏写的能力。

## 2. 最小可运行示例

环境三步（db 轨道走独立 Compose runner，不用语言轨道的 `TAG=latest scripts/run-example.sh` 入口）：

```bash
bash db/scripts/up.sh            # 起 mysql/postgres/mongo/redis compose 栈
bash db/scripts/wait-ready.sh    # 轮询就绪（ healthcheck 语义）
bash db/scripts/run-example.sh db L1-MY-02-crud    # 跑单条用例
```

第一条建议跑 `L1-MY-02-crud`（MySQL CRUD 与影响行数）和 `L1-PG-02-crud`（PostgreSQL RETURNING），
对比两库对「同一件事」的表达差异；再跑 `L1-MG-02-crud` 看文档模型的 CRUD 形态。

## 3. 惯用法与反模式对照表

| 场景 | 惯用法 | 反模式（可复现） |
|---|---|---|
| 找慢查询根因 | 先 `EXPLAIN` 看 `type/key/rows`（`L1-MY-04-index-explain`） | 不看执行计划直接加索引——类型不匹配时索引根本不上场（`L2-03-index-not-used` 复现） |
| 验证隔离级别语义 | 用两个会话对照读（`L1-MY-05-transaction`） | 单会话自说自话——可重复读的「快照」现象单会话根本观察不到 |
| 事务范围 | 事务只包「必须原子」的语句（`L2-04-txn-boundary-deadlock`） | 把网络调用/用户等待包进事务——锁等待放大（`L2-13-lock-wait` 复现） |
| 连接使用 | 用连接池并设超时（`L2-01-pool-timeout`） | 每请求裸建连接 + 无超时——池化意义消失且故障被放大 |

**可执行反例（无索引全表扫）**：

```bash
# 错误做法:对过滤列不建索引,然后 wonder 为什么慢
docker exec -e MYSQL_PWD=devbox devbox-db-mysql-1 mysql -uroot -e \
  "EXPLAIN SELECT * FROM big WHERE pad='xxxx'"
# 真实输出(20000 行测试表): type=ALL, key=NULL, rows=20000, filtered=10.00, Extra=Using where
# 后果:全表扫描;数据量放大 N 倍,扫描成本线性放大
```

修复对照：`CREATE INDEX` 后同类查询 `type=ref, key=idx_k, rows=20`（真实实验输出，
见 [问题指南](问题指南.md) §索引与执行计划）。

## 4. 真实工作中的变体

1. **口令管理**：本轨道口令固定（`KI-06`，教学确定性取舍）；真实工作中等价物是
   「凭据不入库、按环境注入」——compose 的 `${DB_IMAGE_PREFIX}` 环境变量替换就是
   「配置外置」的最小演示形态。
2. **toolbox 以 root 运行**：db 客户端容器默认 root（`KI-07`，暂不改的取舍见 ROADMAP）；
   真实工作中应非 root + 最小权限账号（`L2-09-least-privilege` 演示的就是这个方向）。
3. **待补**：生产级连接池参数调优（压测曲线）无真实素材，不编造；待补原因：本工程无压测用例，
   编造数字违反素材纪律（[11](../../docs/11-知识点清单增强规范.md) §7.2）。
