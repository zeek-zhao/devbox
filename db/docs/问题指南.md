## 事务与隔离

### 典型现象

「我明明提交了，另一个会话却读不到」；或反过来「事务里第一次读到的数，
后面再读还是旧的，别处提交的新行看不见」——这两个方向相反的困惑是同一枚硬币：
隔离级别的可见性语义。可复现：`L1-MY-05-transaction`。

### 先做的三个检查

1. 确认当前隔离级别：`SELECT @@transaction_isolation`（MySQL 8.4 默认 REPEATABLE READ）；
2. 确认「读不到」的两个会话是否真在同一事务边界内（autocommit 状态、有无 START TRANSACTION）；
3. 检查事务里是否混入了 DDL——MySQL 的 DDL 会隐式提交，事务边界静默改变。

### 定位命令 / 工具

```bash
docker exec -e MYSQL_PWD=devbox devbox-db-mysql-1 mysql -uroot -e \
  "SELECT @@transaction_isolation; SHOW PROCESSLIST"        # 谁在事务里/跑多久
docker exec -e MYSQL_PWD=devbox devbox-db-mysql-1 mysql -uroot -e \
  "SELECT * FROM information_schema.innodb_trx"             # 当前活跃事务
```

### 根因分类表

| 现象 | 可能根因 | 验证方法 |
|---|---|---|
| 会话 A 读不到 B 已提交的行 | REPEATABLE READ 快照读：A 的事务快照建在 B 提交之前 | 复现实验（下）；或 A `COMMIT` 后重读 |
| 同一事务两次读结果不同 | 落在 READ COMMITTED（或快照未建立） | `@@transaction_isolation` |
| 事务「莫名其妙」结束了 | 混入 DDL / 超长事务被回滚 | `SHOW PROCESSLIST` + 语句清单 |
| 死锁报错 | 两事务以相反顺序锁两行 | `L2-04-txn-boundary-deadlock`；`SHOW ENGINE INNODB STATUS` 的 LATEST DETECTED DEADLOCK 段 |

### 修复与预防

- 需要跨语句一致的读：显式 `START TRANSACTION WITH CONSISTENT SNAPSHOT` 并理解快照点；
- 缩小事务范围：只包原子必需的语句（`L2-13-lock-wait` 的反证）；
- 预防落成测试：把「可见性预期」写成判据（`L1-MY-05-transaction` 的判据即为此形态）。

### 类型②实验（真实输出，2026-11-05，mysql:8.4 容器）

会话 A 建立快照后，会话 B 插入并提交，A 的两次读：

```
first_read
1
second_read
1
[B: inserted+committed]
fresh_read
2
```

`second_read` 仍为 1（快照读），`COMMIT` 后的新会话读到 2——REPEATABLE READ 语义的直接证据。

`L1-MY-05-transaction`、`L2-04-txn-boundary-deadlock`、`L2-13-lock-wait`
（与 frontmatter `examples` 一致）。

## 索引与执行计划

### 典型现象

「加了索引查询还是慢」「EXPLAIN 里 key 是 NULL」——索引存在与索引被用是两回事。
可复现：`L2-03-index-not-used`、`L1-MY-04-index-explain`。

### 先做的三个检查

1. `EXPLAIN` 的 `type` 与 `key` 两列：`type=ALL` 即全表扫（无论索引是否存在）；
2. 过滤条件是否对索引列做了运算/类型转换（隐式转换会让索引失效）；
3. 表行数与 `rows` 列的量级是否一致（优化器基于统计信息估算，小表可能本来就不走索引）。

### 定位命令 / 工具

```bash
docker exec -e MYSQL_PWD=devbox devbox-db-mysql-1 mysql -uroot <db> -e "EXPLAIN <SQL>"
docker exec -e MYSQL_PWD=devbox devbox-db-mysql-1 mysql -uroot <db> -e "SHOW INDEX FROM <table>"
```

慢查询日志已在 compose 中打开（`--slow_query_log=1 --long_query_time=1`），
配合 `L2-02-slow-query` 使用。

### 根因分类表

| 现象 | 可能根因 | 验证方法 |
|---|---|---|
| `type=ALL, key=NULL` | 无可用索引，或条件让索引失效 | 对照实验（下）；检查列类型/函数包裹 |
| 有索引但 `key=NULL` | 小表优化器选择全扫 | `rows` 列量级对比 |
| `type=ref` 但仍慢 | 回表代价高（非覆盖索引） | `Extra` 列看是否 `Using index` |
| 计划时好时坏 | 统计信息过期 | `ANALYZE TABLE` 后复看 |

### 修复与预防

- 修数：按 `EXPLAIN` 证据补/改索引（覆盖索引优先，见 `L4-02-composite-index`）；
- 预防落成测试：判据写「`type` 必须为 ref/range、`key` 必须命中」
  （`L1-MY-04-index-explain` 的判据形态），进 CI 防退化。

### 类型②实验（真实输出，2026-11-05，20000 行测试表）

无索引（`pad` 列）与有索引（`k` 列）的 EXPLAIN 对比：

```
-- WHERE pad='xxxx'（无索引）:
type=ALL  key=NULL  rows=20000  filtered=10.00  Extra=Using where
-- CREATE INDEX idx_k ON big(k) 后 WHERE k=42:
type=ref  key=idx_k  ref=const  rows=20
```

### 相关用例 ID

`L1-MY-04-index-explain`、`L2-02-slow-query`、`L2-03-index-not-used`、`L4-02-composite-index`。

## 连接与就绪（含连接池）

### 典型现象

栈刚起客户端就报错：`ERROR 1045 (28000): Access denied`（账号/凭据类）或
connection refused（服务未就绪）；或运行期「池耗尽、获取连接超时」（`L2-01-pool-timeout`）。

### 先做的三个检查

1. 报错是拒绝（服务在但拒你）还是超时（服务不在/不就绪）？——两者根因树完全不同；
2. 账号与口令：本轨道 MySQL 只有 root 账号（compose 仅设 `MYSQL_ROOT_PASSWORD`），
   用 `devbox` 账号连 MySQL 会得到 Access denied（类型②实验真实复现）；
   PostgreSQL/Mongo 才是 `devbox` 账号；
3. 就绪判断是否用了 healthcheck（`wait-ready.sh` 的轮询语义），而不是 sleep 猜。

### 定位命令 / 工具

```bash
docker compose -f db/docker/docker-compose.yml ps        # 各服务 health 状态
docker logs devbox-db-mysql-1 --tail 50                   # 服务端视角的拒绝原因
bash db/scripts/wait-ready.sh                             # 就绪轮询（up 后必跑）
```

### 根因分类表

| 现象 | 可能根因 | 验证方法 |
|---|---|---|
| `Access denied for user 'devbox'` | MySQL 无此账号（只有 root） | 用 root 重试；`L1-MY-06-user-grant` 看账号体系 |
| connection refused | 容器未就绪/未起 | compose ps 看 health |
| 池获取超时 | 连接未释放（泄漏）或池上限过小 | `L2-01-pool-timeout`；`SHOW PROCESSLIST` 看连接占用 |
| 偶发断连 | wait_timeout / 网络抖动 | 服务端日志 + 客户端重连策略 |

### 修复与预防

- 起栈后必须过 `wait-ready.sh` 再跑用例（run-all.sh 的既有顺序就是防御）；
- 连接必须归池（`L2-01-pool-timeout` 的判据）；账号最小权限（`L2-09-least-privilege`）；
- 已知限制留痕：db toolbox 容器仍以 root 运行（`KI-07`，**取舍**，不是待办）——来源：`S-04`。

### 类型②实验（真实输出，2026-11-05）

```
ERROR 1045 (28000): Access denied for user 'devbox'@'localhost' (using password: YES)
```

（MySQL 容器用 devbox 账号连接；该账号在 MySQL 服务里不存在——账号类拒绝的典型样本。）

### 相关用例 ID

`L2-01-pool-timeout`、`L2-09-least-privilege`、`L1-MY-06-user-grant`、`L2-10-conn-security`。
