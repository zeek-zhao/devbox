# Python 知识点清单

## 1. 怎么用这份清单

每个 KP 编号对应一个建议用例 ID；L1 聚焦单文件可运行的语言特性，L2 聚焦测试、工具和项目工程，L3 聚焦并发、性能与二进制接口。验收以可重复的程序输出、退出状态或检查器结果为准，不以主观描述为准。

本清单针对 Python 3.12.3、pytest 9.2.0、ruff 0.17.3 和 mypy 2.4.1。容器无外网且只用标准库；pytest、ruff、mypy 是镜像已提供的验收工具，不是用例运行时可额外安装的依赖。

## 5. L4 设计模式专题

L4 是**专题层**：不再引入新语法，而是把 L1–L3 的能力组合成可复用的结构。
本层素材整理自外部 `python-sample` 仓库的既有实现（cpp/python 有现成单文件，go 需拆分，
java 按本表判据实现），一个模式一个用例，共 23 例。

**与 L1–L3 的三点不同**：

1. 用例一律标 `coverage: pending` —— 设计模式是**可复用结构**的练习，不强制接入毕业项目；
   是否纳入 `--strict` 收口见 `devbox-待办清单.md` 的待定项。
2. 判据只允许「stdout 固定文本 / 退出码 / 编译结果」，**不许出现耗时、随机、并发调度顺序**。
3. 同一模式在四门语言里 ID 相同（`L4-0NN-<slug>`），便于横向对照。

### 为什么 L4 不计入 R-E-01 的每语言 55 软目标

R-E-01 的软目标衡量的是「语言能力覆盖」，L4 是**结构复用**专题，与 L1–L3 的知识点不重叠。把 23 例计入后每语言 76 例，已超出 47–59 区间，这是**有意的范围扩展**，不是漏算。

## 6. 明确不覆盖的

| 内容 | 为什么不覆盖 |
|---|---|
| 需要额外安装的第三方库及其专属 API | 镜像无外网且依赖缓存不可用，用例只能依赖已提供的标准库和验收工具。 |
| 需要访问外部网络或在线服务的行为 | 网络状态、凭据和服务响应无法保证，不能形成离线、稳定的逐字验收。 |
| 需要编译安装的 Python 扩展 | 容器约束不允许依赖临时编译扩展，且会把考点从语言行为转为平台构建。 |
