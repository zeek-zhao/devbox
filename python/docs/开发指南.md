# Python 轨道开发指南（G2）

> 回答「从零到能改」：环境、目录、一条命令跑通、改动循环。
> 语法本身归知识点清单与 L1 用例，本文只讲本轨道的工程动线。

## 1. 环境与启动

- 镜像：`ghcr.io/zeek-zhao/devbox-python:${TAG:-latest}`（语言名到镜像层的映射真本是 `images/lang-images.tsv`）。
- 版本号只读 `images/versions.env` 的 `${PYTHON_VERSION}`（当前 3.12 系），禁止在文档或 Dockerfile 里另写常量。
- 语言层与 runtime 层的模块集合差异：
  - `devbox-python`（语言层）带完整工具链：python3、pip、uv、ruff、mypy、pytest、pytest-cov、ipython（实测见 [工具指南](工具指南.md) §1）；
  - `devbox-runtime`（部署运行时）只装 `python3-minimal`，没有 pip/ruff/mypy/pytest。所以 `python/project/src/` 只依赖标准库，`tests/` 里的开发期知识点验证不会进 runtime。
- 容器以 `--network none` 离线运行：用例和项目构建只用镜像里已有的东西，不要指望运行时联网装包。
- 本地没有镜像时，按仓库构建入口 `scripts/build-images.sh` 建，或拉 CI 发布的 tag；日常用例执行用 `TAG=latest scripts/run-example.sh python <ID>`（宿主已有本地镜像时把 `TAG` 换成 `local`）。

## 2. 目录结构与各文件职责

```text
python/
├── examples/<ID>/        # 74 个用例；每个目录 run.sh（自编译自运行）+ expected.txt（逐行期望输出）
├── project/              # 毕业项目：CSV 数据处理与报表
│   ├── src/main.py       # CLI 入口（clean / summary / report）
│   ├── src/csv_report/   # 校验、聚合、表格、临时资源管理；只用标准库
│   ├── tests/            # pytest 与开发环境知识点验证（pytest、mock 等只出现在这里）
│   ├── build.sh          # 宿主入口转容器内执行：ruff check → mypy --strict → pytest
│   ├── check-runtime.sh  # 固定输入逐字比对（runtime 语义自检）
│   └── COVERAGE.md       # 74 个用例在项目里的实际落点或豁免
└── docs/                 # 知识点清单、清单自检、本指南三件套（G2/G4/G5）

ruff.toml                 # 仓库根：Python 格式化与 lint 的唯一真本（门禁文件）
images/lang-images.tsv    # python → devbox-python 的映射真本
```

## 3. 一条命令跑通

```bash
TAG=latest scripts/run-example.sh python L0-hello
```

真实跑通记录：在 215 宿主机上 `TAG=latest scripts/run-example.sh python L0-hello` 输出 `python/L0-hello  PASS (1s)`；`L2-005-ruff-check` 同样 PASS。列出全部用例：`scripts/run-example.sh python --list`。

失败先看哪里（按成本从低到高）：

1. 报错含 `manifest unknown` / 拉取失败 → 本机没有该 tag 镜像，`docker images | grep devbox-python` 确认，再决定拉取或本地构建；
2. 输出与 `expected.txt` 不一致 → 用 `scripts/run-example.sh python <ID> --keep` 保留容器，`docker exec` 进去单独跑 `run.sh` 复现；
3. `run.sh` 自身报错（语法、缺文件）→ 对照 runner 顶部注释里的目录契约：`run.sh` 只往 stdout 打业务输出，`expected.txt` 规则是逐行精确、忽略行尾空白与首尾空行。

## 4. 改动循环（改 → 格式化 → lint → 测试 → 提交）

```bash
# 1) 改：examples/<ID>/ 或 python/project/src|tests
# 2) 格式化（仓库级入口，走容器，宿主无需装 ruff）
make fmt
# 3) lint + 类型 + 测试（Python 轨道一条命令全做）
bash python/project/build.sh
# 4) 只查不改（CI 语义）
make fmt-check
# 5) 提交：身份与规范见 T0
git add <文件> && git commit
```

- `python/project/build.sh` 内部依次执行 `ruff check src tests`、`mypy --strict src`、`python3 -m pytest -q tests`，全在 `devbox-python:${TAG:-latest}` 容器内离线跑。
- ruff 循环：`ruff format` 管排版、`ruff check` 管 lint，一个工具两件事；规则真本是仓库根 `ruff.toml`（target py312、line-length 100、只格式化 `*.py`/`*.pyi`）。改规则只改这一个文件。
- 提交身份（user.name/user.email）、门禁与 PR 约定是跨语言通用内容，见 T0。
