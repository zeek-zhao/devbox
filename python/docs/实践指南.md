# Python 实践指南（G1）

> 回答「什么时候用 Python 轨道的哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 命令契约（规范 §4.3）：统一 `TAG=latest scripts/run-example.sh python <ID>`；
> 版本只写 `images/versions.env` 的变量名（`${PYTHON_VERSION}`，版本引用契约 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 Python 工程能力——L1 语言与标准库
基础（可变性与身份、切片拷贝、函数签名与作用域、闭包、装饰器、异常链、dataclass）、
L2 工程能力（包结构与导入、pytest、mypy/ruff、logging、subprocess、pathlib、
importlib.resources）、L3 专题（asyncio 超时、multiprocessing、cProfile、
ctypes、GIL 与 CPU 密集），共 74 个用例；终点是 `python/project` 的毕业项目
「CSV 数据处理与报表」（流式读取、清洗去重、分类聚合、确定性文本报表，
`src/` 只依赖 runtime 已有的标准库）。每一层都用「可观察判据」验收：用例跑通、
输出与 `expected.txt` 逐行一致（口径见 [开发指南.md](开发指南.md)）。

**什么时候别用本指南**：

- 想学某个语言特性本身（描述器协议、`__defaults__` 的底层语义）——直接跑对应
  L1 用例，指南不讲语法，读了也学不会；
- 想找某个具体故障的排查路径（venv 串味、可变默认参数累积）——去
  [问题指南.md](问题指南.md)（G3，按问题域组织）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）；
- 想在运行时装第三方依赖——用例容器 `--network none` 离线启动，运行时安装的包
  不进镜像；要加依赖改 `images/scripts/install/python.sh` 走镜像重建
  （详见 [工具指南.md](工具指南.md)）。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令（可变默认参数这个考点的「正主」在用例里，不在指南里）：

  ```bash
  grep 'L1-007-mutable-default' python/docs/知识点清单.md
  ```

  输出会指向 `KP-PY-L1-07` 行与建议用例 `L1-007-mutable-default`。
- 后果：只读不跑，等于没碰过解释器；「默认表达式只在定义时求值一次」这种结论
  背十遍，不如真看一次两个调用长度变成 `1`、`2`。正确动作是
  `TAG=latest scripts/run-example.sh python L1-007-mutable-default`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（`KI-05` 定案：L0 表示镜像与 runner 通路
验证，不属于知识难度层级），它验证镜像能运行 Python（版本真本
`images/versions.env` 的 `${PYTHON_VERSION}`），与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh python L0-hello
# 实测输出：python/L0-hello               PASS (0s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见
  环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh python L0-hello
  ```

- 后果（实测）：runner 输出 `FAIL (exit!=0)`，stderr 含
  `docker: Error response from daemon: manifest unknown`，以非零退出。
  通路用例 1 秒内就能把这类环境问题暴露出来；不验通路时，同样的错误会发生在
  你等得最久的那一步，且难以与代码 bug 区分（素材池 `S-06`）。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| 每个项目一个虚拟环境，装包先确认 `python3 -m pip -V` 里的路径属于哪个环境（见 [问题指南.md](问题指南.md) 虚拟环境节） | 直接对系统解释器 `python3 -m pip install ...` | 本镜像按 PEP 668 标记为 externally-managed，实测直接装包报 `error: externally-managed-environment` 退出码 1；绕过它（`--break-system-packages`）会把系统工具链（ruff/mypy/pytest 都靠它）搅乱 |
| 排查导入问题时先看 `sys.executable` 与 `sys.path`（见 `L2-001-package-imports`） | 靠「我明明装过了」的直觉继续试 | 装进 venvA 的包对 venvB 与系统解释器都不可见，实测 `ModuleNotFoundError`；直觉不定位环境，只浪费时间 |
| 可变默认参数一律 `None` 哨兵 + 函数体内新建容器（见 `L1-007-mutable-default`） | `def f(x, acc=[])` 直接累积 | 默认表达式只在定义时求值一次，跨调用共享同一个列表，实测长度 `1`、`2` 依次增长；这是 `KP-PY-L1-07` 的核心考点（反例见下） |
| 闭包需要「当时」的值就用默认参数固定（`lambda i=i: i`，见 `L1-010-closure-late-binding`） | 循环里造 `lambda: i` 期望捕获循环当前值 | 闭包捕获的是变量绑定不是值，调用时全取最后一个；与可变默认参数同属「求值时机」一族陷阱 |
| 区分对象身份与值相等：单例（`None`）用 `is`，其余用 `==`（见 `L1-002-mutability-identity`） | 到处用 `is` 比较「相等」 | 小整数/短字符串缓存会让 `is` 碰巧为真，换解释器就翻车；可变性判断同理不能靠外层直觉 |
| 包内资源用 `importlib.resources` 读（见 `L2-012-package-resources`） | 拼源码目录相对路径 | 打包/换工作目录后路径就断；资源 API 不依赖 cwd |
| 一律经 runner 跑用例 | 手写 `docker run python3 main.py` 复刻 runner | CI 与本地用同一个 runner（真本 `scripts/run-example.sh`）；口径分裂造成「本地假绿」（素材池 `S-01`：TAG 与 IMAGE_TAG 名字不一致曾让 6 个用例 job 全红） |
| 版本只引用 `images/versions.env` 变量 | 在文档/脚本里手写 Python 版本常量 | 升级时手写常量集体过期，且过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：可变默认参数跨调用累积**

- 错误做法：

  ```python
  def add_tag(tag, tags=[]):
      tags.append(tag)
      return tags

  print(add_tag("a"))
  print(add_tag("b"))
  print(add_tag.__defaults__)
  ```

- 复现命令（在 `${PYTHON_VERSION}` 真本对应的 `devbox-python:latest` 镜像里实测）：

  ```bash
  docker run --rm "ghcr.io/zeek-zhao/devbox-python:${TAG:-latest}" python3 - <<'PY'
  def add_tag(tag, tags=[]):
      tags.append(tag)
      return tags
  print(add_tag("a"))
  print(add_tag("b"))
  print(add_tag.__defaults__)
  PY
  ```

- 后果（实测输出，原样记录）：

  ```text
  ['a']
  ['a', 'b']
  (['a', 'b'],)
  ```

  两次「独立」调用共享同一个列表，`__defaults__` 里就是那个被污染的对象。
  改成 `tags=None` + 函数体内 `tags = []` 后，两次输出都是 `['b']` 型的独立结果
  （实测分别为 `['a']`、`['b']`）。用例 `L1-007-mutable-default` 把两组写法
  放在同一个 `expected.txt` 里对照验收。

## 4. 真实工作中的变体

**变体 1：用 uv 管理虚拟环境（本镜像的示范路径）**
镜像预装 uv（安装脚本 `images/scripts/install/python.sh` 自述「uv 管理虚拟环境」），
`uv venv` 建环境、`uv pip install --python <venv>/bin/python ...` 显式指定目标
解释器装包——把「装进哪个环境」从隐式默认变成显式参数，正是上面反例里
「装错环境」的直接预防。注意用例容器离线，`uv`/`pip` 在容器内只能操作本地已有
的包，装不了一个新名字（实测见 [问题指南.md](问题指南.md)）。

**变体 2：runtime 层镜像的可用模块集合比语言层小**
`devbox-runtime` 只有 python3 解释器本体与最小运行库，实测连 `import json` 都报
`ModuleNotFoundError: No module named 'json'`（2026-11-05 在
`ghcr.io/zeek-zhao/devbox-runtime:latest` 容器内实测）。语言层镜像与 runtime 层
的模块集合差异是真实约束：毕业项目 `src/` 因此只依赖 runtime 已有的标准库，
脚本 COPY 进 runtime 前要核对依赖（docs/20 §3.5；runtime 注释曾写
`python3-minimal`、实际 `apt install python3`，口径漂移登记为 `Q-S-08`，
素材池 `S-05`）。

**变体 3：需要可复现的构建结果**
`:latest` 随 main 变动（`KI-08`），复现某个历史结果时用 CI 每次构建都打的
`sha-<commit>` 标签：`TAG=sha-<commit-sha> scripts/run-example.sh python <ID>`。
本地调试自建镜像时 `TAG` 缺省会落到 `local`（真本 `scripts/run-example.sh`：
`TAG="${TAG:-${IMAGE_TAG:-local}}"`），`local` 只是本地约定，不要写死进文档或
CI 配置。

**反例（可执行）**

- 错误做法：并发任务都依赖可变标签 `:latest`。
- 复现思路（真实历史 bug `#184`，素材池 `S-02`）：两个任务同时跑，A 推的
  `:latest` 被 B 覆盖，A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」
  无法区分。
- 可直接观察 tag 风险的命令（实测）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh python L0-hello   # manifest unknown，rc=1
  ```

- 后果与修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  需要固定版本时优先 sha 标签。
