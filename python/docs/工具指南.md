# Python 轨道工具指南（G4）

> 镜像内工具清单、调用方式、选型与常见误用。所有「是否预装 / 版本」结论来自
> 2026-11-05 在 215 上对 `ghcr.io/zeek-zhao/devbox-python:latest` 的容器实测
> （`docker run --rm ghcr.io/zeek-zhao/devbox-python:${TAG:-latest} bash -lc '<cmd>'`）。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源 |
|---|---|---|---|
| python3 | 解释器 | 预装（实测 `Python 3.12.3`） | `images/versions.env` 的 `${PYTHON_VERSION}`（主次版本锁 3.12） |
| pip | 包管理 | 预装（实测 pip 24.0） | 随系统 python3-pip；构建脚本未单独锁 |
| ruff | 格式化 + lint | 预装（`/usr/local/bin/ruff`，实测 0.17.3） | 构建脚本 pip 安装，未锁版本；升级由镜像重建带来 |
| pytest | 测试 | 预装（实测 9.2.0） | 同上；`pytest-cov` 一并预装 |
| mypy | 类型检查 | 预装（实测 2.4.1） | 同上 |
| uv | 虚拟环境与依赖管理 | 预装（实测 0.13.6） | 同上 |
| ipython | 交互式探查 | 预装（实测 9.18.0） | 同上 |

> ruff/pytest/mypy 的补丁号没进 `images/versions.env` 真本，上表数字是**实测快照**，不是承诺值；
> 判「版本变了没有」以容器里 `--version` 输出为准，不要背表。

## 2. 每工具一节

### ruff（格式化 + lint，唯一真本 ruff.toml）

- 装在哪：语言层镜像 `/usr/local/bin/ruff`；规则真本是**仓库根** `ruff.toml`（门禁文件）。
- 怎么调：单文件/项目内 `ruff format <路径>`、`ruff check <路径>`；仓库级统一入口 `make fmt` / `make fmt-check`（走容器，宿主无需装）。
- 参数速查：`ruff check --fix` 自动修复；`ruff format --check` 只查不改（CI 语义，等价 `make fmt-check`）。
- 相关用例：见 L2-005-ruff-check。
- 注意：`ruff.toml` 的 `include` 只放行 `*.py`/`*.pyi`，因为 ruff 0.17 起会连带格式化 Markdown 里的 ```python 代码块，而教学文档里的代码块常是刻意反例。

### pytest

- 装在哪：语言层镜像，`python3 -m pytest` 与 `pytest` 均可。
- 怎么调：项目内 `python3 -m pytest -q tests`；独立跑测试的完整命令见 `python/project/README.md`。
- 参数速查：`-q` 安静输出；`-k <表达式>` 按名筛选；`--tb=short` 缩短栈；覆盖率用 `--cov`（pytest-cov 已预装）。
- 相关用例：见 L2-002-pytest-basics、L2-011-mock-boundaries。

### mypy

- 装在哪：语言层镜像。
- 怎么调：`mypy --strict src`（毕业项目的口径是 src 严格、tests 不强求）。
- 相关用例：见 L2-003-typing-protocols、L2-004-mypy-check。

### python3 / pip

- 怎么调：`python3`（Ubuntu 24.04 的系统解释器，版本锁 `${PYTHON_VERSION}` 主次版本）。
- PEP 668：24.04 的 pip 受保护，镜像构建脚本装全局工具时用 `pip install --break-system-packages`；这是**镜像构建期**的事，见 `images/scripts/install/python.sh`。

### uv / ipython

- uv：极快的依赖解析与虚拟环境管理，镜像里作为「现代 Python 工程」示范；`uv --version` 确认可用。
- ipython：交互式探查容器内对象行为（比 `python3 -c` 舒服），进容器方式见 [开发指南](开发指南.md) §3 的 `--keep`。

## 3. 选型对比

| 需求 | 本工程选择 | 为什么 | 同类 |
|---|---|---|---|
| 格式化 | ruff format | 与 ruff check 同一工具同一配置，避免 black+isort 多真本漂移 | black、isort（未装） |
| lint | ruff check | 规则集与格式化共用一份 `ruff.toml` | flake8、pylint（未装） |
| 测试 | pytest | 断言即代码、fixture 体系，教学表达力优于 unittest | unittest（标准库自带，仅作对照知识） |
| 类型检查 | mypy | `--strict` 档位适合教学收敛 | 不适用：镜像内无第二同类工具 |

## 4. 常见误用

1. **另建 pyproject.toml/setup.cfg 配置 ruff**。后果：出现第二配置真本，本地 `ruff check` 与 CI（读仓库根 `ruff.toml`）口径漂移，出现「本地绿 CI 红」。规则改动只落 `ruff.toml`。
2. **运行时在容器里 `pip install` 装依赖**。后果：用例容器以 `--network none` 离线启动，直接失败；即使联网装成功，也只活在本机，别人照文档跑不通。要加依赖改 `images/scripts/install/python.sh` 并走镜像重建。
3. **在仓库根裸跑 `ruff format .`**。后果：绕过 `ruff.toml` 的 `include` 限制时可能扫进文档里的 ```python 反例代码块并「修好」它们，反例失效。统一走 `make fmt`。
4. **把 mypy 的检查范围当成 src + tests**。后果：以为测试代码也被严格类型检查，实际上毕业项目口径是 `mypy --strict src`；给 tests 添类型注解的收益要靠 pytest 侧验收，别指望 mypy 兜底。
