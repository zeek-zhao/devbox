# Python 工程参考（G4 · 参考）

> 本文只有一个主要承诺：**Python 轨道的工程事实速查**——镜像、构建、运行、依赖、
> 环境变量、版本真本，一张表对齐，全部可从仓库内文件复核。
> 通用开发动线（runner 细节、CI、门禁、提交纪律）是 T0 真本：
> [docs/13-通用开发指南](../../docs/13-通用开发指南.md)，本文只写 Python 轨差异。

## 1. 工程全景表

| 域 | 事实 | 真本出处 |
|---|---|---|
| 镜像 | `ghcr.io/zeek-zhao/devbox-python:latest`（本地自建时 `TAG` 用 `local`） | `images/python/Dockerfile`、`images/lang-images.tsv` |
| 解释器 | CPython `${PYTHON_VERSION}`（真本 `images/versions.env`，Dockerfile 不写字面量） | `images/versions.env` |
| 构建 | `bash python/project/build.sh`（ruff → mypy --strict → pytest 一条龙） | `python/project/build.sh` |
| 运行用例 | `TAG=latest scripts/run-example.sh python <ID>` | `scripts/run-example.sh`、[docs/13](../../docs/13-通用开发指南.md) §1 |
| 列出用例 | `scripts/run-example.sh python --list` | 同上 |
| 依赖 | 只用标准库 + 镜像内预装工具（pytest/mypy/ruff），运行期零第三方依赖 | `python/examples/` 各用例、`ruff.toml` |
| 环境变量 | `TAG` / `IMAGE_TAG` / `REGISTRY` / `PYTHONDONTWRITEBYTECODE` | 本文 §5 |
| 版本真本 | 镜像内一切版本号只来自 `images/versions.env` | `scripts/check-version-truth.sh` |
| 用例计数 | `python/examples/` 89 个目录 = L 系 74（L0 1 + L1 32 + L2 12 + L3 6 + L4 23）+ E 系 15 | `ls python/examples \| wc -l` |

## 2. 镜像层与版本真本

- Python 镜像继承 base → tool 层（`make build-base build-tool build-lang`，
  [docs/01](../../docs/01-镜像体系.md)）；语言层 ARG 只有 `${PYTHON_VERSION}`
  与 `PIP_INDEX_URL` 两个，值一律来自 `images/versions.env`，Dockerfile 禁止写死版本号
  （`scripts/check-version-truth.sh` 卡）。
- 用例命令里的 `TAG=latest` 与 CI 传入的 `IMAGE_TAG` 是同一个值的两个名字；
  历史教训见 [docs/13](../../docs/13-通用开发指南.md) §1。
- 镜像拉不动时先看 CI 的 `probe` job——那是镜像问题不是代码问题。

## 3. 构建与运行

| 动作 | 命令 | 说明 |
|---|---|---|
| 轨道质量门禁 | `bash python/project/build.sh` | ruff（lint）→ mypy --strict（类型）→ pytest（测试），任一步非零即红 |
| 单个用例 | `TAG=latest scripts/run-example.sh python E-003-exception-chaining` | stdout 逐行比对 `expected.txt` |
| 整门语言 | `TAG=latest scripts/run-example.sh python --all` | 全量 89 个用例 |
| 保留现场 | `TAG=latest scripts/run-example.sh python <ID> --keep` | 容器不销毁，`docker exec` 进去复现 |
| 全仓格式检查 | `make fmt-check` | 口径随仓库统一脚本（ruff format） |
| 全仓 lint | `make lint` | ruff 规则集真本 `ruff.toml`（仓库根） |

失败时先看哪里：runner 最后一段输出指明是导入失败、超时还是期望输出不匹配；
再 `--keep` 进容器看现场；最后才怀疑镜像（[docs/13](../../docs/13-通用开发指南.md) §1）。
build.sh 门禁红时按红的那一步修：ruff 红看规则号，mypy 红看类型行，
pytest 红看失败断言。

## 4. 依赖纪律

- **运行期只用标准库**：`python/examples/` 各用例不 import 任何第三方包；
  离线容器没有 PyPI 缓存（`PIP_INDEX_URL` 只服务镜像构建期，不是用例运行期）。
- 开发工具（pytest/mypy/ruff）已预装在镜像内，版本随镜像层走，不在文档里写死；
  需要新工具时走 `images/versions.env` → Dockerfile ARG 流程。
- 类型与 lint 口径：`mypy --strict`、`ruff.toml`（仓库根真本），对应
  用例 `L2-004-mypy-check`、`L2-005-ruff-check`。

## 5. 环境变量速查

| 变量 | 谁读 | 作用 | 与错误处理的关系 |
|---|---|---|---|
| `TAG` | `scripts/run-example.sh` / `python/project/build.sh` | 选镜像 tag，文档统一写 `TAG=latest` | 跑 E 系演练用例的前置 |
| `IMAGE_TAG` | CI | `TAG` 的 CI 别名，同一个值 | 禁止在文档里混用两个名字 |
| `REGISTRY` | `scripts/run-example.sh` | 镜像仓库前缀，缺省读 `images/versions.env` 的 `${REGISTRY}` | 私有部署时改 |
| `PYTHONDONTWRITEBYTECODE` | CPython | 不写 `__pycache__`，保持容器内目录干净 | build.sh 内已固定导出 |

## 6. 常见误用

1. **在文档/用例里写死解释器版本号**（如 `python3.12.x`）：版本只许引用
   `${PYTHON_VERSION}` 变量名，字面量随升级集体过期——
   [docs/11](../../docs/11-知识点清单增强规范.md) §4.4 版本引用契约。
2. **把 `TAG=latest` 写成 `devbox-python:local` 这类硬编码 tag**：本地自建镜像时才用
   `local`，文档统一 `TAG=latest`（[docs/13](../../docs/13-通用开发指南.md) §1 命令契约）。
3. **演练目录不按 `T-NNN-` 命名，或漏写 README 的 `coverage: exempt`**：2026-11-12 `#390` 起
   演练统一放 `<lang>/examples/T-NNN-<slug>/`（计入 804 口径）；非 `T-` 前缀目录会被用例 runner
   当普通用例跑（缺 `expected.txt` 即红），见 [docs/72](../../docs/72-排障演练规范.md) §1。
