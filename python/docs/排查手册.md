# Python 排查手册（G3 · 按问题域排障）

> 本文只有一个主要承诺：**按症状查到排查命令与判据**。每个小节统一四件套：
> 典型现象（可观察）→ 排查命令（可执行）→ 判据（期望输出）→ 修复（可验证）。
> §2「错误处理」章的 15 节逐一对应 15 个 E 系示范用例 README 的 exempt 指向
> （`python/docs/排查手册.md 错误处理章`）；索引速查见 [知识点清单](知识点清单.md) §E。
> 命令契约统一 `TAG=latest scripts/run-example.sh python <ID>`（[工程参考](工程参考.md) §5）。

## 1. 怎么用这本手册

1. 按症状在 §2 定位小节（每节标题即问题域）；
2. 先跑「排查命令」拿到真实输出，与「判据」对照——判据行不出现，说明故障形态与本节不同，换节或走 §3 lab；
3. 按「修复」改，重跑同一命令验证判据转绿；
4. 修完跑门禁：`bash python/project/build.sh`（ruff → mypy --strict → pytest，[工程参考](工程参考.md) §3）。

## 2. 错误处理（E 系 15 例对应节）

### 2.1 异常层次与分类处理（E-001-exception-hierarchy）

- **典型现象**：三种领域失败（输入坏 / 依赖抖动 / 自身 bug）共用一个裸 `Exception` 往上传，调用点不知道该拒绝、重试还是停机。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-001-exception-hierarchy`
- **判据**：三种异常各归唯一类别与动作，末行 `taxonomy types=3 VALIDATION=1 TRANSIENT=1 INTERNAL=1`。
- **修复**：定义领域异常层次，类别在抛出点定死，类别映射唯一动作（reject-input / retry / fail-fast）。

### 2.2 except 匹配顺序与宽窄选择（E-002-except-order）

- **典型现象**：宽 `except Exception` 写在最前，具体类型分支永远命不中，所有失败长一个样。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-002-except-order`
- **判据**：`specific-first: ValueError: ...`、`tuple-catch: KeyError: "missing"`、`fallback-last: Exception: RuntimeError: boom`，末行 `order-rule: except clauses are tried top-down, subclass handlers go first`。
- **修复**：具体类型在前、同级用元组一次捕获、宽 `Exception` 兜底殿后且只收真意外。

### 2.3 异常链的三种形态（E-003-exception-chaining）

- **典型现象**：跨层换异常类型后根因断链——`__cause__`/`__context__` 丢失，日志里只剩新异常。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-003-exception-chaining`
- **判据**：隐式链 `implicit: type=RuntimeError cause=None context=ValueError`；显式链 `explicit: ... cause=ValueError context=ValueError`；裸重抛 `bare-reraise: same-object=True cause=None`。
- **修复**：换类型用 `raise NewError(...) from e`；纯重抛用裸 `raise`；不写 `from None` 抹现场。

### 2.4 EAFP 与 LBYL 对照（E-004-eafp-lbyl）

- **典型现象**：先 `if os.path.exists` 再打开——检查通过后文件被删，使用处照样炸；两步之间有 check-then-use 窗口。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-004-eafp-lbyl`
- **判据**：命中与缺失两种情形下 LBYL/EAFP 结果一致（`lbyl-hit: got 3` vs `eafp-miss: default`），末行 `verdict: EAFP collapses check and use into one step, closing the check-then-use window`。
- **修复**：存在性/有效性检查改 EAFP（try/except），把检查与使用并成原子步骤。

### 2.5 errno 与 OSError 子类映射（E-005-errno-mapping）

- **典型现象**：按异常消息文本匹配错误类别，换个平台/语言环境就漂移；或把 EACCES 当重试错误反复重试。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-005-errno-mapping`
- **判据**：`real-missing: errno=2 type=FileNotFoundError category=MISSING action=create-or-skip`；`denied: errno=13 ... action=stop-and-report`；`transient: errno=11 ... action=retry`；末行 `mapping: errno values are the stable interface; subclasses are the built-in mapping`。
- **修复**：优先捕获内建 OSError 子类，按 errno 归类决定动作；消息文本永远不是分类依据。

### 2.6 错误路径清理顺序（E-006-cleanup-order）

- **典型现象**：多资源中途失败后不关或乱序关，资源泄漏；清理动作自身失败把主异常顶掉。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-006-cleanup-order`
- **判据**：`open: a`、`open: b`、`fail: boom` 后按 `close: b`、`close: a` 逆序回滚，随后才 `caught: boom`；可选清理失败 `suppress: continued after optional cleanup failure`。
- **修复**：嵌套 `with` / `ExitStack` 保证后开先关；可选清理用 `contextlib.suppress` 显式吞并留痕，主异常不被覆盖。

### 2.7 重试与指数退避（E-007-retry-backoff）

- **典型现象**：对参数错误（VALIDATION）盲目重试；或无退避无上限，把一次抖动放大成风暴。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-007-retry-backoff`
- **判据**：前两次 TRANSIENT 失败后第三次成功，`backoff: retries=2 delays=10,20ms`；`no-retry: ValidationError rejected immediately (age must be a positive integer)`；末行 `rule: retry only TRANSIENT errors, back off exponentially, cap the attempts`。
- **修复**：只重试 TRANSIENT 类别，指数退避（10ms、20ms…）加次数上限；不可重试类别立即拒绝。

### 2.8 快速失败与退出码协议（E-008-fail-fast-exit）

- **典型现象**：非法参数深入处理流程才炸，退出码清一色 1，上游无法按类别分流；错误详情混进 stdout。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-008-fail-fast-exit`
- **判据**：`protocol: usage=2 data=1 success=0`；`usage-error -> exit=2`、`data-error -> exit=1`、合法输入 `exit=0`；末行 `rule: fail at the boundary with a typed exit code, not deep inside`。
- **修复**：边界声明退出码协议，入口即校验即拒；错误详情进 stderr，stdout 只留可断言的协议行。

### 2.9 校验错误聚合（E-009-error-aggregation）

- **典型现象**：逐字段短路与出，一次只报一个错，用户改一轮报一个；或只数坏行不列原因。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-009-error-aggregation`
- **判据**：坏记录列出全部错误（`record 2: errors=2 name-empty age-negative`），汇总 `aggregate: bad=3 errors=5 -> report all, then reject`。
- **修复**：聚合器模式——逐记录收集全部错误、逐条列出、全部报告后再整体拒绝。

### 2.10 结构化错误日志（E-010-structured-logging）

- **典型现象**：日志是自由文本，机器答不出「TRANSIENT 失败几次」；错误类别写在消息前缀里，检索靠正则猜。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-010-structured-logging`
- **判据**：三行 JSON 日志，每行固定含 `code`、`level`、`message` 三键、键按字典序，如 `{"code": "TRANSIENT", "level": "ERROR", "message": "database unavailable"}`。
- **修复**：错误类别做成 JSON 字段（`code=`），机器可按字段直接检索统计；键序与键集固定。

### 2.11 超时与截止（E-011-timeout-deadline）

- **典型现象**：慢任务没有 deadline，线程池被死等拖垮；或超时被静默忽略、无类别无善后。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-011-timeout-deadline`
- **判据**：`deadline-hit: TimeoutError after 0.05s`、`deadline-class: TIMEOUT -> action=cancel-and-report`、`fast-path: got done`（池子没被拖垮）。
- **修复**：每个等待设截止，超时抛 `TimeoutError`、归类 TIMEOUT、取消任务善后，后续任务照常执行。

### 2.12 异常消息契约（E-012-message-contract）

- **典型现象**：`ParseError('oops')` 三项契约全不达标——没有字段名、没有实际值、没有行动建议，调用方靠猜。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-012-message-contract`
- **判据**：`contract: bad: field=False value=False action=False`；好消息 `field 'amount' got 'abc' expected integer (act: fix input)` 三项全 True；末行 `rule: messages carry field, value, expectation; secrets stay out`。
- **修复**：异常消息按契约写：字段名 + 实际值 + 期望（+ 行动建议）；凭证与敏感值不进消息。

### 2.13 未捕获异常的兜底边界（E-013-excepthook-boundary）

- **典型现象**：工作线程漏抛异常无声消失（无 excepthook 就无记录）；或兜底动作过重把整个进程拖死。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-013-excepthook-boundary`
- **判据**：`uncaught: ZeroDivisionError: division by zero`（excepthook 记一行类型+消息）+ `boundary: unexpected errors are logged once, process keeps running`。
- **修复**：装 `threading.excepthook` 兜底——每个漏抛异常记一行（类型+消息），进程按约定继续；兜底只记录，不做复杂恢复。

### 2.14 优雅降级（E-014-graceful-degradation）

- **典型现象**：降级后说不清数据来自哪一路、主源为什么被弃用；全部路径失败时抛一个不含原因的裸 RuntimeError。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-014-graceful-degradation`
- **判据**：主源失败逐字留痕（`primary failed: primary-db: TRANSIENT primary-db offline`）；`fallback: stale-snapshot (served by cache)` + `degradation: failed-sources=1`；全败时 `no-source:` 行携带每个源的原因。
- **修复**：降级链逐源留痕（来源标签 + 失败原因 + 失败源计数），全部路径失败才抛，且异常携带全部原因。

### 2.15 错误处理反模式对照（E-015-antipattern-compare）

- **典型现象**：三组反模式——静默吞错（失败无痕）、按消息文本分流（跨版本漂移）、裸 `except:` 连 `KeyboardInterrupt` 一起吞（Ctrl-C 失效）。
- **排查命令**：`TAG=latest scripts/run-example.sh python E-015-antipattern-compare`
- **判据**：`anti-1: kept going (failure swallowed, bug invisible) -> wrong` 对照 `fix-1: {...} -> logged, visible`；`anti-2: other (classified by message text) -> wrong` 对照 `fix-2: INTERNAL (classified by type) -> stable`；`anti-3: caught (wrong: bare except also swallows Ctrl-C)` 对照 `fix-3: escaped to caller`；末行 `rule: never swallow silently; classify by type; let BaseException escape`。
- **修复**：吞错处改结构化记录并分类退出；分流按类型/errno；裸 `except:` 改 `except Exception`，让 `BaseException` 逃逸。
