# Vue 开发指南（G2）

> 本文只写 Vue 轨道的差异；跨语言通用动线（runner、CI、门禁、提交纪律）以
> [13-通用开发指南](../../docs/13-通用开发指南.md) 为单一真本，不在此复制。
> 练什么看[知识点清单](知识点清单.md)，工具细节看[工具指南](工具指南.md)，小疑问看 [FAQ](FAQ.md)。

## 1. 环境与启动

- 镜像：`devbox-vue`（定义在 `images/vue/Dockerfile`，基于 `devbox-tool` 底座层）。
  版本真本只有 `images/versions.env`：Node 写 `${NODE_VERSION}`（官方 tarball，
  不走 apt/nvm），vue 三件套写 `${VUE_VERSION}`，prettier 写 `${PRETTIER_VERSION}`，
  npm 源 `${NPM_REGISTRY}`。任何文档不写字面量版本号。
- 关键取舍：镜像**刻意不装 vite**——vite 产物文件名带内容 hash，`expected.txt`
  没法逐行精确比对。用例统一走 SFC + SSR：`@vue/compiler-sfc` 编译单文件组件，
  `@vue/server-renderer` 的 `renderToString` 输出确定的 HTML 字符串。
- 全局模块靠 `NODE_PATH=/usr/local/lib/node_modules`（镜像 ENV 已设）解析，
  **只对 CommonJS `require` 生效**，所以用例统一用 `require` 而不是 `import`。
- 获取镜像：`docker pull "ghcr.io/zeek-zhao/devbox-vue:${TAG:-latest}"`；
  本地自建过镜像就用 `TAG=local`（TAG 契约见 T0 §1）。
- 交互进入容器：`docker run --rm -it "ghcr.io/zeek-zhao/devbox-vue:${TAG:-latest}" bash`。

## 2. 目录结构与各文件职责

```
vue/
├── examples/<ID>/        # 教学用例，一个目录一个考点（清单见 知识点清单.md）
│   ├── run.sh            # 自己负责运行（node 直跑，无构建步骤），只往 stdout 打业务输出
│   ├── expected.txt      # 期望输出，逐行精确（忽略行尾空白与首尾空行）
│   └── README.md         # 考点说明
├── project/              # 毕业项目（SSR todo 应用）
│   ├── package.json      # scripts: start（node src/server.js）/ smoke（test/smoke.sh）/ perf
│   ├── src/              # server.js（SSR 入口）、client.js、components/、store/、router/
│   ├── src/perf/         # 渲染性能基线（node src/perf/baseline.js）
│   ├── test/smoke.sh     # 冒烟：起 SSR 服务，断言响应含种子 todo（L2-004-unit-test-harness）
│   └── COVERAGE.md       # 覆盖表
└── docs/                 # 本指南层文档（G2/G4/G5）
```

## 3. 一条命令跑通

```bash
cd <仓库根>
TAG=latest scripts/run-example.sh vue L0-hello
```

预期：runner 在 devbox-vue 容器里运行用例，逐行比对 `expected.txt`，末尾打印
`PASS`（实测 L0-hello 约 0s、L1-002-ref-vs-reactive 约 1s）。列全部用例：
`scripts/run-example.sh vue --list`；跑整门：`TAG=latest scripts/run-example.sh vue --all`。

失败时先看哪里：

1. runner 的最后一段输出——会指明是运行报错、超时还是期望输出不匹配；
2. 加 `--keep` 保留容器，再 `docker exec` 进去手动跑 `run.sh` 对比现场；
3. 镜像都拉不到（第一步就 manifest unknown）→ 是镜像或网络问题，不是代码问题；
4. 报 `Cannot find module 'vue'` 之类 → 多半是在 ESM/`import` 语境下找全局模块
   （NODE_PATH 只对 CJS 生效），或绕开了镜像直接在宿主跑。

## 4. 改动循环：改 → 格式化 → lint → 测试 → 提交

```bash
# 1) 改代码（vue/examples/<ID>/ 或 vue/project/）

# 2) 格式化：宿主不装 prettier，统一走容器入口（fmt.sh 管 vue 轨道）
bash scripts/fmt.sh --lang vue            # 就地格式化 vue/ 下源码
bash scripts/fmt.sh --check --lang vue    # 只检查，有差异 exit 1（CI 口径）
# fmt.sh 已配好 --ignore-path /work/.prettierignore，不会重排 expected.txt / README

# 3) lint：不适用：devbox-vue 未预装 eslint（实测），本轨道门禁 = prettier 检查 + 冒烟测试

# 4) 测试：毕业项目冒烟（起 SSR 服务断言响应），容器内一条命令
docker run --rm -v "$PWD/vue/project:/work/vue/project" -w /work/vue/project \
  "ghcr.io/zeek-zhao/devbox-vue:${TAG:-latest}" bash test/smoke.sh
# 单测/渲染断言类用例直接用 runner（见 §3）；性能基线：node src/perf/baseline.js

# 5) 提交：身份白名单、Conventional Commits、禁 AI 署名尾巴——纪律见 T0 §5
git add <文件> && git commit
```

要点：

- prettier 检查是门禁不是建议：CI 的 fmt job 与本地 `fmt.sh --check` 同口径
  （L2-005-prettier-check 的考点）。
- 毕业项目依赖 `vue` 版本在 `package.json` 声明，与镜像全局 `${VUE_VERSION}`
  必须同版（vue / @vue/compiler-sfc / @vue/server-renderer 三者同版本约束）。
- SFC 编译、scoped css、script setup 等工程练法见 L2-001-sfc-compile、
  L2-017-sfc-scoped-css、L2-016-script-setup-compile。
