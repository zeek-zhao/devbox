# Vue 工具指南（G4）

> 「是否预装」全部在 `ghcr.io/zeek-zhao/devbox-vue` 镜像里实测过（2026-11-05，
> probe 命令见 §1 脚注），不是抄 README。版本一律引用 `images/versions.env` 变量名，
> 实测输出的具体版本号不写进文档——以容器当场输出为准。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源 |
|---|---|---|---|
| node | 运行时（用例与毕业项目全靠它） | 是（官方 tarball 装到 /usr/local） | `${NODE_VERSION}`（images/versions.env） |
| npm / npx | 包管理 / 脚手架执行 | 是（随 Node） | 随 `${NODE_VERSION}` |
| prettier | 格式化 .vue / .js（CI fmt job 的 vue 轨道执行器） | 是（npm 全局） | `${PRETTIER_VERSION}` |
| vue | 运行时（CJS 构建自带模板编译器） | 是（npm 全局，`NODE_PATH` 解析） | `${VUE_VERSION}` |
| @vue/compiler-sfc | 编译 .vue 单文件组件 | 是（npm 全局，与 vue 同版本） | `${VUE_VERSION}` |
| @vue/server-renderer | SSR renderToString | 是（npm 全局，与 vue 同版本） | `${VUE_VERSION}` |
| vite | 前端构建器 | 否——**刻意不装**：产物文件名带内容 hash，expected.txt 无法逐行比对 | 不适用，见 §2.4 |
| vitest / eslint / vue-tsc | 测试框架 / lint / 类型检查 | 否（实测 `command -v` 无结果） | 需自装，见 §2.4 |
| yarn / pnpm | 包管理替代 | 否（实测无结果） | 不适用：工程统一用 npm |

复跑实测的 probe 命令：

```bash
docker run --rm "ghcr.io/zeek-zhao/devbox-vue:${TAG:-latest}" bash -lc \
  'node --version; npm --version; npx --version; prettier --version;
   NODE_PATH=/usr/local/lib/node_modules node -p "require(\"vue/package.json\").version";
   for t in vite vitest eslint vue-tsc yarn pnpm; do command -v "$t" >/dev/null 2>&1 || echo "$t: 未预装"; done'
```

## 2. 每工具一节

### 2.1 node（运行时）

- 装在哪：镜像内 `/usr/local`（官方 tarball，SHA256 来自 versions.env；
  不用 apt——24.04 源里 Node 偏旧，不用 nvm——非 root 用户找不到）。
- 怎么调：容器内直接 `node ...`；镜像 ENV 已设 `NODE_PATH=/usr/local/lib/node_modules`。
- 陷阱速记：`NODE_PATH` 只对 CommonJS `require` 生效，ESM `import` 找不到全局模块；
  本工程所有用例统一 `require`。

### 2.2 npm / npx

- 装在哪：随 Node。构建期 registry 已切 `${NPM_REGISTRY}` 镜像源；运行期不需要网络。
- 怎么调（毕业项目内）：`npm start`（node src/server.js）、`bash test/smoke.sh`
  或 `npm run smoke`、`npm run perf`（渲染性能基线，见 L3-012-render-perf-baseline）。
- 装新依赖用 `npm install <pkg>` 并随 `package-lock.json` 一起提交；全局装会破坏
  镜像可重现性，不要在容器里顺手 `npm install -g` 当作依赖。

### 2.3 prettier（与 fmt.sh 的关系）

- 怎么调：工程口径统一走 `bash scripts/fmt.sh --lang vue`
  （容器内执行 `prettier --write --ignore-path /work/.prettierignore .`；
  `--check` 只查不改，CI 用它）。不要绕过 fmt.sh 直接在容器里裸跑 prettier——
  不带 `--ignore-path` 会把用例的 `expected.txt`、`README.md` 一起重排，直接打爆 diff。
- 规则真本：仓库根 `.prettierrc.json`（改它属门禁变更，走 T0 §3 例外流程）。
- 练习：L2-005-prettier-check。

### 2.4 未预装工具（vite / vitest / eslint / vue-tsc / yarn / pnpm）

- **vite 不装是设计决定**：产物 hash 让 `expected.txt` 无法固定，用例改走
  SFC + SSR 确定输出。想要构建器体验请到工程外自装，不要改镜像口径。
- vitest / eslint / vue-tsc 需要时在项目目录 `npm install --save-dev <pkg>` 自装；
  引入新的门禁（如 eslint）属于改判定标准，必须走 T0 §3 的人工评审放行。
- 包管理只认 npm：yarn / pnpm 未装也不许装——统一锁文件口径，避免多锁文件漂移。

## 3. 选型对比

- 格式化器：不适用：无同类——工程内格式化只认 prettier（.vue/.js 一体处理）。
- SSR 与构建器：@vue/server-renderer（预装、输出确定、可逐行比对）对比 vite
  （未装、产物带 hash）。选 SSR 的理由：教学用例必须输出可精确断言。
- 运行时入口：node 直跑对比 vite dev server。工程口径 node 直跑：零构建步骤、
  容器内即可复现，与 runner 的三文件契约兼容。

## 4. 常见误用

1. **在宿主机直接敲 node / prettier**：宿主（Windows 开发机、CI 构建机）没装
   Node 工具链，必然 command not found。格式化器和被测代码一样只能活在镜像里；
   宿主入口是 `bash scripts/fmt.sh --lang vue` 或按 §2 的 docker run 形式进容器。
2. **用 `import` 引全局 vue 找不到模块**：`NODE_PATH` 只对 CommonJS 生效，
   ESM 解析不理它。本工程统一 `require`；真要 ESM 请先在项目里本地装依赖。
3. **裸跑 prettier 不带 ignore**：把 `expected.txt`/`README.md` 一起重排，
   用例全红、diff 灾难。永远走 `fmt.sh`，它带好了 `--ignore-path`。
4. **给毕业项目换 vite/装 eslint「顺手改进」**：改变了镜像口径与门禁判定，
   属于改判定标准，必须走 T0 §3 的人工评审放行，不许悄悄改。
