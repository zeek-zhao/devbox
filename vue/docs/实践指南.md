# Vue 实践指南（G1）

> 回答「什么时候用 Vue 轨道的哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 命令契约（规范 §4.3）：统一 `TAG=latest scripts/run-example.sh vue <ID>`；
> 版本号只写 `images/versions.env` 的变量名（`${VUE_VERSION}`/`${NODE_VERSION}`，
> 版本引用契约 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 Vue 3 工程能力——L1 组合式 API
基础（ref/reactive、computed、watch、props 单向流、slots、provide/inject）、
L2 工程能力（SFC 编译、单测、prettier、package exports、env 配置、Teleport/
Suspense/KeepAlive）、L3 专题（响应式系统内核、hydration、composable 复用、
虚拟列表、性能基线、泄漏审计、可访问性），共 74 个用例；终点是 `vue/project`
的毕业项目。每一层都用「可观察判据」验收：用例跑通、输出与 `expected.txt`
逐行一致（验收口径见 [开发指南.md](开发指南.md)）。

**什么时候别用本指南**：

- 想学某个 API 本身（`watchEffect` 的 flush 时机细节、`defineExpose` 语义）——
  直接跑对应 L1 用例，指南不讲语法，读了也学不会；
- 想找某个具体故障的排查路径（解构丢响应性、产物里 env 变 undefined）——
  去 [问题指南.md](问题指南.md)（G3，按问题域组织：响应性陷阱、构建与产物）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）；
- 想引组件库/状态库（Element Plus、Pinia 等）——本轨道 L1–L3 用例只用
  `vue` 本体与官方运行时（镜像全局装的是 `vue` + `@vue/compiler-sfc` +
  `@vue/server-renderer`，`${VUE_VERSION}` 真本 `images/versions.env`），
  引依赖不会通过评审。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令（语法考点的「正主」在清单与用例里，不在指南里）：

  ```bash
  grep 'L1-026-to-refs-props' vue/docs/知识点清单.md
  ```

  输出会指向 KP 行与建议用例 `L1-026-to-refs-props`——props 保持响应式的
  载体是用例，不是本篇。
- 后果：只读不跑，等于没碰过运行时；解构丢响应性这类「不报错、只是悄悄失效」
  的问题只有跑断言才会现形。正确动作是
  `TAG=latest scripts/run-example.sh vue L1-026-to-refs-props`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（`KI-05` 定案：L0 表示镜像与 runner 通路
验证，不属于知识难度层级），它验证镜像能 require 到 vue 三件套并完成 SSR
渲染，与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh vue L0-hello
# 实测输出：vue/L0-hello                  PASS (1s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见
  环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh vue L0-hello
  ```

- 后果（实测）：runner 输出 `FAIL`，stderr 含
  `docker: Error response from daemon: manifest unknown`，以非零退出。
  通路用例 1 秒就能把这类环境问题暴露出来；不验通路时，同样的错误会发生在
  你等得最久的那一步，且难以与代码 bug 区分（素材池 `S-06`）。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| props 只读、单向流动（见 `L1-005-props-one-way`） | 在子组件里直接改 props，或解构 props 后用解构值 | 解构出的是当次快照，源头更新后视图不跟着动（实测反例见下）；`toRefs(props)` 才保响应（`L1-026-to-refs-props`） |
| 明确 ref 与 reactive 的分工，跨边界一律用 ref（见 `L1-002-ref-vs-reactive`） | 把 reactive 对象整体替换或解构赋值 | 整体替换/解构都会断开 Proxy 追踪；ref 通过 `.value` 保持引用稳定 |
| 大对象用 shallowRef/markRaw 控制追踪范围（见 `L3-014-shallow-markraw`） | 把整棵大列表/图表实例包成深度响应式 | 深度代理大对象是白付的遍历成本，第三方实例被代理还会出诡异 bug |
| 构建期配置显式声明：env 变量用 `VITE_` 前缀并在代码中集中读取（见 `L2-007-env-config`） | 在代码里随手读未声明的 `import.meta.env.X` | prod 构建会把它**静默内联成 `undefined`**（实测见 [问题指南.md](问题指南.md) 构建与产物节），无告警 |
| 需要运行时编译模板时显式选带编译器的构建（见 `L2-018-runtime-compiler`） | 默认 runtime-only 构建 + 字符串模板 | 产物里没有编译器，运行时报「template option but runtime compilation is not supported」 |
| 一律经 runner 跑用例；版本只引用 `images/versions.env` 变量 | 手写 `docker run`/`node` 复刻 runner；手写版本常量 | 口径分裂造成「本地假绿」（素材池 `S-01`）；手写版本过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：解构 props 丢失响应性**

- 错误做法：

  ```js
  const { reactive, effect } = require("vue");

  const props = reactive({ count: 0 });

  // 正确：经属性访问跟踪（effect 会重跑）
  let traced = -1;
  effect(() => { traced = props.count; });

  // 错误：解构出原始值，脱离响应式
  const { count } = props;

  props.count = 1;
  console.log(`props.count=${props.count} traced=${traced} destructured=${count}`);
  ```

- 复现命令（在本轨道镜像里实测）：

  ```bash
  docker run --rm -v "$PWD":/exp -w /exp \
    "ghcr.io/zeek-zhao/devbox-vue:${TAG:-latest}" node props.js
  ```

- 后果（实测输出，退出码 0——**不报错**）：

  ```
  props.count=1 traced=1 destructured=0
  ```

  源头 `props.count` 已更新、正常跟踪的 effect 也拿到新值（`traced=1`），
  但解构出来的 `count` 停留在旧值 `0`——依赖解构值的地方从此不再更新，
  且没有任何报错提示。修法：`toRefs(props)` 解构出 ref 保持连接（见
  `L1-026-to-refs-props`），或干脆不解构、始终经 `props.x` 访问。

## 4. 真实工作中的变体

**变体 1：本地已自建镜像（`make images` 或 `scripts/build-images.sh`）**
runner 的取值顺序是 `TAG` → `IMAGE_TAG` → `local`（真本 `scripts/run-example.sh`），
本地调试自建镜像时不传 `TAG` 即落到 `local`，或显式
`TAG=local scripts/run-example.sh vue <ID>`。注意 `local` 只是本地约定名，
不要写死进文档或 CI（素材池 `S-01` 的教训：两个名字各说各话）。

**变体 2：需要可复现的构建产物（对应 `L2-007-env-config` 的工程化延伸）**
prod 产物的行为在**构建时刻**就被定死（env 内联、运行时编译器是否打入），
所以「复现某个产物」= 复现同样的构建输入：显式传 env（`VITE_DECLARED=...`
形式）、固定依赖版本、固定 `${VUE_VERSION}`。要审产物别猜——对构建出的
bundle 做文本检查（grep 关键内联值），可复现且机器可判（实测见
[问题指南.md](问题指南.md) 构建与产物节）。`:latest` 随 `main` 变动
（`KI-08`），复现历史结果用 `TAG=sha-<commit-sha>`。

**变体 3：整轨回归**
改动波及面大（升级 `${VUE_VERSION}`、动公共构建配置）时跑全轨 74 例，与 CI
的 `examples` job 同款入口：`TAG=latest scripts/run-example.sh vue --all`。
SSR/hydration 类用例（`L1-016-ssr-basic`、`L3-003-hydration-mismatch`）也在
这一步一起验，不要因为本地跑过单例就跳过整轨。

**反例（可执行）：并发任务互推可变标签 `:latest`**

- 错误做法与后果（真实历史 bug `#184`，素材池 `S-02`）：A 推的 `:latest` 被
  B 覆盖，A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」无法区分。
- 可直接观察 tag 风险的命令：

  ```bash
  TAG=nosuchtag scripts/run-example.sh vue L0-hello   # manifest unknown，实测
  ```

- 修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  本地需要固定版本时同样优先 sha 标签。
