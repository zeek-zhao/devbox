# Vue 用例编写规范

本规范针对 `vue/examples/` 中以确定性输出验收的 Vue 3 用例。这里验证的是 Vue API、SFC 编译接口和 SSR 行为，不是一个浏览器开发服务器或打包项目。

## 1. 用例目录契约

每个用例目录必须恰好包含以下三个文件：

```text
vue/examples/<ID>/
├── run.sh          # 执行用例并只向 stdout 输出业务结果
├── expected.txt    # 逐行精确匹配的期望输出
└── README.md       # 考点、判据、边界与复现方式
```

`run.sh` 使用 `set -euo pipefail`，失败时返回非零；诊断或进度信息写到 stderr。编号沿用已有的 L1/L2/L3 层级和 ID，不重命名已有用例。

## 2. 构建与运行：不需要打包器

镜像固定使用 Node.js **22.11.0** 和 Vue **3.5.44**；`vue`、`@vue/compiler-sfc`、`@vue/server-renderer` 使用同一 Vue 版本。依赖由镜像全局安装，`NODE_PATH=/usr/local/lib/node_modules` 供 Node 的 CommonJS `require` 查找，因此用例直接运行 `node`，不要改成依赖 ESM 全局解析的写法。

运行流程分为两类：

1. 普通 JavaScript 用例用 `require('vue')` 创建组件或验证响应式行为。SSR 用 `createSSRApp(...)` 创建应用，并 `await renderToString(app)` 输出 HTML。
2. SFC 编译用例将 `.vue` 源码作为字符串交给 `@vue/compiler-sfc` 的 `parse`，再按考点调用 `compileScript` 或 `compileTemplate`。这些用例检查确定的编译产物片段或重复编译结果；没有把 SFC 打包成浏览器 bundle。跨文件用例则在临时目录写入普通 JavaScript 模块并由 Node 运行。

所以这里不需要 Vite、Webpack 或其他打包器：不生成带内容 hash 的 bundle，SSR 直接给出可比较的 HTML。`renderToString` 是异步操作，必须等待 Promise 完成后再输出或断言结果。临时编译文件放在 `/tmp` 或 `${TMPDIR}`，不要污染用例目录。

## 3. `expected.txt` 与输出确定性

`expected.txt` 按行精确比较实际 stdout；runner 仅归一化行尾空白和首尾空行，不会替你排序、不删除内部空行，也不会把动态值改写成占位符。stdout 只放稳定的业务结果。

除公共确定性要求外，Vue 用例特别注意：

- 不输出组件 `uid`、内部 vnode / 实例 id 或其他实现细节。
- 不输出 `Date`、渲染耗时、内存占用等运行时波动值。性能用例可像 `L3-012-render-perf-baseline` 一样只输出稳定的量级判断、计数和字节数。
- SSR HTML 的属性顺序可能影响逐字节期望值。只在顺序由输入和当前渲染路径确定时断言完整 HTML；否则提取并断言关键标签、属性或片段，不要依赖偶然的序列化顺序。
- `watch` / `watchEffect` 可断言触发次数和调度结果，但修改响应式状态后须显式 `await nextTick()` 再观察调度完成后的结果。不要依赖未刷新的时序或打印异步交错顺序。
- 集合或由对象生成的列表先显式排序；计时与异步用例只输出稳定的最终状态和计数。

## 4. SSR 与 hydration mismatch 的边界

当前用例没有浏览器，也没有执行 DOM hydration。`L3-003-hydration-mismatch` 用同一个组件分别以 `client: false` 和 `client: true` 调用 `renderToString`，比较两份 HTML，并报告零基首个差异位置及字符。两端使用固定字符串来稳定复现差异。

这只能说明服务端 HTML 与客户端首次渲染内容不一致时会形成水合风险；它不声称实际执行了水合，也不捕获浏览器的 hydration 警告。测试必须将模拟输入固定下来，避免用当前时间或随机数制造漂移。

## 5. 新增用例步骤

1. 先查看同层级相邻用例和本规范，确认主题尚未重复，并使用仓库分配的 ID 格式。
2. 创建目录及恰好三个契约文件；README 写明考点、可观察判据和 SSR/浏览器边界。
3. 选择直接 Node、SFC 编译或 SSR 路径。需渲染时等待 `renderToString`；需检查响应式调度时等待 `nextTick()`。
4. 将产物、时间、随机数和临时文件控制在确定范围内；只让 stdout 输出业务结果。
5. 通过 Vue runner 取得真实 stdout，再检查 `expected.txt`、格式和覆盖表；连跑三次确认输出逐字节一致。不要通过复制当前错误输出来掩盖实现问题。

## 6. 常见错误

| 错误 | 相关用例 / 正确边界 |
|---|---|
| 用 `createApp` 当作 SSR 应用 | SSR 用 `createSSRApp`，见 `L1-016-ssr-basic`。 |
| 没有等待 `renderToString`，输出不完整或遗漏异步内容 | 等待 Promise；异步组件和 Suspense 分别见 `L2-009-async-component`、`L2-011-suspense`。 |
| 把 SSR 当成浏览器，假定 ref 已绑定真实元素 | SSR 没有 DOM，template ref 保持 `null`，见 `L1-011-template-refs`；`nextTick` 也不会创建 DOM，见 `L1-018-nexttick`。 |
| 修改 ref 后立即断言 watcher 的调度结果 | `await nextTick()` 后再检查，见 `L1-004-watch-vs-watcheffect`。 |
| 用 `Date.now()` 或随机值模拟两端渲染差异 | 使用固定 server/client 输入，见 `L3-003-hydration-mismatch`。 |
| 把 SFC 源码直接交给 `compileScript` | 先 `parse` 并传入返回的 descriptor，见 `L2-001-sfc-compile`。 |
| SSR 输出中把 Teleport 目标内容当作主 HTML | 从 SSR context 的 `teleports` 字段取目标内容，见 `L2-010-teleport`。 |
| 忘记全局依赖通过 CommonJS 路径解析 | 使用 `require` 和镜像配置的 `NODE_PATH`，见 `L0-hello` 通路验证用例。 |
