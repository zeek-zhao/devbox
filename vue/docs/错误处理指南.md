# Vue 错误处理指南（how-to）

> 面向「要在 Vue 代码里把错误处理写对」的操作指南：按任务路由到 E 类示例，
> 每条纪律给得出用例 ID 与验证命令。从已有故障出发的排查走
> [排查手册](排查手册.md)；语法层知识归 L1/L2 用例，本篇不重复贴代码。
> 全部 15 个 E 例已于 2026-11-11 在 `devbox-vue:latest` 内真跑通过
> （`TAG=latest scripts/run-example.sh vue <ID>`，镜像层真本
> `images/lang-images.tsv`）。

## 1. 适用边界

- 适用于：在本仓库 Vue 代码（含毕业项目）里设计或修复错误处理路径——错误
  来源分类、错误对象构造、匹配分派、cause 包装、身份保持、上下文标注、
  副作用清理、吞错与重抛、异步边界、重试退避、截止时间、并行聚合、上报、
  配置 fail-fast、反模式自查。
- 不适用于：第一次学 Vue 的响应式与组件语法（见 [知识点清单](知识点清单.md)
  L1 段）；手上已经有一个故障要排查（见 [排查手册](排查手册.md)——本篇只讲
  怎么写对，不讲坏了怎么找）。
- 本篇是 how-to：只讲「做某件事的步骤」，不讲完整语法书。命令契约见
  [docs/11](../../docs/11-知识点清单增强规范.md) §4.3（统一 `TAG=latest
  scripts/run-example.sh vue <ID>`，禁止硬编码镜像 tag）。

## 3. 十条核心纪律（每条可执行、可断言）

1. **分类挂在官方字段上**（E-001）：`app.config.errorHandler` 同时接住同步
   渲染错误与异步 setup 拒绝；按 `info` 参数（setup function / render
   function）分类，不解析消息文本。
2. **错误对象带结构化三元组**（E-002）：`code` 供分派、`field` 供定位控件、
   `message` 供人读；构造统一走 `super(message)` + 显式赋值。
3. **匹配身份不匹配文案**（E-003，配合 E-002）：`instanceof` 先分类型、
   `code` 再分分支；分派表允许「不认识」（report），不允许「猜」。
4. **包装 = 上下文 + cause**（E-004）：`new Error(msg, { cause: err })` 是
   ES2022 语言标准；cause 链每层一句话、逐层可下钻。
5. **中间层透传同一引用**（E-005）：不 catch、不重包、不改写——`instanceof`
   与自定义 `code` 才能穿过组件层存活；要加上下文用 cause 包装。
6. **上下文逐层追加**（E-006）：每层 `onErrorCaptured` 只做两件事——名字
   前置进 `err.context`、`return undefined` 放行，没有一层需要知道全貌。
7. **副作用注册与清理同处声明**（E-007）：`watchEffect(onCleanup => ...)`
   让框架保证两条清理路径（重新执行前、scope 停止时）都被调用。
8. **`return false` 只留给「真的处理掉了」**（E-008）：只是「看见了」不算
   处理；原样放行用 `return undefined`，身份与 context 标注都保留。
9. **边界范围以实测为准**（E-009）：errorHandler 覆盖组件树内同步 + 异步
   setup；游离 Promise 必须在发起处显式 catch，框架替不了「没人认领」。
10. **预算写死在签名可见处**（E-010/E-011/E-012/E-014）：重试只接
    `E_TRANSIENT` 且次数封顶；`Promise.race` 给挂起请求设截止；聚合用
    `allSettled` 不短路；配置缺失在 createApp 之前 fail-fast。
