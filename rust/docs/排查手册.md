# Rust 排查手册（G3 · 按问题域排障）

> 本文只有一个主要承诺：**按症状查到排查命令与判据**。每个小节统一四件套：
> 典型现象（可观察）→ 排查命令（可执行）→ 判据（期望输出）→ 修复（可验证）。
> §2 的 15 节逐一对应 15 个 E 系示范用例 README 的 exempt 落点；各 E 例 README
> 「落点」栏指向的节号见 [知识点清单](知识点清单.md) §E 反查表。
> 命令契约统一 `TAG=latest scripts/run-example.sh rust <ID>`（[工程参考](工程参考.md) §5）。

## 1. 怎么用这本手册

1. 按症状在 §2 定位小节（每节标题即问题域）；
2. 先跑「排查命令」拿到真实输出，与「判据」对照——判据行不出现，说明故障形态与本节不同，换节或走 §3 lab；
3. 按「修复」改，重跑同一命令验证判据转绿；
4. 修完跑格式与 lint：`bash rust/project/build.sh` 或 `make fmt-check lint`（[工程参考](工程参考.md) §3）。

## 2. 错误处理（E 系 15 例对应节）

### 2.1 错误分类决策表（E-001-error-taxonomy）

- **典型现象**：外部输入解析失败直接 panic 打崩进程；或排序不变量破坏被包成 `Err` 让调用方「处理」一个 bug。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-001-error-taxonomy`
- **判据**：末行 `taxonomy: recoverable=Result, unrecoverable=panic`；可恢复分支输出 `recoverable: Err -> fallback port 0`。
- **修复**：调用方能介入的（重试/降级/取默认）→ `Result`；破坏不变量的 → `panic`/`assert!` 终止。`catch_unwind` 只用于 FFI 边界与线程池兜底。

### 2.2 退出码与诊断行口径（E-002-main-return-result）

- **典型现象**：失败退出码不是 1；或 stderr 诊断行没有错误结构（只剩一句手写文案）。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-002-main-return-result`
- **判据**：`bad-config-exit=1` 且出现 `Error: ConfigError { field: "workers", source: ParseIntError { kind: InvalidDigit } }`。
- **修复**：`fn main() -> Result<(), E>` 让 std 运行时代为打印 `Error: <Debug>` 并退出 1；不手写 `std::process::exit`。

### 2.3 unwrap/expect 治理清单（E-003-unwrap-expect-hygiene）

- **典型现象**：进程退出码 101，stderr 只有 `called Result::unwrap() on an Err value: ...` 与一条 `RUST_BACKTRACE=1` 提示，无业务语境。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-003-unwrap-expect-hygiene`
- **判据**：`unwrap-mode: exit=101`、`unwrap-mode: context-in-message=no`；对照 `handled-mode: invalid config -> fallback 0, exit stays 0`。
- **修复**：测试外的 `unwrap` 改为 `expect("此处为何不可能失败的语境")` 或完整 `match`；允许保留 `unwrap` 的只有测试与写了注释的不变量断言。

### 2.4 From/map_err 选型规则（E-004-from-vs-map-err）

- **典型现象**：每个调用点重复 `map_err` 转换样板；或转换时 `.to_string()` 销毁类型，根因丢失。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-004-from-vs-map-err`
- **判据**：`question-mark is From::from: true` 且 `err path equal: true`（两条路径产出的错误值逐字段相等）。
- **修复**：一个目标类型占主导 → 实现 `From<源> for 目标`，调用点裸 `?`；调用点需要携带本层信息 → `map_err` 显式转；二者产出必须一致。

### 2.5 Box dyn 与具体 enum 的边界取舍（E-005-box-dyn-error）

- **典型现象**：多种异构错误各自为政，一个函数里出现五种错误类型签名；或为不关心的来源硬造枚举变体。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-005-box-dyn-error`
- **判据**：`heterogeneous errors handled at one boundary: 2`（两类异构错误在同一 match 边界处理）。
- **修复**：应用层聚合边界用 `Box<dyn Error>` 收拢；需要针对性恢复的分支 `downcast_ref::<T>()` 取回具体类型；库层仍返回具体枚举。

### 2.6 上下文分层与 source 链规范（E-006-context-layering）

- **典型现象**：顶层只报「解析失败」，不知道失败发生在哪个业务动作里；`source` 链被 `.to_string()` 截断。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-006-context-layering`
- **判据**：`top context: loading document for search index` → `next layer: parsing document id from \`seven\`` → `root cause: invalid digit found in string`，且 `context stack depth: 3`。
- **修复**：每跨一层业务边界附加「这层在做什么」的语境；顶层报告沿 `source()` 走到底逐层打印；不手写拼接。

### 2.7 聚合 vs 短路的场景对照（E-007-error-aggregation）

- **典型现象**：批量输入只报第一个失败，修一行重跑一次才发现下一处也坏。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-007-error-aggregation`
- **判据**：`aggregated: 3 ok, 2 failed` 且 `failed: row 1: ...`、`failed: row 3: ...` 两行齐全。
- **修复**：配置/导入类输入用聚合（一次报出全部行号与原因）；链路依赖类保持短路（`all-or-nothing short-circuits: true`）。

### 2.8 重试分类与退避参数口径（E-008-retry-backoff）

- **典型现象**：瞬时抖动一次失败直接报错；或对 schema 不匹配这类永久故障盲目重试，放大成持续压垮对方的流量。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-008-retry-backoff`
- **判据**：`retry: recovered after transient errors, value payload`；`broken: no retry on permanent error (schema mismatch)`；末行 `policy: retry transient with exponential backoff, fail fast on permanent`。
- **修复**：错误先分 Transient/Permanent；瞬时错误指数退避（1ms、2ms、4ms……）上限 5 次；永久错误立即上抛。

### 2.9 迭代器错误流选型（E-009-iterator-error-flow）

- **典型现象**：`filter_map(Result::ok)` 静默丢错，失败项无痕消失；或 `collect` 让单个坏元素毁掉整批。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-009-iterator-error-flow`
- **判据**：`collect all: true`、`try_fold: short-circuited`、`ok-only: [2, 4, 8]`、`partition: 3 ok, 1 err` 四行齐。
- **修复**：按语义选型——全收 `collect`、遇错即停 `try_fold`、显式分区 `fold`；排障阶段禁用 `filter_map(Result::ok)` 静默丢弃。

### 2.10 fail-fast 边界与副作用隔离（E-010-fail-fast-validation）

- **典型现象**：边解析边执行，第 1 行已写入、第 2 行才失败，留下半批脏数据。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-010-fail-fast-validation`
- **判据**：`invalid batch rejected before any side effect: invalid id at line 2: \`bad\``；空批 `empty batch rejected: empty batch`。
- **修复**：先整批解析校验、产出拒绝信息（精确到行号与字段），校验全绿才进入执行段；副作用只在通过后开始。

### 2.11 错误展示分层（用户/排障/根因）（E-011-error-display-reporting）

- **典型现象**：给用户的界面/日志打印 `PaymentError { ... }` Debug 结构；或给排障只留一句人话，无法定位字段。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-011-error-display-reporting`
- **判据**：`user view: payment PAY-1234 failed`；`operator view: PaymentError { reference: "PAY-1234", ... }`；`root cause walk: invalid digit found in string`。
- **修复**：两个视图来自同一个错误值——Display 给用户，Debug 给排障；根因沿 `source` 链单独走一层打印，不手写两份文案。

### 2.12 stdout/stderr 分流与分级口径（E-012-error-observability）

- **典型现象**：诊断与业务输出混在一路；失败被吞掉或打断业务流，无计数可对账。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-012-error-observability`
- **判据**：stdout 只有业务行 + 收尾 `metrics: processed=3 warned=1 failed=1`；stderr 出现 `[WARN] row 2: ... degrading to id 0` 与 `[ERROR] row 4: ...`。
- **修复**：业务数据走 stdout；诊断走 stderr 并带 `[WARN]`/`[ERROR]` 锚点；降级要留痕；进程收尾一行计数。

### 2.13 降级链与来源标签规范（E-013-graceful-degradation）

- **典型现象**：降级后说不清数据来自哪一路；默认值被误当真值。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-013-graceful-degradation`
- **判据**：`query \`42\` -> 42 via primary`、`query \` 7 \` -> 7 via replica`、`query \`gone\` -> 0 via default` 三条来源标签齐全。
- **修复**：主源 → 备用源 → 默认值的固定降级链，每条结果携带 `via <来源>` 标签；默认值用 `unwrap_or_else` 惰性构造。

### 2.14 反模式清单与识别方法（E-014-antipattern-catalog）

- **典型现象**：错误原因被 `.ok()` 销毁；调用方只能对消息文本做 `starts_with` 约定；坏行按 0 混入使合计静默失真。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-014-antipattern-catalog`
- **判据**：`anti-1 swallowed: true (error cause destroyed by .ok())`、`anti-2 stringly-typed: caller matches on message text only (true)`、`anti-3 continue-on-error: total 5 (bad rows silently vanish)`，且各自 `fixed` 行给出修复后输出。
- **修复**：吞错处改完整处理或显式降级；stringly-typed 改枚举变体按类型分支；continue-on-error 改聚合或 fail-fast。

### 2.15 线程边界错误传播与锁中毒处置（E-015-thread-error-propagation）

- **典型现象**：子线程的错误静默消失（`join()` 返回值被忽略）；持锁线程 panic 后整把锁被当永久报废。
- **排查命令**：`TAG=latest scripts/run-example.sh rust E-015-thread-error-propagation`
- **判据**：`join ok: Ok(Ok(42))`；`join err propagated: BadInput(7)`；`channel: Err(BadInput(9))`；`poison recovered: counter 1 (increment before panic survived)`。
- **修复**：子线程 `Err` 经 `JoinHandle` 或通道回收并在边界统一处理；`Mutex` 中毒先判定数据一致性（panic 前的写入是否有效），一致则 `into_inner` 恢复，不一致才视为致命。
