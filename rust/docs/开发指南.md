## 1. 环境与启动

- 镜像：`devbox-rust`（定义在 `images/rust/Dockerfile`，基于 `devbox-tool` 底座层）。
  版本真本只有 `images/versions.env`：工具链写 `${RUST_TOOLCHAIN}`（rustup 安装，
  profile minimal，再补 clippy / rustfmt 组件），下载镜像源 `${RUSTUP_DIST_SERVER}`、
  `${RUSTUP_UPDATE_ROOT}`。任何文档不写字面量版本号。
- 获取镜像：`docker pull "ghcr.io/zeek-zhao/devbox-rust:${TAG:-latest}"`；
  本地自建过镜像就用 `TAG=local`（TAG 契约见 T0 §1）。
- 交互进入容器：`docker run --rm -it "ghcr.io/zeek-zhao/devbox-rust:${TAG:-latest}" bash`。
- 宿主机不装 Rust 也能干活：`rust/project/build.sh` 检测到宿主没有 cargo 时
  会自动落到容器里跑（前提是镜像已在本地）。

## 2. 目录结构与各文件职责

```
rust/
├── examples/<ID>/        # 教学用例，一个目录一个考点（清单见 知识点清单.md）
│   ├── run.sh            # 自己负责编译与运行，只往 stdout 打业务输出
│   ├── expected.txt      # 期望输出，逐行精确（忽略行尾空白与首尾空行）
│   └── README.md         # 考点说明
├── project/              # 毕业项目（Cargo 工程）
│   ├── Cargo.toml / Cargo.lock   # 清单与锁定（离线构建靠 lock）
│   ├── build.sh          # 一条龙：cargo fmt --check → clippy -D warnings → test → build --release --offline
│   ├── src/ tests/ examples/     # 源码 / 集成测试 / cargo examples
│   └── COVERAGE.md       # 覆盖表
└── docs/                 # 本指南层文档（G2/G4/G5）
```

## 3. 一条命令跑通

```bash
cd <仓库根>
TAG=latest scripts/run-example.sh rust L0-hello
```

预期：runner 在 devbox-rust 容器里编译运行用例，逐行比对 `expected.txt`，
末尾打印 `PASS`（实测约 0s）。列全部用例：`scripts/run-example.sh rust --list`；
跑整门：`TAG=latest scripts/run-example.sh rust --all`。

失败时先看哪里：

1. runner 的最后一段输出——会指明是编译失败、运行超时还是期望输出不匹配；
2. 加 `--keep` 保留容器，再 `docker exec` 进去手动跑 `run.sh` 对比现场；
3. 镜像都拉不到（第一步就 manifest unknown）→ 是镜像或网络问题，不是代码问题。

## 4. 改动循环：改 → 格式化 → lint → 测试 → 提交

```bash
# 1) 改代码（rust/examples/<ID>/ 或 rust/project/）

# 2) 格式化：宿主不装 rustfmt，统一走容器入口
bash scripts/fmt.sh --lang rust            # 就地格式化 rust/ 下源码
bash scripts/fmt.sh --check --lang rust    # 只检查，有差异 exit 1（CI 口径）

# 3) lint + 4) 测试 + 构建：毕业项目一条龙（工程内等价命令）
docker run --rm -v "$PWD:/workspace" -w /workspace/rust/project \
  "ghcr.io/zeek-zhao/devbox-rust:${TAG:-latest}" bash -lc '
cargo fmt --all -- --check
cargo clippy --offline --all-targets -- -D warnings
cargo test --offline --all-targets --all-features
cargo build --release --offline'

# 5) 提交：身份白名单、Conventional Commits、禁 AI 署名尾巴——纪律见 T0 §5
git add <文件> && git commit
```

要点：

- `clippy` 警告按 `-D warnings` 提级为错误：这不是可选项，是 `build.sh` 的门禁
  （L2-008-clippy-warnings 的考点）。
- 工程内依赖走 `--offline`（Cargo.lock 锁定），保证离线可重现；首次新增依赖要
  先联网 `cargo fetch` 更新 lock 再提交（见 L2-009-offline-build）。
- 单元测试 / 集成测试 / doctest 的分层练法见 L2-003-unit-tests、
  L2-004-integration-tests、L2-005-doctests。
