# Rust 实践指南（G1）

> 回答「什么时候用 Rust 轨道的哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 命令契约（规范 §4.3）：统一 `TAG=latest scripts/run-example.sh rust <ID>`；
> 版本/工具链只写 `images/versions.env` 的变量名（`${RUST_TOOLCHAIN}`，版本引用契约 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 Rust 工程能力——L1 语言与标准库
基础（移动语义、借用、生命周期、Option/Result、迭代器、内部可变性）、L2 工程
能力（crate 布局、feature、fmt/clippy、离线构建、workspace、build script）、
L3 专题（零拷贝解析、scoped thread、FFI、原子序、unsafe、Send/Sync 界），共 74
个用例；终点是 `rust/project` 的毕业项目「跨平台 CLI 工具」（词频/重复行/基准，
仅标准库，`--self-check` 确定性自检）。每一层都用「可观察判据」验收：用例跑通、
输出与 `expected.txt` 逐行一致（验收口径见 [开发指南.md](开发指南.md)）。

**什么时候别用本指南**：

- 想学某个语言特性本身（借用检查器 NLL 规则、 trait object 安全性推导）——
  直接跑对应 L1 用例，指南不讲语法，读了也学不会；
- 想找某个具体故障的排查路径（E0502 借用冲突读法、feature 冲突、离线构建失败）
  ——去 [问题指南.md](问题指南.md)（G3，按问题域组织：所有权与借用、依赖与
  feature）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）；
- 想引第三方 crate（serde、tokio 等）——本轨道 L1–L3 用例与毕业项目只用标准库
  （`L2-009-offline-build` 的依赖清单只有 1 行，即自身），引依赖不会通过评审。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令（语法考点的「正主」在清单与用例里，不在指南里）：

  ```bash
  grep 'L1-005-borrow-scope' rust/docs/知识点清单.md
  ```

  输出会指向 KP 行与建议用例 `L1-005-borrow-scope`——借用作用域知识点的载体是
  用例，不是本篇。
- 后果：只读不跑，等于没碰过 `rustc`；借用冲突报错要读得熟只能靠真编真错。
  正确动作是 `TAG=latest scripts/run-example.sh rust L1-005-borrow-scope`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（`KI-05` 定案：L0 表示镜像与 runner 通路
验证，不属于知识难度层级），它验证镜像能编译并运行 Rust（工具链
`${RUST_TOOLCHAIN}`，真本 `images/versions.env`），与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh rust L0-hello
# 实测输出：rust/L0-hello                 PASS (1s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见
  环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh rust L0-hello
  ```

- 后果（实测）：runner 输出 `FAIL`，stderr 含
  `docker: Error response from daemon: manifest unknown`，以非零退出。
  通路用例 1 秒就能把这类环境问题暴露出来；不验通路时，同样的错误会发生在
  你等得最久的那一步，且难以与代码 bug 区分（素材池 `S-06`）。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| 让所有权/借用规则替你设计 API：返回 owned 值或 `&T`/`&mut T` 明确二选一（见 `L1-003-shared-borrows`、`L1-004-mutable-borrows`） | 到处 `clone()` 把编译错「修掉」 | clone 掩盖的是数据流问题，成本是每次分配；编译错是免费的设计评审（反例见下） |
| 可变性精确到最小：默认 `&T`，需要再 `&mut T`/`Cell`/`RefCell`（见 `L1-025-rc-refcell`） | 整个结构全 `mut` 或全 `Arc<Mutex<>>` 包一切 | 锁粒度失控、内部可变性滥用会把检查推迟到运行时 panic |
| 依赖一律写进 `Cargo.toml` 并提交 `Cargo.lock` | 手动 `cargo install` 后绕过清单构建 | 离线/干净环境直接 `no matching package`（实测见 [问题指南.md](问题指南.md) 依赖与 feature 节） |
| feature 表达「可选能力」，命名不与隐式语义耦合（见 `L2-006-cargo-features`） | 用 feature 互斥地换行为、或写出自引用 feature | `cyclic feature dependency` 构建直接红（实测）；feature unification 会让构建结果随依赖树变化（docs/20 §3.3） |
| 一律经 runner 跑用例 | 手写 `docker run` / `cargo run` 复刻 runner 行为 | CI 与本地用同一个 runner（真本 `scripts/run-example.sh`）；口径分裂造成「本地假绿」（素材池 `S-01`：TAG 与 IMAGE_TAG 名字不一致曾让 6 个用例 job 全红） |
| 版本/工具链只引用 `images/versions.env` 变量 | 在文档/脚本里手写工具链版本常量 | 升级时手写常量集体过期，且过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：可变借用与不可变借用冲突（E0502）**

- 错误做法：

  ```rust
  fn main() {
      let mut v = vec![1, 2, 3];
      let first = &v[0];      // 不可变借用还活着
      v.push(4);              // 试图可变借用同一数据
      println!("first = {}", first);
  }
  ```

- 复现命令（在本轨道镜像里实测）：

  ```bash
  docker run --rm -v "$PWD":/exp -w /exp \
    "ghcr.io/zeek-zhao/devbox-rust:${TAG:-latest}" rustc borrow.rs -o /tmp/borrow
  ```

- 后果（实测输出，退出码 1）：

  ```
  error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
   --> borrow.rs:4:5
    |
  3 |     let first = &v[0];
    |                  - immutable borrow occurs here
  4 |     v.push(4);
    |     ^^^^^^^^^ mutable borrow occurs here
  5 |     println!("first = {}", first);
    |                            ----- immutable borrow later used here

  error: aborting due to 1 previous error
  ```

  这是借用检查器在编译期替你拦下的数据竞争——同样的问题在 C++/Go 里是
  运行时悬垂指针或竞态（Go 要靠 `-race`，见 Go 轨道 [../go/docs/问题指南.md](../go/docs/问题指南.md)）。
  修法：调整语句顺序（用完 `first` 再 push）或克隆出 owned 值，
  `L1-005-borrow-scope` 演示作用域如何决定借用何时结束。

## 4. 真实工作中的变体

**变体 1：本地已自建镜像（`make images` 或 `scripts/build-images.sh`）**
runner 的取值顺序是 `TAG` → `IMAGE_TAG` → `local`（真本 `scripts/run-example.sh`），
本地调试自建镜像时不传 `TAG` 即落到 `local`，或显式
`TAG=local scripts/run-example.sh rust <ID>`。注意 `local` 只是本地约定名，
不要写死进文档或 CI（素材池 `S-01` 的教训：两个名字各说各话）。

**变体 2：离线/受控网络环境构建（对应 `L2-009-offline-build`）**
干净机器、无外网或依赖镜像受控时，`cargo build --offline` 只认本地缓存与
vendor 目录——这正是本轨道「仅标准库」的用意之一：零第三方依赖即可离线构建。
引第三方依赖时先 `cargo vendor` 并提交 vendor 目录，否则离线构建直接红
（实测报错见 [问题指南.md](问题指南.md)）。

**变体 3：整轨回归**
改动波及面大（升级 `${RUST_TOOLCHAIN}`、动公共构建配置）时跑全轨 74 例，与
CI 的 `examples` job 同款入口：`TAG=latest scripts/run-example.sh rust --all`。
并发与 unsafe 类用例（`L3-011-send-sync-bounds` 等）也在这一步一起验，
不要因为本地跑过单例就跳过整轨。

**反例（可执行）：并发任务互推可变标签 `:latest`**

- 错误做法与后果（真实历史 bug `#184`，素材池 `S-02`）：A 推的 `:latest` 被
  B 覆盖，A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」无法区分。
- 可直接观察 tag 风险的命令：

  ```bash
  TAG=nosuchtag scripts/run-example.sh rust L0-hello   # manifest unknown，实测
  ```

- 修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  本地需要固定版本时同样优先 sha 标签。
