# Rust 工程参考（G4 · 参考）

> 本文只有一个主要承诺：**Rust 轨道的工程事实速查**——镜像、构建、运行、依赖、
> 环境变量、版本真本，一张表对齐，全部可从仓库内文件复核。
> 通用开发动线（runner 细节、CI、门禁、提交纪律）是 T0 真本：
> [docs/13-通用开发指南](../../docs/13-通用开发指南.md)，本文只写 Rust 轨差异。

## 1. 工程全景表

| 域 | 事实 | 真本出处 |
|---|---|---|
| 镜像 | `ghcr.io/zeek-zhao/devbox-rust:latest`（本地自建时 `TAG` 用 `local`） | `images/rust/Dockerfile`、`images/lang-images.tsv` |
| 工具链 | 版本读 `${RUST_TOOLCHAIN}`，rustup 走 `${RUSTUP_DIST_SERVER}` 镜像源 | `images/versions.env`（版本单一真本，不写字面量） |
| 构建 | `bash rust/project/build.sh`（format → lint → build → test 一条龙） | `rust/project/build.sh`、`rust/project/README.md` |
| 运行用例 | `TAG=latest scripts/run-example.sh rust <ID>` | `scripts/run-example.sh`、[docs/13](../../docs/13-通用开发指南.md) §1 |
| 列出用例 | `scripts/run-example.sh rust --list` | 同上 |
| 依赖 | 只用 std 与固定工具链，禁止第三方 crate（容器离线无注册表缓存） | `rust/docs/知识点清单.md` §5、`rust/examples/E-*/Cargo.toml` |
| 环境变量 | `TAG` / `IMAGE_TAG` / `REGISTRY` / `RUST_BACKTRACE` | 本文 §5 |
| 版本真本 | 镜像内一切版本号只来自 `images/versions.env` | `scripts/check-version-truth.sh` |
| 用例计数 | `rust/examples/` 89 个目录 = L 系 74（L0 1 + L1 45 + L2 17 + L3 11）+ E 系 15 | `ls rust/examples \| wc -l` |

## 2. 镜像层与版本真本

- Rust 镜像继承 base → tool 层（`make build-base build-tool build-lang`，[docs/01](../../docs/01-镜像体系.md)）；
  语言层 ARG 只有三个：`${RUST_TOOLCHAIN}`、`${RUSTUP_DIST_SERVER}`、`${RUSTUP_UPDATE_ROOT}`，
  值一律来自 `images/versions.env`，Dockerfile 禁止写死版本号（`scripts/check-version-truth.sh` 卡）。
- 用例命令里的 `TAG=latest` 与 CI 传入的 `IMAGE_TAG` 是同一个值的两个名字；
  历史教训（不一致导致整片 job 全红而本地假绿）见 [docs/13](../../docs/13-通用开发指南.md) §1。
- 镜像拉不动时先看 CI 的 `probe` job——那是镜像问题不是代码问题。

## 3. 构建与运行

| 动作 | 命令 | 说明 |
|---|---|---|
| 轨道质量门禁 | `bash rust/project/build.sh` | fmt/clippy/build/test 四步，任一步非零即红 |
| 单个用例 | `TAG=latest scripts/run-example.sh rust E-006-context-layering` | stdout 逐行比对 `expected.txt` |
| 整门语言 | `TAG=latest scripts/run-example.sh rust --all` | 全量 89 个用例 |
| 保留现场 | `TAG=latest scripts/run-example.sh rust <ID> --keep` | 容器不销毁，`docker exec` 进去复现 |
| 全仓格式检查 | `make fmt-check` | 与 `RUST_TOOLCHAIN` 配套的 rustfmt 口径 |
| 全仓 lint | `make lint` | clippy 阈值口径见 `rust/examples` 各用例 run.sh |

失败时先看哪里：runner 最后一段输出指明是编译失败、超时还是期望输出不匹配；
再 `--keep` 进容器看现场；最后才怀疑镜像（[docs/13](../../docs/13-通用开发指南.md) §1）。

## 4. 依赖纪律

- **只用标准库**：`rust/examples/` 各用例与 `rust/project/` 不引入任何第三方 crate；
  离线容器没有 crates.io 缓存，下载不可重复（清单 §5「明确不覆盖的」）。
- `Cargo.lock` 提交入库；新增 std 能力不需要动依赖，需要动工具链时改
  `images/versions.env`（走版本真本流程，不在用例里绕）。
- `rustfmt.toml` / `rustfmt` 版本与 `${CLANG_FORMAT_MAJOR}` 无关，Rust 侧跟
  `${RUST_TOOLCHAIN}` 自带版本走。

## 5. 环境变量速查

| 变量 | 谁读 | 作用 | 与错误处理的关系 |
|---|---|---|---|
| `TAG` | `scripts/run-example.sh` | 选镜像 tag，文档统一写 `TAG=latest` | 跑 E 系演练用例的前置 |
| `IMAGE_TAG` | CI | `TAG` 的 CI 别名，同一个值 | 禁止在文档里混用两个名字 |
| `REGISTRY` | `scripts/run-example.sh` | 镜像仓库前缀，缺省读 `images/versions.env` 的 `${REGISTRY}` | 私有部署时改 |
| `RUST_BACKTRACE` | std 运行时 | panic 时打印回溯；`E-003` 演示了 panic 提示行 | 排查退出码 101 时置 `1` |

## 6. 常见误用

1. **在指南/用例里写死工具链版本号**（如 `rustc 1.x.y`）：版本只许引用
   `images/versions.env` 变量名，字面量会随工具链升级集体过期——对照
   [docs/11](../../docs/11-知识点清单增强规范.md) §4.4 版本引用契约。
2. **把 `TAG=latest` 写成 `devbox-rust:local` 这类硬编码 tag**：本地自建镜像时才用
   `local`，文档统一 `TAG=latest`（[docs/13](../../docs/13-通用开发指南.md) §1 命令契约）。
3. **给 `rust/examples/` 加新目录当演练场**：演练素材放 `<lang>/labs/`，
   绝不进 `examples/`（会污染用例计数口径，见 [docs/72](../../docs/72-排障演练规范.md) §1）。

## 7. 选型对比

不适用：本轨道工具链单一（rustc/cargo/clippy/rustfmt 四件套均来自
`${RUST_TOOLCHAIN}`），无同类可替换工具，不存在选型问题。
