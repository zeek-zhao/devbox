# L1-002-copy-types


## 考点
对应 KP-RS-L1-02：`u32` 实现 `Copy`，赋值和传值后原绑定仍能使用。
看到三个编号均为 `7`、修改副本为 `8` 后原编号不变，说明理解了复制值彼此独立。
`copy_value` 的 `Copy` 约束由编译器验证；`String` 只能在赋值后的新所有者处使用。

## 易错点
会把所有赋值都当作复制，导致移动类型后续不可用，因为 `String` 不实现 `Copy`。
按类型是否实现 `Copy` 判断；必要时显式借用或克隆，不要把整数经验套到拥有型文本上。

## 延伸
在文档编号、计数值传递中用简单值类型，让调用方保留原值。
尝试将 `String` 传给本例的 `copy_value`，分析为何其类型不满足约束，而不是添加克隆掩盖差异。
