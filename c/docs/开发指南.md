# C 开发指南（G2）

> 从零到能改：环境、目录、一条命令跑通、改动循环、调试入口。
> C 轨道目前是最小集（G2/G4/G5 三篇）；实践指南（G1）与问题指南（G3）按排期后补，
> 本文提到排查细节时指向 [工具指南.md](工具指南.md) 与 [FAQ.md](FAQ.md)。
> 写法契约见《知识点清单增强规范》§4：版本号只写 `images/versions.env` 变量名，
> 全文不出现手写版本常量与硬编码镜像 tag。

## 1. 环境与启动（镜像 tag / 版本号来源）

**镜像**：C 轨道没有自己的镜像层。语言名到镜像层的映射真本是
`images/lang-images.tsv`，`c` 与 `cpp` 复用同一个 `devbox-cpp` 层（同一套
gcc / clang 工具链，安装真本 `images/scripts/install/cpp.sh`）。
仓库前缀 `REGISTRY` 真本是 `images/versions.env`。

**tag 来源**：镜像 tag 一律经变量传入，禁止写死。runner（真本
`scripts/run-example.sh`）的取值优先级是 `TAG` → `IMAGE_TAG` → `local`：
CI 传 `IMAGE_TAG`，本地习惯传 `TAG`，两者是同一个值的两个名字（名字不一致曾导致
6 个用例 job 全红而本地各跑各的都绿，规范 §4.3 留痕）。宿主已有本地构建的镜像时，
把 `TAG` 换成 `local`：

```bash
docker pull "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}"   # 手动拉取
TAG=local scripts/run-example.sh c <ID>                     # 用本地镜像跑用例
```

**工具链版本**（真本 `images/versions.env`，禁止手写字面量）：

| 工具 | 版本来源 |
|---|---|
| gcc / g++ | `${GCC_MAJOR}` |
| clang / clang-format | `${CLANG_MAJOR}` / `${CLANG_FORMAT_MAJOR}`（两者必须同步，否则「本地 fmt 通过、CI fmt-check 报差异」） |
| cmake | `${CMAKE_MIN_VERSION}` |

**启动后的自检**：进容器逐个跑 `--version`，输出主版本号应与上表变量相符；
一键核验命令见 [工具指南.md](工具指南.md) §1。

## 2. 目录结构与各文件职责

```text
c/
  docs/
    知识点清单.md           # 用例 ID 清单（练什么的真本）
    用例编写规范.md         # 怎么写用例（验收真本）
    开发指南.md             # 本篇（G2）
    工具指南.md             # G4：工具与参数速查
    FAQ.md                  # G5：高频短问答
  examples/                 # 78 个用例（L0-hello + L1/L2/L3 编号用例）
    <ID>/
      run.sh                # 必须存在：自己负责编译与运行，只往 stdout 打业务输出
      expected.txt          # 期望输出：逐行精确，忽略行尾空白与首尾空行
      README.md             # 考点说明
  project/                  # 毕业项目
```

runner 对每个用例目录强制三文件契约（真本 `scripts/run-example.sh` 头注释）：
缺目录报 `MISSING`，缺 `run.sh` 报 `NO-RUNNER`，输出不一致报 `MISMATCH`。
练什么以 [知识点清单.md](知识点清单.md) 为准，怎么写以
[用例编写规范.md](用例编写规范.md) 为准。

## 3. 一条命令跑通（含失败时先看哪里）

```bash
TAG=latest scripts/run-example.sh c L0-hello
# 实测输出（2026-11-05，devbox-cpp:latest）：c/L0-hello                  PASS (0s)
```

多文件编译看 `L2-001-multifile-build`，带 Makefile 的增量构建看
`L2-002-makefile-incremental`，同样是这一条命令，只换 ID。

失败时按这个顺序看：

1. **`MISSING(...)` / `NO-RUNNER`**：三文件契约没满足。对照
   [知识点清单.md](知识点清单.md) 核对目录名拼写，确认 `run.sh` 存在且可执行。
2. **拉镜像失败 / `manifest unknown`**：`TAG` 指向的镜像不存在或还没拉过，
   先 `docker pull "ghcr.io/zeek-zhao/devbox-cpp:${TAG:-latest}"`；
   `TAG` 与 `IMAGE_TAG` 的取值规则见 §1。
3. **`MISMATCH`**：实际输出与 `expected.txt` 不一致，runner 会并排打印差异。
   故意改了行为的，按 [用例编写规范.md](用例编写规范.md) 更新期望文件；
   `--update` 仅限新写用例。
4. **`FAIL (exit!=0)`**：看 runner 打印的 stderr 前 20 行，多为编译错误；
   需要进容器手工复现时加 `--keep` 保留容器，再 `docker exec -it devbox-keep-c-<ID> bash`。
5. 更多排查路径（镜像、格式化、门禁漂移）见 [FAQ.md](FAQ.md)。

## 4. 改动循环：改 → 格式化 → lint → 测试 → 提交

```bash
# 1. 改 c/ 下的源码或用例（编辑器里完成）
# 2. 就地格式化（唯一入口 scripts/fmt.sh；C 走 clang-format）
make fmt                                   # 全部语言
bash scripts/fmt.sh --check --lang c       # 只读检查，CI 跑的就是 --check
# 3. 跑受影响用例
TAG=latest scripts/run-example.sh c L0-hello
# 4. 提交（提交身份须在仓库白名单内，禁止 AI 署名尾巴，CI 的 authors job 会卡）
```

格式化范围注意：`scripts/fmt.sh` 只处理各语言目录下的源码；`scripts/`、`images/`
与用例里的 `run.sh` 不在范围内（真本脚本头注释）——改它们是门禁变更，不是排版变更。
lint 在 C 轨道以编译警告承担：用例基线是 `-std=c17 -Wall -Wextra -Werror`
（见 `L0-hello/run.sh`），更严的 `-Wconversion -Wshadow -Wcast-qual` 见
`L2-010-strict-warnings`，静态分析器见 `L2-011-gcc-analyzer`。
