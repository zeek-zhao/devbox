# C 错误处理指南（how-to）

> 面向「要在 C 代码里把错误处理写对」的操作指南：按任务路由到 E 类示例，
> 每条纪律给得出用例 ID 与验证命令。从已有故障出发的排查走
> [排查手册](排查手册.md)；语法层知识归 L1/L2/L3 用例，本篇不重复贴代码。
> 全部 15 个 E 例已于 2026-11-11 在 `devbox-cpp:latest` 内真跑通过
> （`TAG=latest scripts/run-example.sh c <ID>`，C 复用 cpp 镜像层，真本
> `images/lang-images.tsv`）。

## 1. 适用边界

- 适用于：在本仓库 C 代码（含毕业项目）里设计或修复错误处理路径——分类、构造、
  匹配、传播、上下文、清理、重试、超时、聚合、观测、快速失败。
- 不适用于：第一次学 C 的语法（见 [知识点清单](知识点清单.md) L1 段）；
  手上已经有一个故障要排查（见 [排查手册](排查手册.md)——本篇只讲怎么写对，
  不讲坏了怎么找）。
- 本篇是 how-to：只讲「做某件事的步骤」，不讲完整语法书。命令契约见
  [docs/11](../../docs/11-知识点清单增强规范.md) §4.3（统一 `TAG=latest
  scripts/run-example.sh c <ID>`，禁止硬编码镜像 tag）。

## 3. 七条核心纪律（每条可执行、可断言）

1. **先分类，再处理**（E-001）：错误码用封闭枚举，`switch` 覆盖全部枚举值，
   新码漏写分支由 `-Wswitch` 编译期报错；处理策略挂在类别（USAGE 修调用 /
   ENVIRONMENT 可重试 / INTERNAL 快速失败）上，不散落成各处 if 表。
2. **统一的抛出形态**（E-002）：失败只走「返回错误值」一种形态，`code==0` 即成功；
   `what` 是稳定的机器可读标识（供匹配与断言），`detail` 是人读上下文，两者分离。
3. **身份只比码**（E-005，配合 E-003）：`strstr(msg, "timeout")` 一类文本匹配
   是双向失效的——会把别的错误判进来，也会因改文案漏判出去；E-005 用
   `db-txn` 一行输出定量演示这个陷阱。
4. **传播只加信息，不改身份**（E-004 + E-006 + E-008）：包装只加消息前缀不改码；
   上下文以 KV 字段逐层挂载（消息给人读，字段给机器查）；中间层处理不了就
   补上下文原样重抛——没有第四种「记了日志就算处理了」。
5. **清理逻辑只有一份**（E-007）：资源变量先初始化为未持有，错误路径
   `goto cleanup` 跳到唯一出口，按申请逆序只释放已持有的资源，释放后立刻置空
   （与 L1-023 双重释放防线衔接）。
6. **边界翻译一次**（E-009）：库函数失败后立即保存 errno（L2-014 纪律），
   翻译成应用码的动作只发生在边界层一处；输出打 errno 数字值而非 strerror 文案
   （数字 POSIX 固定，文案随 locale 漂移）。
7. **按类别决定终止方式**（E-010 + E-011 + E-012 + E-014）：暂态类才重试且
   退避有界；批量操作设预算与安全点并返回进度；并发失败收齐后聚合报分布；
   只有 INTERNAL 类（前提被破坏）才快速失败，诊断行带 `文件:行号 + 不变量原文`，
   退出码固定 70（EX_SOFTWARE 惯例）。

## 4. 反模式清单（每条可复现）

- 吞错：`if (rc != 0) { log(rc); rc = 0; }` —— 日志与控制流分叉（E-008 吞错路径、
  E-015 bad 版本都是可运行反例）。
- 文本匹配判身份：`strstr(msg, "timed out")` —— 两类同词错误互相污染（E-005）。
- 对参数错误重试：输入不变结果不变，白烧 CPU（E-010 strict 路径演示正确做法）。
- 每个错误点手写一遍释放序列：分支多了必然漏一处（E-007 反例）。
- 把上下文拼进一句话再靠 `strstr` 反解：字段边界一变解析就断（E-006 反例）。
- 对不变量破坏「尽力恢复」继续跑：恢复逻辑建立在已损坏状态上（E-014 反例）。

可运行对照反例入口：`TAG=latest bash scripts/run-example.sh c E-015-antipattern-compare`，
bad/good 两个版本的差异就是输出本身（`error_reported=0` vs `error_reported=1`）。

## 5. 评审清单（review 错误处理代码时逐条问）

- [ ] 失败只有一种返回形态吗？有没有「返回值 0 但 stderr 里有错」的路径？
- [ ] 身份判定比的是码还是文案？default/兜底分支存在吗？
- [ ] 中间层有没有第三种动作（记日志后 return 0）？
- [ ] 错误路径的资源清理是不是只有一份？释放后有没有置空？
- [ ] errno 是不是在失败后立即保存？翻译是不是只在边界层？
- [ ] 重试是不是先分类？退避与次数上限在哪里可见？
- [ ] INTERNAL 类失败是不是带 `文件:行号 + 不变量原文` 且退出码可告警？

逐条判据都对应第 2 节路由表里的一行用例；写法契约与状态机见
[docs/11](../../docs/11-知识点清单增强规范.md) §4、§7.1。
