# C 工具指南（G4）

> 工具清单、装在哪、怎么调、参数速查、选型对比、常见误用。
> 所有工具都装在 `devbox-cpp` 镜像里（C 复用 cpp 层，真本 `images/lang-images.tsv`），
> 宿主上没有，统一经容器调用。命令契约见《知识点清单增强规范》§4.3；
> 版本号一律引用 `images/versions.env` 变量（§4.4），本篇不写字面量。

## 1. 工具全景表

预装核验方法（真跑于 2026-11-05，`devbox-cpp:latest`）：

```bash
docker run --rm ghcr.io/zeek-zhao/devbox-cpp:latest bash -lc \
  'which gcc clang g++ make cmake valgrind gdb clang-format ar gcov'
```

| 工具 | 用途 | 本工程是否预装 | 版本来源（真本 `images/versions.env`） |
|---|---|---|---|
| gcc | 主编译器（用例默认 `CC=gcc`） | 是（实测 `/usr/bin/gcc`） | `${GCC_MAJOR}` |
| clang | 第二编译器，交叉检查诊断 | 是（实测 `/usr/bin/clang`） | `${CLANG_MAJOR}` |
| make | L2 构建用例的构建器 | 是 | 随镜像层安装 |
| cmake | 备选构建系统 | 是 | `${CMAKE_MIN_VERSION}` |
| valgrind | 内存错误/泄漏离线检测 | 是 | 随镜像层安装 |
| gdb | 断点调试、批处理回溯 | 是 | 随镜像层安装 |
| clang-format | 格式化（`make fmt` 的底层） | 是 | `${CLANG_FORMAT_MAJOR}`（必须与 `${CLANG_MAJOR}` 同步） |
| ASan/UBSan/LeakSan | 编译器内置消毒器 | 是（编译开关，非独立二进制） | 随 `${GCC_MAJOR}` / `${CLANG_MAJOR}` |
| gcov | 覆盖率统计（gcc 自带） | 是 | 随 `${GCC_MAJOR}` |
| cppcheck / ccache / strace / ltrace / pkg-config | 辅助工具 | 是（实测 `which` 命中） | 随镜像层安装 |
| clang-tidy | 静态分析（clang 系） | **未预装**（实测 `command not found`）；静态分析用 gcc `-fanalyzer`（见 `L2-011-gcc-analyzer`） | — |
| perf / bear / autoconf | 剖析 / 编译数据库 / autotools | **未预装**（实测 `command not found`） | — |

## 2. 每工具一节：装在哪、怎么调、常用参数速查

统一调用方式：工具在镜像里，宿主直跑必然 command not found。两条路：

```bash
# 路 A：用 runner 的 --keep 保留用例容器，再 exec 进去（接着跑完的现场调试）
TAG=latest scripts/run-example.sh c L2-008-gdb-batch-backtrace --keep
docker exec -it devbox-keep-c-L2-008-gdb-batch-backtrace bash

# 路 B：直接起一次性容器（独立实验）
docker run --rm ghcr.io/zeek-zhao/devbox-cpp:latest bash
```

### gcc / clang

- 装在哪：镜像层内 `PATH` 直取；用例经 `CC` 环境变量选编译器（真本各用例 `run.sh`）。
- 常用参数速查（本轨道用例基线，见 `L0-hello/run.sh`）：
  `-std=c17`（语言标准显式声明）、`-Wall -Wextra -Werror`（警告基线，C 的坑只有开警告才暴露）、
  `-g`（调试信息，gdb 需要）、`-O2`（优化；与 `-g` 并用时 gdb 变量可见性受影响）、
  `-fsanitize=address|undefined`（消毒器，一次一个）、
  `-fanalyzer`（编译期静态分析，对应 `L2-011-gcc-analyzer`）、
  `-Wconversion -Wshadow -Wcast-qual`（更严警告，对应 `L2-010-strict-warnings`）。

### make

- 装在哪：镜像里；练习入口 `TAG=latest scripts/run-example.sh c L2-002-makefile-incremental`。
- 常用参数速查：`make <目标>`、`make -n`（干跑只打印不执行）、增量重建只发生
  在目标比依赖旧时（该用例考点）；构建产物放独立目录，别混进源码目录。

### valgrind

- 装在哪：镜像里。
- 常用参数速查：`valgrind --leak-check=full ./程序`（泄漏明细与摘要）。
  编译时仍要 `-g` 才有行号。与 ASan 二选一，不要叠加（见 §4 误用 2）。

### gdb

- 装在哪：镜像里；考点用例 `L2-008-gdb-batch-backtrace`。
- 常用参数速查：编译加 `-g`；批处理模式 `gdb -batch -ex run -ex bt ./程序`
  （崩溃即打印回溯后退出，适合进 CI 日志）；交互式 `break` / `run` / `bt` / `print`。
  优化构建会内联重排，断点位置与变量可见性会变。

### ASan / UBSan / LeakSan

- 装在哪：编译器内置，编译开关而非独立工具。
- 怎么调：`-fsanitize=address`（越界/释放后使用，对应 `L2-006-asan-bounds`）、
  `-fsanitize=undefined`（有符号溢出等，对应 `L2-007-ubsan-overflow`）、
  LeakSan 随 ASan 分发，`ASAN_OPTIONS=detect_leaks=1` 进程退出时报告泄漏
  （对应 `L2-009-leak-detection`）。报告含地址且非零退出，不能直接当 `expected.txt`。

### clang-format

- 装在哪：镜像里；宿主上没有（真本 `scripts/fmt.sh` 头注释）。
- 怎么调：不要直接调，走统一入口 `make fmt` / `bash scripts/fmt.sh --check --lang c`；
  版本失配的后果见 §4 误用 3。

### 未预装工具怎么办

clang-tidy 场景先用 gcc `-fanalyzer`（`L2-011-gcc-analyzer`）；需要系统级剖析或
编译数据库时，在用例容器里临时 `apt-get install` 不可取（构建不可复现），应改
`images/` 层并走镜像构建流程——那是门禁变更，不是文档能解决的。

## 3. 选型对比

- **gcc vs clang**：本轨道两者都预装，不是单选。默认 `gcc`（用例基线与 CI 口径一致）；
  换 `CC=clang` 重编一遍是拿第二双眼睛看诊断——两个编译器的警告/报错措辞不同，
  一方沉默的坑另一方可能点破。消毒器与 `-fanalyzer` 以 gcc 口径为真本。
- **make vs cmake**：本轨道用例以 `make` 为主（`L2-002-makefile-incremental`），
  cmake 已预装但 C 用例未使用；毕业项目如需 cmake，以 `c/project/` 实际脚本为准。
- **ASan vs valgrind**：都查内存问题。ASan 编译期插桩、快、报行号，日常首选；
  valgrind 不用重编、适合查已有二进制。同一程序二选一跑，不叠加。
- cppcheck / clang-tidy 等其余工具不涉及同类多选一：不适用：无同类。

## 4. 常见误用

1. **在宿主上直接跑 gcc / valgrind**。这些工具只在镜像里（实测宿主 `command not found`）。
   正确做法：一律经容器调用——跑用例走 runner，手工调试走 §2 路 A/路 B。
2. **ASan 与 valgrind 叠加跑**。ASan 自管内存分配器，valgrind 的插桩与它互相干扰，
   误报成堆。正确做法：同一个程序只选其一；对比结论时分别重编、分别跑。
3. **绕过 `make fmt` 直接调 clang-format**。本地版本若与 `${CLANG_FORMAT_MAJOR}`
   不同步（它必须与 `${CLANG_MAJOR}` 同步），会出现「本地 fmt 通过、CI fmt-check
   报差异」；正确做法：统一走 `bash scripts/fmt.sh --check --lang c`（它经容器跑），
   版本永远来自 `images/versions.env`。
4. **文档/脚本里写死镜像 tag**。`devbox-cpp:local` 之类的字面量是本地约定，
   写死后 CI 与他人在别的 tag 下必红。正确做法：命令统一 `TAG=latest
   scripts/run-example.sh c <ID>`，本地调试临时换 `TAG=local`。
