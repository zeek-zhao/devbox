# C 排查手册（troubleshooting）

> 按「症状 → 排查命令 → 判据 → 修复」组织的手册。§2 是错误处理章，含
> §2.1–§2.15 共 15 节，逐节对应 `c/examples/E-001..E-015`（各例 README 的
> `coverage: exempt` 注释指向本手册 §2 的对应节）。
> §3、§4 是路由章：内存/资源与构建/运行问题的入口指向既有指南与 lab。
> 全部排查命令已于 2026-11-11 在 `devbox-cpp:latest` 内真跑核对（C 复用 cpp
> 镜像层，真本 `images/lang-images.tsv`）；写法纪律见
> [docs/72-排障演练规范](../../docs/72-排障演练规范.md)（现象禁止编造，只许来自
> 真跑或已登记问题）。

## 1. 使用方法

1. 先在本手册按症状定位到节；每节给一条可直接执行/粘贴的排查命令与判据输出。
2. 判据不成立 → 按该节「修复」处理；判据成立但问题仍在 → 走该节给出的关联文档。
3. 「怎么写对」的设计问题走 [错误处理指南](错误处理指南.md)；镜像、版本、环境变量
   事实走 [工程参考](工程参考.md)。

## 2. 错误处理章（对应 E-001..E-015）

### 2.1 同一失败在不同调用点行为不一致（E-001-error-taxonomy）

- 症状：同一种失败有的被重试三次、有的直接退出，行为随调用点漂移。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-001-error-taxonomy`
- 判据：末行 `taxonomy codes=6 usage=2 environment=2 internal=1`——6 个码
  各归唯一类别，策略挂在类别上。
- 修复：错误码改封闭枚举 + 唯一归类函数，调用方只问 `classify(code)`；
  对 USAGE 重试是类别与动作错配，修调用而不是重试。详见 E-001 README。

### 2.2 失败码与正常结果分不清（E-002-error-create）

- 症状：有的函数失败返回 -1、有的返回 0、有的打印后返回 void，调用方无法统一判定。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-002-error-create`
- 判据：1 行成功 + 3 行错误，错误行固定带 `code / what / detail`，例如
  `what=age_negative detail="age must be >= 0"`。
- 修复：统一「返回错误值」形态，`code==0` 即成功；`what` 稳定可匹配、
  `detail` 人读。详见 E-002 README。

### 2.3 处理策略与错误身份对不上（E-003-error-match）

- 症状：NOT_FOUND 被拿去重试，NO_MEMORY 被当超时处理。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-003-error-match`
- 判据：4 行输出，无错行 `matched=NONE`、两个 `matched=EXACT` 分支、
  兜底 `matched=FALLBACK outcome=escalate`。
- 修复：先判成功再 `switch(code)` 精确匹配，`default` 显式升级；
  禁止按 `strstr(what, "not found")` 匹配。详见 E-003 README。

### 2.4 多层传播后错误失真（E-004-error-wrap）

- 症状：底层报 `open failed`，顶层只剩 `boot failed, code=1`，不知道断在哪层。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-004-error-wrap`
- 判据：`error_chain=load_settings: read_config: open failed` 与
  `root_code=3 depth=2`——根因码跨两层包装不变。
- 修复：每层 wrap 只加消息前缀不改码；每层替换消息/改写泛化码都会丢根因。
  详见 E-004 README。

### 2.5 错误被文本匹配误判（E-005-error-identity）

- 症状：`strstr(msg, "timed out")` 把锁等待超时判成网络超时，修错方向。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-005-error-identity`
- 判据：`op=db-txn   by_code=LOCK_STALL  by_text=NET_TIMEOUT`（按码与按文本
  结论相反的定量反例），末行 `sentinel_err_is_matches=1`。
- 修复：身份判定只比码（哨兵 + `err_is`）；`what` 字符串供人读，
  不当身份用。详见 E-005 README。

### 2.6 错误缺少结构化上下文（E-006-error-context）

- 症状：告警只有一句 load failed，搜不到是哪个用户、哪次请求、哪个字段。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-006-error-context`
- 判据：两行 `event`，各带 `code / op / target` 与逐层 KV
  （`user_id=42 request=GET /profile trace=t-42` 等）。
- 修复：上下文以 KV 字段逐层 `with_field` 挂载；字段表满丢新增但码不变；
  不要把上下文拼进一句话再反解。详见 E-006 README。

### 2.7 错误路径资源泄漏（E-007-goto-cleanup）

- 症状：第三步失败提前 return，buf/handle 泄漏，压测或长跑才偶发暴露。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-007-goto-cleanup`
- 判据：失败路径 `release handle`、`release buf` 按申请逆序出现、不出现
  release lock，落 `open_session rc=8`；成功路径三个资源各申请/释放一次。
- 修复：goto 统一出口 + 释放后置空（双重释放防线见 L1-023；同一主题的
  实机排障演练见 [T-001-oob-double-free](../examples/T-001-oob-double-free/WALKTHROUGH.md)）。
  详见 E-007 README。

### 2.8 日志有错但程序当成功（E-008-error-reraise）

- 症状：中间层打日志后 `return 0`，顶层照常往下走，故障推迟到远处表象。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-008-error-reraise`
- 判据：重抛路径 `[reraise] top sees code=9 -> fail over to replica`；
  吞错路径 `[swallow] top sees success (code=0)`——吞错的可观察后果。
- 修复：中间层动作只有处理掉、补上下文重抛（码不变）、透传三种。
  详见 E-008 README。

### 2.9 errno 与应用码两套体系混用（E-009-errno-boundary）

- 症状：三层深处判 `errno == ERANGE` 时 errno 早被中途库调用改写。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-009-errno-boundary`
- 判据：`input=99999999999999999999999  app_code=2 errno=34`（失败后立即保存）
  与 `map ENOENT=2 -> app_code=3`、`map EACCES=13 -> app_code=3`。
- 修复：errno 在失败后立即保存（L2-014 纪律），翻译只在边界层一处，
  之后全链路只认应用码；输出打 errno 数字值不打 strerror 文案。
  详见 E-009 README。

### 2.10 重试策略失当（E-010-retry-backoff）

- 症状：参数错误被重试到上限白烧 CPU；或真超时因立即重试打在同一个拥堵窗口。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-010-retry-backoff`
- 判据：flaky 场景 `flaky attempt=1 code=4 class=retryable backoff_ms=100`、
  `backoff_ms=200` 后第三次成功；strict 场景首个 attempt 即 `give_up=1`。
- 修复：先分类再重试（只有 TIMEOUT/UNAVAILABLE 类进重试环），固定退避表
  加 attempts 上限。详见 E-010 README。

### 2.11 批量操作无预算/取消无效（E-011-deadline-cancel）

- 症状：后端 hang 后调用方无限等待；外部取消被无视；停止后进度不上报。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-011-deadline-cancel`
- 判据：`deadline code=4 completed_steps=3` 与 `cancel code=6
  completed_steps=2`——两类停止信号各有专门码，且返回已完成步数。
- 修复：检查点放循环顶部安全点；TIMEOUT（内部预算）与 CANCELLED（外部意志）
  分码；阻塞调用必须设预算。详见 E-011 README。

### 2.12 并发批处理只报第一个失败（E-012-error-aggregate）

- 症状：第一个失败整批标红，3 超时 + 1 IO 错被压成 1 个失败，修复后下轮再爆。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-012-error-aggregate`
- 判据：4 行 worker 结果按槽位固定顺序，末行
  `summary total=4 ok=1 failed=3 by_code TIMEOUT=2 IO=1`。
- 修复：每 worker 只写自己的槽位，join 后聚合，既报个数也报 by_code 分布。
  详见 E-012 README。

### 2.13 错误留不下可计算痕迹（E-013-error-observability）

- 症状：错误处理只 perror 一句，聚不了类、告不了警，「超时多了还是 IO 错多了」
  只能人肉 grep。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-013-error-observability`
- 判据：4 行 `event seq=... level=warning/error/info ... attempt=...`，末行
  `metrics total=4 timeouts=2 io_errors=1`（事件与计数同源）。
- 修复：单行 KV 事件 + 同源计数；`attempt` 字段让重试后恢复可见；
  禁止多行打印一个错误。详见 E-013 README。

### 2.14 不变量破坏后带病运行（E-014-fail-fast）

- 症状：内部不变量被破坏后程序继续跑，表象与破坏点相距十万八千里。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-014-fail-fast`
- 判据：ok 路径 `invariant holds`；fatal 路径
  `FATAL invariant violated: main.c:45 (root->left > 0)` 后由 run.sh 捕获打印
  `fatal_exit=70`。
- 修复：只有 INTERNAL 类走快速失败（分类口径见 E-001）；诊断行带
  `文件:行号 + 不变量原文`（`#expr` 字符串化）；退出码固定 70 供监控按码告警。
  详见 E-014 README。

### 2.15 可恢复失败被吞成假数据（E-015-antipattern-compare）

- 症状：打不开文件却照常返回 0，下游产出「看起来正常」的错误结果；
  无崩溃、无非零退出，比崩溃更难发现。
- 排查命令：`TAG=latest bash scripts/run-example.sh c E-015-antipattern-compare`
- 判据：bad 版本 `value=0 error_reported=0` 且 `downstream computed=0`
  （假数据流入下游）；good 版本 `value=none error_reported=1 code=3` 且
  `downstream aborted=1`。
- 修复：失败显式上抛（E-002 纪律），处置（中止/默认值）由调用方显式决策；
  `(void)cfg_open(&ok)` 一类丢弃返回值是事故源头。详见 E-015 README。
