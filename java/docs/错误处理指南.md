# Java 错误处理指南（how-to）

> 面向「要在 Java 代码里把错误处理写对」的操作指南：按任务路由到 E 类示例，
> 每条纪律给得出用例 ID 与验证命令。从已有故障出发的排查走
> [排查手册](排查手册.md)；语法层知识归 L1/L2 用例，本篇不重复贴代码。
> 全部 15 个 E 例已于 2026-11-11 在 `devbox-java:latest` 内真跑通过
> （`TAG=latest scripts/run-example.sh java <ID>`，镜像层真本
> `images/lang-images.tsv`）。

## 1. 适用边界

- 适用于：在本仓库 Java 代码（含毕业项目）里设计或修复错误处理路径——异常分类、
  cause 链、捕获顺序、中断、未捕获出口、清理、重试、致命错误、契约分层、
  结构化日志、死锁、聚合、退出码、降级、反模式自查。
- 不适用于：第一次学 Java 的语法（见 [知识点清单](知识点清单.md) L1 段）；
  手上已经有一个故障要排查（见 [排查手册](排查手册.md)——本篇只讲怎么写对，
  不讲坏了怎么找）。
- 本篇是 how-to：只讲「做某件事的步骤」，不讲完整语法书。命令契约见
  [docs/11](../../docs/11-知识点清单增强规范.md) §4.3（统一 `TAG=latest
  scripts/run-example.sh java <ID>`，禁止硬编码镜像 tag）。

## 3. 十条核心纪律（每条可执行、可断言）

1. **先分类，再处理**（E-001）：每类失败一个异常子类、统一基类
   `DomainError`，`instanceof` 判定不依赖消息文本；处理策略挂在类别
   （VALIDATION 修调用 / TRANSIENT 可重试 / INTERNAL 快速失败）上。
2. **包装必带 cause**（E-002）：`new SomeException(e.getMessage())` 是
   反模式——cause 是链的生命线；根因沿 `getCause()` 走到底，并防御自指。
3. **catch 子类在前、能并则并**（E-003）：javac 对「子类跟在父类后」报错，
   对「重复块」不报——后者靠 `catch (A | B)` 联合捕获维持。
4. **中断信号必须回信**（E-004）：捕获 `InterruptedException` 后立即恢复
   中断位；当前层不处理就把请求传给下一个检查点，空吞让取消机制整体失灵。
5. **每条线程路径都有失败出口**（E-005）：裸线程靠
   `UncaughtExceptionHandler`，池任务靠观测 Future；两条出口二选一覆盖。
6. **清理失败不遮盖主异常**（E-006）：手写 finally 抛新异常会替换待传播
   异常；try-with-resources 把关闭异常挂进 `getSuppressed()`。
7. **只重试 TRANSIENT，退避且封顶**（E-007）：VALIDATION 是调用方 bug，
   重试修不好只会放大下游压力；退避按 `base * 2^(n-1)` 增长且次数封顶。
8. **致命错误按触发源分类**（E-008）：`getClass().getName()` 做锚点不按
   message；heap-exhaustion 查泄漏，StackOverflowError 修递归。
9. **assert 守 bug、类型化异常守契约**（E-009）：生产 JVM 默认关断言，
   公共 API 校验用 `IllegalArgumentException` 等类型化异常。
10. **日志给机器查、退出码给脚本消费**（E-010/E-013/E-015）：单行 JSON、
    类别是字段；类别 → 退出码只在进程边界映射一次；禁止
    `getMessage().contains("timeout")` 一类文本分流。
