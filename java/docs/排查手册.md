# Java 排查手册（troubleshooting）

> 按「症状 → 排查命令 → 判据 → 修复」组织的手册。§2 是错误处理章，含
> §2.1–§2.15 共 15 节，逐节对应 `java/examples/E-001..E-015`（各例 README 的
> `coverage: exempt` 注释指向本手册 §2 的对应节）。
> §3、§4 是路由章：并发/JVM 与构建/运行问题的入口指向既有指南与 lab。
> 全部排查命令已于 2026-11-11 在 `devbox-java:latest` 内真跑核对（15/15 PASS）；
> 写法纪律见 [docs/72-排障演练规范](../../docs/72-排障演练规范.md)（现象禁止编造，
> 只许来自真跑或已登记问题）。

## 1. 使用方法

1. 先在本手册按症状定位到节；每节给一条可直接执行/粘贴的排查命令与判据输出。
2. 判据不成立 → 按该节「修复」处理；判据成立但问题仍在 → 走该节给出的关联文档。
3. 「怎么写对」的设计问题走 [错误处理指南](错误处理指南.md)；镜像、版本、环境变量
   事实走 [工程参考](工程参考.md)。

## 2. 错误处理章（对应 E-001..E-015）

### 2.1 同一异常在不同调用点行为不一致（E-001-exception-taxonomy）

- 症状：同一种失败有的被当输入问题拒绝、有的被重试三次、有的静默吞掉，
  行为随调用点漂移。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-001-exception-taxonomy`
- 判据：末行 `taxonomy types=3 VALIDATION=1 TRANSIENT=1 INTERNAL=1`——三类
  异常各归唯一类别，类别决定唯一动作（reject-input / retry / fail-fast）。
- 修复：每类一个异常子类、统一基类 `DomainError`，一次 `catch (DomainError)`
  接住后按 `instanceof` 归类；处理策略挂在类别上，不散落成各调用点的 if 表。
  详见 E-001 README。

### 2.2 排障只见「某操作失败」不见根因（E-002-cause-chain-walk）

- 症状：跨层包装只复制消息不带 cause，顶层日志说不清「为什么失败」、
  也说不清包装了几层。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-002-cause-chain-walk`
- 判据：`root cause: java.io.IOException: sector unreadable`（沿 `getCause`
  走到底取出根因）与 `chain-depth: 3`（三层链逐层可读）。
- 修复：包装构造器必须用 `(message, cause)` 二参版本；`rootCause` 沿
  `getCause()` 走到 null 并防御自指（cause == self）。详见 E-002 README。

### 2.3 catch 分支永远不命中 / 重复处理块（E-003-catch-order）

- 症状：子类 catch 跟在父类之后成不可达代码（javac 直接报错）；或同一段
  处理逻辑散成多个重复 catch 块靠约定维持。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-003-catch-order`
- 判据：`specific-first: FileNotFoundException caught: docs/7 missing`
  （子类先命中）、`union-catch: FileNotFoundException caught by union handler`
  （联合捕获），末行 `order-rule: subclass handlers must precede their base class`。
- 修复：catch 按书写顺序自上而下匹配——子类处理器写在父类之前；无子类
  关系的同类处理用 `catch (A | B)` 联合捕获。详见 E-003 README。

### 2.4 任务停不下来 / shutdown 等到超时（E-004-interrupt-handling）

- 症状：取消请求发了但任务不响应，线程池 shutdown 等到超时——中断信号被
  空吞，取消机制整体失灵。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-004-interrupt-handling`
- 判据：`worker: interrupted during sleep` → `worker: flag restored=true` →
  `worker: stopped cooperatively`，末行
  `rule: catching InterruptedException must restore the flag or exit`。
- 修复：捕获 `InterruptedException` 后立即
  `Thread.currentThread().interrupt()` 恢复标志，再按标志协作停止；当前层
  不处理就必须把信号传给下一个检查点。详见 E-004 README。

### 2.5 任务跑了但没结果（静默失败）（E-005-uncaught-handler）

- 症状：裸线程里抛出的异常默认只往 stderr 打一行；线程池任务异常被
  Future 静默持有，不 `get()` 就永远无人知晓。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-005-uncaught-handler`
- 判据：`handler: caught IllegalStateException from worker-1`（裸线程出口）、
  `executor-no-get: future held the failure, nothing surfaced`（反例）与
  `executor-get: ExecutionException caused by IllegalStateException`（观测出口）。
- 修复：两条出口二选一覆盖——裸线程靠 `UncaughtExceptionHandler`（或
  `ThreadFactory` 统一装），池任务靠「每个 Future 都被 get/回调观测」。
  详见 E-005 README。

### 2.6 日志只见 close failed，业务异常消失（E-006-suppressed-cleanup）

- 症状：手写 finally 清理时 `close()` 自己抛的异常把业务异常整个顶掉，
  真正的故障连一行痕迹都没有。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-006-suppressed-cleanup`
- 判据：`manual-finally: surfaced=IllegalStateException suppressed-count=0
  (business error masked by close failure)` 对照
  `twr: surfaced=BusinessError suppressed=[IllegalStateException]`。
- 修复：清理用 try-with-resources，关闭异常进 `getSuppressed()`；手写
  finally 里不要抛新异常顶掉主异常。详见 E-006 README。

### 2.7 临时故障一抖就整体报错 / 重试放大下游压力（E-007-retry-backoff）

- 症状：不区分错误类型全部重试：参数错误重试三次原样失败，无退避的
  紧逼重试是雪崩放大器。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-007-retry-backoff`
- 判据：`backoff: delays=10,20ms -> 2 retries before success`（前两次
  TRANSIENT 按指数退避后第三次成功）与
  `no-retry: ValidationException rejected immediately (age must be a positive integer)`。
- 修复：重试器只接 `TransientException`（VALIDATION 是调用方 bug）；退避按
  `base * 2^(n-1)` 指数增长且次数封顶。详见 E-007 README。

### 2.8 日志见 OutOfMemoryError 就加堆，越加越坏（E-008-oom-taxonomy）

- 症状：按消息文本一刀切：递归失控（`StackOverflowError`）被加堆掩盖，
  堆泄漏被加堆推迟，直到容器 OOM-killed 才发现方向全错。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-008-oom-taxonomy`
- 判据：`oom-kind: heap-exhaustion -> action=raise-heap-or-fix-leak` 与
  `soe-kind: call-depth -> action=fix-recursion`，末行
  `taxonomy: fatal errors are classified by trigger, not by message text`。
- 修复：用 `getClass().getName()` 做分类锚点而不是 message；heap-exhaustion
  查泄漏或加堆，StackOverflowError 修递归。容器内复现小堆 OOM 与 jcmd
  交叉验证见 [T-001 WALKTHROUGH](../examples/T-001-deadlock-oom/WALKTHROUGH.md)。
  详见 E-008 README。

### 2.9 生产环境校验消失 / 告警等级全错（E-009-assert-contract）

- 症状：用 `assert` 校验公共 API——生产 JVM 默认不带 `-ea`，校验整个消失；
  反过来用 `IllegalArgumentException` 表达内部不变量，把程序 bug 伪装成
  用户错误。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-009-assert-contract`
- 判据：`assert-enabled: true`（`-ea` 下开启）、
  `internal-invariant: AssertionError caught (assertions guard internal bugs)`、
  `public-api: IllegalArgumentException: amount must be positive`。
- 修复：assert 只守内部不变量（测试用 `java -ea` 运行）；公共 API 契约用
  `IllegalArgumentException` / `NullPointerException` 等类型化异常。详见
  E-009 README。

### 2.10 告警规则随日志措辞静默失效（E-010-structured-logging）

- 症状：错误日志是自由文本，统计「过去一小时 TRANSIENT 错误几次」只能
  正则解析；措辞一改告警规则和统计全部静默失效。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-010-structured-logging`
- 判据：三行 JSON 各固定含 `seq / code / level / message`，末行
  `rule: one JSON per line; error class is a field, not a message prefix`。
- 修复：一行一个 JSON，错误类别（code/level）是字段不是消息前缀，日志与
  计数同源。详见 E-010 README。

### 2.11 程序不退出也不报错（活着但卡死）（E-011-deadlock-diagnosis）

- 症状：两个线程以相反顺序获取 lockA/lockB 形成互等闭环；与素材 S-14
  同源。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-011-deadlock-diagnosis`
  （进程内 ThreadMXBean 检出）；容器级用 `jcmd <pid> Thread.print` 看
  `Found one Java-level deadlock:`——复现与交叉验证见
  [T-001 WALKTHROUGH](../examples/T-001-deadlock-oom/WALKTHROUGH.md)。
- 判据：`deadlock-detected: true`、`deadlocked-threads: worker-1,worker-2`、
  `fix-run: completed without deadlock (uniform lock order)`。
- 修复：统一锁序杀死闭环；`tryLock` 带超时做兜底。详见 E-011 README。

### 2.12 批量任务每轮只冒出一个坏任务（E-012-error-aggregation）

- 症状：一个失败就 cancel 其余或直接抛出：N 个坏任务要跑 N 轮，成功任务
  的结果被一并丢弃。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-012-error-aggregation`
- 判据：4 个任务按提交顺序逐个记账（`doc-2: FAILED ValidationException
  (schema mismatch)`、`doc-4: FAILED TransientException (storage busy)`），
  末行 `aggregate: ok=2 failed=2 -> collect all failures before deciding`。
- 修复：全部跑完、逐个记账、汇总后再决策；失败按任务隔离，不中断批次。
  详见 E-012 README。

### 2.13 调用方分不清该修命令还是修数据（E-013-exit-code-protocol）

- 症状：批处理所有失败一律 `System.exit(1)`（甚至异常栈直接崩出退出码 1），
  脚本/CI/调度器只能解析 stdout 文本猜。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-013-exit-code-protocol`
- 判据：`protocol: usage=2 data=1 success=0` 与三条探针
  `probe-usage-exit: 2`、`probe-data-exit: 1`、`probe-ok-exit: 0`。
- 修复：错误类别到退出码的映射只在进程边界做一次（Main 声明协议），内部
  异常类不散落 `System.exit`。详见 E-013 README。

### 2.14 主源一抖整条读路径报错 / 降级不透明（E-014-graceful-degradation）

- 症状：主数据源抖动直接报错，缓存快照可用却拿不到任何结果；或降级
  「成功」却没人知道结果来自回退路径、主路径已经坏了多久。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-014-graceful-degradation`
- 判据：`primary failed: primary-db: TRANSIENT primary-db offline`（原因逐字
  留痕）、`fallback: stale-snapshot (served by cache)`（来源标注）、
  `degradation: failed-sources=1`；全路径失败时
  `no-source: no source available: ...`。
- 修复：降级必须带留痕的原因与数据来源标注；只有每条路径都失败才报错。
  详见 E-014 README。

### 2.15 失败与成功从外部无法区分（E-015-antipattern-compare）

- 症状：`catch (Exception e) {}` 把失败吞进黑洞（任务失败与成功从外部无法
  区分）；`getMessage().contains("timeout")` 文本分流，措辞一改行为漂移。
- 排查命令：`TAG=latest bash scripts/run-example.sh java E-015-antipattern-compare`
- 判据：`anti-1: swallowed (bug invisible) -> wrong` 对照
  `fix-1: {"code": "TRANSIENT", "message": "storage busy", "type":
  "TransientException"} -> logged, visible`；`anti-2: other (classified by
  message text) -> wrong` 对照 `fix-2: TRANSIENT (classified by type) -> stable`。
- 修复：不静默吞错；按类型分类；每条错误单行结构化日志。详见 E-015 README。
