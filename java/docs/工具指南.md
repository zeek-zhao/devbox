# Java 轨道 G4 工具指南

> 工具预装情况均在 `ghcr.io/zeek-zhao/devbox-java:${TAG:-latest}` 容器内实测
> （`which`/`command -v` 逐个验证）；版本号一律引 `images/versions.env` 变量名，真本见该文件。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源 |
|---|---|---|---|
| `java` / `javac` | 运行 / 编译（`--release` 控制字节码级别） | 是（`/opt/java-home/bin`） | `${JAVA_MAJOR}`（`images/versions.env`） |
| `jar` | 打包可执行 jar（`--main-class`） | 是 | 随 JDK（`${JAVA_MAJOR}`） |
| `jshell` | REPL 交互实验与批处理脚本 | 是 | 随 JDK |
| `javap` | 反汇编字节码，核对 major version / 调用点 | 是 | 随 JDK |
| `javadoc` | 生成 API 文档（`-Xdoclint:all`） | 是 | 随 JDK |
| `jcmd` / `jstack` / `jmap` / `jps` | 线程栈、堆、进程诊断 | 是 | 随 JDK |
| `mvn` | 工程级构建（Maven） | 是（`/usr/bin/mvn`） | 未锁版本，以 `mvn -version` 为真 |
| `gjf` | google-java-format 格式化器（`--aosp`） | 是（`/usr/local/bin/gjf`） | `${GJF_VERSION}`（与 `GJF_SHA256` 成对校验） |
| `gcc` / `cc` | 编译 JNI 用的 `.so` | 是（`/usr/bin/gcc`、`/usr/bin/cc`） | 随基础镜像 |

预装验证命令（应逐个给出路径而非 MISSING）：

```bash
docker run --rm ghcr.io/zeek-zhao/devbox-java:${TAG:-latest} bash -lc 'which java javac mvn gjf jar jshell jcmd gcc cc; java -version'
```

## 2. 每工具一节

### 2.1 javac / java

- 装在哪：`JAVA_HOME=/opt/java-home`（镜像内由 install 脚本从 `javac` 反解生成）。
- 怎么调：本工程固定 `javac --release 21 -encoding UTF-8 -Xlint:all -Werror`（与 `${JAVA_MAJOR}` 一致，`L2-002-compile-bytecode`）；运行 `java -ea -cp out app.Main`（`-ea` 开断言，测试 harness 依赖它）。
- 速查：`--release N` 决定字节码级别（major version = 44+N）；`-d out` 指输出目录（classpath 根）；`-h` 生成 JNI 头。

### 2.2 jar

- 调用：`jar --create --file app.jar --main-class app.Main -C out .`，之后 `java -jar app.jar` 独立于 classpath 运行（`L2-003-executable-jar`）。
- 速查：`--list --file app.jar` 查内容；必须从完整输出根目录打包，只放入口 class 会丢辅助类。

### 2.3 jshell

- 调用：交互式直接 `jshell`；脚本批处理用 `jshell --feedback silent script.jsh`。批处理时诊断不等于失败——要显式检查并打业务标记（`L2-011-jshell-experiments`）。

### 2.4 javap

- 调用：`javap -verbose -classpath out app.Main`；核对 `major version: 65`（对应 `--release 21`）与方法调用点（`L2-002-compile-bytecode`）。

### 2.5 javadoc

- 调用：`javadoc -quiet -Werror -Xdoclint:all -d api -sourcepath src devbox.rest`；`@param/@return/@throws` 与签名不一致即红灯（`L2-004-api-javadoc`）。

### 2.6 jcmd（含 jstack/jmap/jps）

- 调用：`jcmd <pid> Thread.print` 抓线程栈定位阻塞帧（`L3-003-jvm-thread-diagnostics`）；`jps`/`jps -l` 找自有 JVM 进程。
- 速查：`Thread.print` 抓栈优先于 `jstack`（见 §4 误用 2）；`jmap -histo <pid>` 看对象直方图。

### 2.7 mvn

- 调用：容器内 `mvn` 直接可用；`MAVEN_OPTS` 由镜像环境变量带入（本地仓库 `/opt/m2`、UTF-8）。本工程用例编译不依赖 Maven，Maven 属工程级选项；版本未锁，升级以镜像内 `mvn -version` 输出为准。

### 2.8 gjf（google-java-format）

- 调用：统一走 `bash scripts/fmt.sh --lang java`（等价容器内 `gjf --aosp --replace`），不要在宿主找 gjf。版本 `${GJF_VERSION}` 与 `GJF_SHA256` 成对校验，改版本必然影响全仓格式，须与 CI 对齐。

### 2.9 gcc / cc

- 调用：仅 JNI 用例需要：`javac -h` 生成头，`gcc -shared -fPIC -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux"` 编 `libprobe.so`，`-Djava.library.path` 指向库目录（`L3-006-jni-native`）。

## 3. 选型对比

- **构建工具**：Maven vs Gradle——本工程统一 Maven。原因：镜像内 apt 提供的 Gradle 过旧，且用例层只需 `javac`；Maven 由 `MAVEN_OPTS` 统一本地仓库与编码。若引入 Gradle 需先改 `images/versions.env` 与镜像层，属基础设施变更。
- **格式化器**：不适用：无同类（Java 轨道唯一指定 google-java-format `--aosp`，无备选）。
- **REPL**：不适用：无同类（JDK 自带 jshell，无第三方 REPL）。

## 4. 常见误用

1. **OOM 只会说「内存不够」**：`OutOfMemoryError` 要看附带的详细消息分类——`Java heap space`（堆不足/泄漏）、`GC overhead limit exceeded`（GC 时间占比过高，常是泄漏早期）、`Metaspace`（类加载器泄漏）。定位先 `jmap -histo <pid>` 看对象直方图，而不是盲目调大 `-Xmx`；分类错了修复方向就错。
2. **死进程用 jstack 抓栈**：`jstack <pid>` 在目标 JVM 卡死/资源紧张时可能连不上；优先 `jcmd <pid> Thread.print`（同进程内执行，成功率高）。抓栈要多次采样对比——单次栈分不清「阻塞」与「刚好在跑」，死锁会有线程互等 `waiting to lock` 的闭环。
3. **把 NoClassDefFoundError 当类不存在**：`ClassNotFoundException`（加载期找不到，查 classpath）与 `NoClassDefFoundError`（编译期在、运行期缺，常见于打包漏辅助类或静态初始化失败）根因不同。先确认 `jar --list --file app.jar` 里有没有目标类，再看初始化异常。
4. **输出乱码先怀疑终端**：Java 默认编码跟随平台 locale，跨容器读写文件必须显式 `StandardCharsets.UTF_8`（`L2-008-files-utf-eight`），构建编码由 `MAVEN_OPTS` 的 `-Dfile.encoding=UTF-8` 保证；时区同理，比较/落盘时间戳要显式 `ZoneId`，不依赖容器默认时区。
