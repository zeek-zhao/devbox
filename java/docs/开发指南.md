# Java 轨道 G2 开发指南

> 本文只写 Java 轨道差异；跨语言通用流程（runner 用法、提交身份、门禁、PR 约定）
> 见 §6 的 T0 链接，不在本文复制。

## 1. 环境与启动

- **镜像**：`ghcr.io/zeek-zhao/devbox-java:${TAG:-latest}`（tag 规则见镜像体系文档；本地已有镜像想省去拉取时把 `TAG` 换成 `local`）。
- **JDK 版本**：`${JAVA_MAJOR}`（真本是 `images/versions.env`，不在本文写字面量）。
- **构建工具**：Maven。版本真本未锁，以镜像内 `mvn -version` 为准；`MAVEN_OPTS`（本地仓库 `/opt/m2` 与 UTF-8 编码）同样来自 `images/versions.env`。本工程用例编译只用 `javac`，Maven 用于工程级构建。
- **JAVA_HOME**：镜像内固定 `/opt/java-home`，由 `install/java.sh` 从 `javac` 反解生成，并已加入 `PATH`；不要手写 JDK 路径。
- **classpath 来源**：本工程不用 IDE 工程文件。单用例由 `run.sh` 自己负责 `javac -d <输出目录>` + `java -cp <输出目录>`，classpath 就是编译输出目录（包根），见 `L2-001-packages-classpath`。
- **进入环境**：宿主不需要 JDK，任何构建/运行都在容器里做：

  ```bash
  docker run --rm -v "$PWD:/work" -w /work/java ghcr.io/zeek-zhao/devbox-java:${TAG:-latest} bash -lc 'java -version'
  ```

## 2. 目录结构与各文件职责

```text
java/
  examples/<ID>/   用例目录，runner 的最小单元
    run.sh         编译+运行该用例，只往 stdout 打业务输出（runner 与它逐行比对）
    expected.txt   期望输出，逐行精确（忽略行尾空白）
    README.md      考点说明
  project/         毕业项目（REST 索引服务）：build.sh 幂等编译+测试，check-runtime.sh 运行时自检
  docs/            本轨道文档：知识点清单.md 与本指南层三件套
```

改动 Java 代码只涉及这三处；`scripts/` 与 `images/` 属基础设施，动它们等于动门禁。

## 3. 一条命令跑通

```bash
TAG=latest scripts/run-example.sh java L1-004-string-pool
```

预期输出 `PASS`。失败时按顺序看：

1. runner 打出的最后几行——`expected.txt` 与 stdout 的逐行 diff 就在那里；
2. 加 `--keep` 保留容器，`docker exec` 进去手动重放 `run.sh` 里的编译命令，看 stderr；
3. 确认不是旧镜像：`docker image inspect ghcr.io/zeek-zhao/devbox-java:latest` 与 CI 的 tag 对齐；
4. 仍然红：按 T0 的 CI 红灯定位流程走（见 §6），不要改 `expected.txt` 凑绿。

## 4. 改动循环

改 → 格式化 → 编译 → 测试 → 提交，全部可在宿主一条命令完成：

1. **改**：改 `java/examples/<ID>/` 或 `java/project/src/` 下的 `.java`；
2. **格式化**：`bash scripts/fmt.sh --lang java`——容器内跑 google-java-format `--aosp`（4 空格），版本由 `${GJF_VERSION}` 锁定（真本 `images/versions.env`，校验和成对校验）；宿主没有格式化器，直跑必然 command not found；只检查不落盘用 `bash scripts/fmt.sh --lang java --check`；
3. **编译**：单用例由 runner 代做；工程用 `bash java/project/build.sh`（`--release 21`、`-Xlint:all -Werror`，即 `L2-002-compile-bytecode` 的口径），打 jar 见 `L2-003-executable-jar`；
4. **测试**：单用例 `TAG=latest scripts/run-example.sh java <ID>`；工程 `build.sh` 自带 `java -ea` 测试与自检；格式红线用 `--check` 模式预演；
5. **提交**：提交身份与信息约定见 T0（§6）。不要提交 `build/` 产物。
