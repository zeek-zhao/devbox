## 1. 怎么用这份清单

本清单决定 Java 用例的考点与验收边界；一个 KP 对应一个建议用例 ID，不合并、不拆分。共 50 条：L1 33 条语言与标准库基础，L2 11 条工程能力，L3 6 条专题。L1 以单文件、50 行内展示核心现象为目标；L2 处理多文件、命令行工具与测试；L3 处理并发、JVM、二进制格式、基准与本地接口。

工具链固定为 `javac 21.0.12.1` / `openjdk 21.0.12.1`，只用 `javac`、`java`、JDK 工具及标准库；JNI 另用镜像已有的 `gcc`/`cc`。不启用预览特性，不下载依赖。测试采用手写 harness 与 `java -ea`。毕业项目落点统一指向 Java 命令行文本索引器的构建、查询与持久化。

验收分两层：代码或命令检查下面的具体判据，stdout 只保留固定业务结果。负向编译只检查非零退出及对应错误类别，不匹配完整编译器诊断；预期异常显式捕获并检查类型，非预期异常必须传播。无序集合先排序，并发必须等待完成；时间、PID、线程 ID、地址、绝对路径与完整工具版本不进入 expected。

## 明确不覆盖的

| 内容 | 为什么不覆盖 |
|---|---|
| 第三方构建工具、下载插件及依赖仓库工作流 | 镜像无外网且本地依赖缓存目录不存在，命令可执行不代表插件可解析；本清单只考 JDK 自带编译与打包。 |
| 第三方 jar、测试框架及 JSON 工具包 | 无网络与预置依赖，无法离线重建；使用标准库及手写 harness，不把无法运行的生态能力计入覆盖。 |
| Web 框架、数据库驱动及 GUI | 属于生态/框架或需要外部服务与显示环境，不是本轮语言能力和命令行索引器的验收边界。 |
| Java 预览特性与内部 JDK API | 预览需额外开关、内部 API 受版本与模块封装影响；Java 21 的 record、sealed、正式 switch 模式匹配已足够。 |
| 垃圾回收触发时刻、对象地址与终结回调顺序 | GC 与调度不保证固定时刻和顺序，不能稳定断言；资源关闭使用 AutoCloseable，不将回收等同于及时关闭。 |
| 非 Java 的对象销毁与编译期元编程机制 | 不属于 Java 语义，照搬其他语言会考错能力；这里考引用副本、类型擦除、资源关闭与 JVM。 |
| 以竞态坏例的必然失败、并发日志顺序作判据 | 数据竞争不保证每次丢更新，调度也不保证顺序；只断言正确同步后的结果并检查关键同步路径。 |
| 外网通信与绝对性能阈值 | 无外网且运行负载不可控，结果不确定；专题使用操作计数与可归一化的本地 JVM 诊断。 |
| 原生对象自动序列化与不可信对象反序列化 | 其对象图、兼容及安全边界超出本轮明确字节协议；使用手写带版本、长度检查的二进制格式。 |
