# L1-030-strict-mode


## 考点
对应 KP-SH-L1-30：观察 `set -euo pipefail` 的失败传播，并显式处理允许失败的命令。
未命中被 `if` 接住、未处理失败与未定义变量导致子脚本失败，说明理解严格模式边界。

## 易错点
`-e` 在条件判断等语境有例外，不能替代错误处理；预期失败放进 `if` 并检查状态。
把允许失败的操作放进显式分支，而不是假设 `-e` 会替脚本处理所有情况。

## 延伸
比较管道中 `pipefail` 对失败状态的影响，并为每个可恢复错误定义处理策略。
为关键子命令验证输入、状态码和错误输出，避免只依靠严格模式判断业务正确性。
