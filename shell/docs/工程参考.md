# Shell 工程参考（G4 · 参考）

> 本文只有一个主要承诺：**Shell 轨道的工程事实速查**——镜像、构建、运行、依赖、
> 环境变量、版本真本，一张表对齐，全部可从仓库内文件复核。
> 通用开发动线（runner 细节、CI、门禁、提交纪律）是 T0 真本：
> [docs/13-通用开发指南](../../docs/13-通用开发指南.md)，本文只写 Shell 轨差异。

## 1. 工程全景表

| 域 | 事实 | 真本出处 |
|---|---|---|
| 镜像 | `ghcr.io/zeek-zhao/devbox-shell:latest`（本地自建时 `TAG` 用 `local`） | `images/shell/Dockerfile`、`images/lang-images.tsv`（shell 映射 shell 层） |
| 解释器 | bash，随 Ubuntu base 层（`${UBUNTU_TAG}`），不单独锁版本 | `images/versions.env` |
| lint 口径 | shellcheck 严重级锁 `${SHELLCHECK_SEVERITY}`（warning），Makefile 与 build.sh 同口径 | `images/versions.env` |
| 构建 | `bash shell/project/build.sh`（bash -n 语法检查 + shellcheck 门禁 + 产物 stamp） | `shell/project/build.sh` |
| 运行用例 | `TAG=latest scripts/run-example.sh shell <ID>` | `scripts/run-example.sh`、[docs/13](../../docs/13-通用开发指南.md) §1 |
| 列出用例 | `scripts/run-example.sh shell --list` | 同上 |
| 依赖 | 只用 bash 内建与 std 工具（grep/diff/timeout 等）；辅助工具版本走真本（如 `${YQ_VERSION}`） | `images/versions.env` |
| 环境变量 | `TAG` / `IMAGE_TAG` / `REGISTRY` / `${SHELLCHECK_SEVERITY}` 口径 | 本文 §5 |
| 用例计数 | `shell/examples/` 69 个目录 = L 系 54（L0 1 + L1 35 + L2 12 + L3 6）+ E 系 15 | `ls shell/examples \| wc -l` |

## 2. 镜像层与版本真本

- Shell 镜像继承 base → tool 层（`make build-base build-tool build-lang`，
  [docs/01](../../docs/01-镜像体系.md)）；语言层自身极薄——bash 来自 base，
  补充工具的版本一律引用 `images/versions.env` 变量名（`${YQ_VERSION}`、
  `${YQ_SHA256}`），Dockerfile 禁止写死版本号（`scripts/check-version-truth.sh` 卡）。
- 用例命令里的 `TAG=latest` 与 CI 传入的 `IMAGE_TAG` 是同一个值的两个名字；
  历史教训见 [docs/13](../../docs/13-通用开发指南.md) §1。
- 镜像拉不动时先看 CI 的 `probe` job——那是镜像问题不是代码问题。

## 3. 构建与运行

| 动作 | 命令 | 说明 |
|---|---|---|
| 轨道质量门禁 | `bash shell/project/build.sh` | `bash -n` 逐文件语法检查 + `shellcheck -S ${SHELLCHECK_SEVERITY}` 门禁 |
| 单个用例 | `TAG=latest scripts/run-example.sh shell E-006-error-context` | stdout 逐行比对 `expected.txt` |
| 整门语言 | `TAG=latest scripts/run-example.sh shell --all` | 全量 69 个用例 |
| 保留现场 | `TAG=latest scripts/run-example.sh shell <ID> --keep` | 容器不销毁，`docker exec` 进去复现 |
| 全仓格式检查 | `make fmt-check` | shfmt 口径，随仓库统一脚本 |
| 全仓 lint | `make lint` | shellcheck 按 `${SHELLCHECK_SEVERITY}` 阈值 |

失败时先看哪里：runner 最后一段输出指明是语法错误、超时还是期望输出不匹配；
再 `--keep` 进容器看现场；最后才怀疑镜像（[docs/13](../../docs/13-通用开发指南.md) §1）。

## 4. 依赖纪律

- **只用 bash 内建 + std 工具**：`shell/examples/` 各用例不引入需要额外安装的解释器
  或框架；镜像内工具清单见 [工具指南](工具指南.md) §1 全景表。
- 需要新工具时走 `images/versions.env`（变量 + 校验和）→ Dockerfile ARG 流程，
  不在用例里临时下载（容器离线，下载不可重复）。
- 脚本纪律基线：`set -euo pipefail`（`L1-030-strict-mode`）、变量加引号、
  诊断走 stderr——对应 [知识点清单](知识点清单.md) §2 各 KP。

## 5. 环境变量速查

| 变量 | 谁读 | 作用 | 与错误处理的关系 |
|---|---|---|---|
| `TAG` | `scripts/run-example.sh` | 选镜像 tag，文档统一写 `TAG=latest` | 跑 E 系演练用例的前置 |
| `IMAGE_TAG` | CI | `TAG` 的 CI 别名，同一个值 | 禁止在文档里混用两个名字 |
| `REGISTRY` | `scripts/run-example.sh` | 镜像仓库前缀，缺省读 `images/versions.env` 的 `${REGISTRY}` | 私有部署时改 |
| `${SHELLCHECK_SEVERITY}` | `make lint` / `shell/project/build.sh` | shellcheck 判红阈值（warning） | lint 红不红以它为准，别自改级别 |

## 6. 常见误用

1. **在文档/脚本里手写 shellcheck 级别常量**：门禁阈值只许引用
   `${SHELLCHECK_SEVERITY}`；手写常量在阈值调整时集体过期（各轨指南已有实测教训）。
2. **把 `TAG=latest` 写成 `devbox-shell:local` 这类硬编码 tag**：本地自建镜像时才用
   `local`，文档统一 `TAG=latest`（[docs/13](../../docs/13-通用开发指南.md) §1 命令契约）。
3. **给 `shell/examples/` 加新目录当演练场**：演练素材放 `<lang>/labs/`，绝不进
   `examples/`（会污染用例计数口径，见 [docs/72](../../docs/72-排障演练规范.md) §1）。

## 7. 选型对比

不适用：本轨道解释器单一（bash + std 工具），无同类可替换解释器，不存在选型问题；
shellcheck 是镜像内唯一静态检查器（无同类）。
