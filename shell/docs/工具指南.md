# Shell 轨道工具指南（G4）

> 「是否预装 / 版本」全部来自 2026-11-05 在 215 上对
> `ghcr.io/zeek-zhao/devbox-shell:latest` 的容器实测：
> `docker run --rm ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest} bash -lc '<cmd>'`。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源 |
|---|---|---|---|
| bash | 主解释器 | 预装（实测 5.2.21） | Ubuntu 24.04 系统自带，versions.env 不锁 |
| sh | POSIX 对照解释器 | 预装（实为 dash） | 系统自带；写 POSIX 用例用它验证方言边界 |
| shellcheck | 静态检查 | 预装（`/usr/bin/shellcheck`，实测 0.9.0） | apt 安装；严重级口径锁 `${SHELLCHECK_SEVERITY}`（warning） |
| shfmt | 格式化 | 预装（实测 3.8.0） | apt 安装；参数口径在 `scripts/fmt.sh` |
| bats | 测试框架 | 预装（实测 Bats 1.10.0） | apt 安装 |
| jq | JSON 处理 | 预装（实测 jq-1.7） | apt 安装 |
| yq | YAML 处理 | **未预装（实测 `command -v yq` 为空）** | `install/shell.sh` 声明安装并锁 `${YQ_VERSION}`，但 latest 镜像里没有——安装脚本与镜像产物漂移；重建镜像才能获得 |

> 除 yq 外的版本都是 apt 系统包，未逐个锁补丁号；表内数字是实测快照，以容器 `--version` 为准。
> shellcheck/shfmt 同时存在于 tool 层与语言层（`install/shell.sh` 幂等重装），shell 镜像可脱离 tool 层独立使用。

## 2. 每工具一节

### bash / sh（解释器与语法检查）

- 装在哪：语言层镜像系统内。
- 怎么调：`bash script.sh`；语法只查不执行 `bash -n script.sh`（项目 build.sh 的第一道门）。
- 严格模式：`set -euo pipefail` 是本轨基准（镜像自检也用它），见 L1-030-strict-mode；`pipefail` 让管道中间的失败不再被吞，见 L1-021-pipeline-pipefail。
- 方言边界：`sh` 是 dash，跑 POSIX 兼容性验证用例（L2-007-posix-bash-portability）时用。

### shellcheck（静态检查）

- 怎么调：`shellcheck -S warning <文件...>`；仓库门禁（Makefile lint、项目 build.sh）都用 `-S warning` 口径，local 变量与告警级别以此为准。
- 参数速查：`-S <severity>` 最低报告级别；`-x` 跟随 source 的文件；`-s bash` 指定目标方言。
- 相关用例：见 L2-002-shellcheck-warning-gate。

### shfmt（格式化）

- 装在哪：语言层镜像。
- 怎么调：仓库统一入口 `make fmt`（写）/ `make fmt-check`（只查），shell 车道真本在 `scripts/fmt.sh`：`shfmt -w -i 2 -ci -ln bash`。
- 参数速查：`-i 2` 缩进 2 空格；`-ci` switch 缩进；`-ln bash` 语言方言；`-w` 写回、`-d` 显示差异（CI 语义）。
- 宿主机没装 shfmt 时不要手拍格式——统一走 `make fmt`，容器里有。

### bats（测试框架）

- 怎么调：进容器 `bats <文件>.bats`；用例形态见 L2-003-bats-run-assertions，fixture 用法见 L2-004-bats-fixtures。
- 参数速查：`bats --filter <名字>` 只跑匹配的 `@test`；`--tap` 输出 TAP 格式供 CI 消费。

### jq（JSON 处理）

- 怎么调：`jq '<filter>' file.json`；教学用例见 L3-003-jq-json-processing。
- 常用：`.key`、`.[]`、`-r` 原样输出字符串、`-e` 以结果真值定退出码。

### yq（YAML 处理）——当前不可用

- 设计上 `shared/lib/yaml.sh` 全部函数建立在 yq 之上，但 latest 镜像实测没有 yq。复现：`docker run --rm ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest} yq --version`（实测 `command not found`）。修复路径是重建 shell 镜像（构建机需要能下载 GitHub release）；在修好之前，不要把依赖 yq 的脚本当成可运行示例。

## 3. 选型对比

| 需求 | 本工程选择 | 同类 |
|---|---|---|
| 静态检查 | shellcheck | 不适用：无同类（镜像内无第二家 shell linter） |
| 格式化 | shfmt | 不适用：无同类 |
| 测试框架 | bats | 对照项是「手写 assert 函数」（L2-001 脚本骨架），bats 的价值在断言输出与可筛选执行 |
| JSON 处理 | jq | 同类应是 yq（YAML 侧），但 yq 当前未预装，见 §2 |
| YAML 处理 | yq（设计上） | 当前镜像不可用，属已知漂移而非选型问题 |

## 4. 常见误用（≥2 条，均给可复现命令）

1. **未引用的变量展开被拆词**。后果：含空格的值被拆成多个参数、glob 再展开一遍。可复现（对应 L1-003-quoting-word-splitting）：
   ```bash
   docker run --rm ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest} bash -c 'value="two words"; for x in $value; do echo "[$x]"; done'
   ```
   输出两行 `[two]` `[words]`；把 `$value` 写成 `"$value"` 才是一行。默认把数据展开写成 `"$value"`、转发参数用 `"$@"`。
2. **以为 `set -e` 万能**。失效场景：`if cmd; then` 条件位、`cmd && other` 左侧、管道无 `pipefail`、命令替换内。可复现：
   ```bash
   docker run --rm ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest} bash -c 'set -e; false | true; echo survived'
   ```
   输出 `survived`——最后一节成功就掩盖了失败；加上 `set -o pipefail` 才会中止。基准写法 `set -euo pipefail`（L1-030、L1-021）。
3. **临时文件/目录不挂 trap 清理**。后果：脚本中途失败留下垃圾，重跑可能撞旧状态。基准做法是 `tmp=$(mktemp -d)` 后立刻 `trap 'rm -rf "$tmp"' EXIT`，信号场景用 `trap ... INT TERM`（L1-029-trap-mktemp、L3-006-signal-cleanup）。反例可复现：去掉 trap 行后脚本 `exit 1`，`ls /tmp/tmp.*` 会留下残留目录。
4. **假设镜像里有 yq**。后果：跑 `shared/lib/yaml.sh` 或任何 YAML 处理脚本直接 `yq: command not found`。先 `command -v yq` 探测（见 §2），或改用 jq 处理 JSON 侧需求（L3-003）。
