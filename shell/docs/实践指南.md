# Shell 实践指南（G1）

> 回答「什么时候用 Shell 轨道的哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 命令契约（规范 §4.3）：统一 `TAG=latest scripts/run-example.sh shell <ID>`；
> 门禁阈值只写 `images/versions.env` 的变量名（`${SHELLCHECK_SEVERITY}`，版本引用契约 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 Shell（Bash）工程能力——L1 语言与
展开机制（引号与词分裂、`IFS`、参数展开、条件与退出码、函数与 `local`、严格模式、
trap/mktemp、重定向），L2 脚本工程（骨架、shellcheck 门禁、bats 测试、幂等步骤、
失败诊断、NUL 安全传路径），L3 专题（并行与 wait、流处理、jq、校验和、信号清理），
共 54 个用例；终点是 `shell/project` 的毕业项目「部署与巡检工具集」（严格模式、
手写长选项解析、原子发布、flock 防重入、并行巡检与确定性报告，只用本地命令）。
每一层都用「可观察判据」验收：用例跑通、输出与 `expected.txt` 逐行一致
（口径见 [开发指南.md](开发指南.md)）。

**什么时候别用本指南**：

- 想学某个展开规则本身（`"$@"` 与 `$*` 的精确差异、`IFS` 的字段切分算法）——
  直接跑对应 L1 用例（`L1-019-array-at-star`、`L1-005-ifs-field-splitting`），
  指南不讲语法，读了也学不会；
- 想找某个具体故障的排查路径（未加引号炸分词、`set -e` 失效）——去
  [问题指南.md](问题指南.md)（G3，按问题域组织）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）；
- 要处理结构化数据或复杂业务逻辑——Shell 的强项是粘合本地命令与文本流；
  毕业项目刻意「只使用本地命令、不下载依赖」，这不是局限而是本轨道的边界，
  需要 JSON 深度处理时用 `jq`（`L3-003-jq-json-processing`）而不是硬解析。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令（引号与词分裂这个考点的「正主」在用例里）：

  ```bash
  grep 'L1-003-quoting-word-splitting' shell/docs/知识点清单.md
  ```

  输出会指向 `KP-SH-L1-03` 行与建议用例 `L1-003-quoting-word-splitting`。
- 后果：只读不跑，等于没碰过 shell；「未加引号的展开会炸分词」这种结论，
  背十遍不如真看一次 `cat: /tmp/my: No such file or directory`。
  正确动作是 `TAG=latest scripts/run-example.sh shell L1-003-quoting-word-splitting`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（`KI-05` 定案：L0 表示镜像与 runner 通路
验证，不属于知识难度层级），它验证镜像能运行 Bash 脚本，与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh shell L0-hello
# 实测输出：shell/L0-hello                PASS (1s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见
  环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh shell L0-hello
  ```

- 后果（实测）：runner 输出 `FAIL`，stderr 含
  `docker: Error response from daemon: manifest unknown`，以非零退出。
  通路用例 1 秒就能把这类环境问题暴露出来；不验通路时，同样的错误会发生在
  你等得最久的那一步，且难以与代码 bug 区分（素材池 `S-06`）。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| 变量展开一律双引号：`"$f"`、`"$(cmd)"`（见 `L1-003-quoting-word-splitting`） | 裸写 `$f`、`$(cmd)` | 展开结果会再经历一次词分裂与 glob：实测路径 `/tmp/my dir/file.txt` 裸展开后 `cat` 收到 2 个参数，报 `cat: /tmp/my: No such file or directory`（反例见下） |
| 传「原样参数列表」用 `"$@"`，需要拼一个字符串才用 `$*`（见 `L1-019-array-at-star`） | 用 `$*` 转发位置参数 | `$*` 用 `IFS` 首字符连接，参数边界丢失；`"$@"` 才保持一一对应 |
| 含空格/换行的文件名用 `find -print0` + `xargs -0` / `read -d ''`（见 `L2-012-null-delimited-paths`） | `for f in $(ls)`、`find | xargs` | 按行/NUL 之外的方式传路径必然在空格处炸分词 |
| 脚本头 `set -euo pipefail`（见 `L1-030-strict-mode`） | 只写 `set -e` 或什么都不写 | 不开 `-u` 未定义变量静默变空串；不开 `pipefail` 管道中间命令失败被吞——实测 `false | true` 默认退出码 0（反例见 [问题指南.md](问题指南.md) 严格模式节） |
| 函数内允许失败的命令显式写 `|| return`/`if cmd; then`（见 `L1-023-functions-local-return`） | 以为 `set -e` 在函数里「到处都生效」 | 函数被 `if`/`&&`/`||` 调用时整段进入「条件上下文」，内部 errexit 失效，实测 `false` 后的代码照样执行 |
| `local` 与赋值分行写：`local out; out=$(cmd)`（见 `L1-023-functions-local-return`） | `local out=$(cmd)` | `local` 的返回值覆盖命令替换的退出码，失败被静默吞掉（实测见 [问题指南.md](问题指南.md)） |
| 清理逻辑用 `trap ... EXIT` + `mktemp`（见 `L1-029-trap-mktemp`） | 手工在脚本各分支 `rm` | 失败提前退出路径漏删，幂等性破坏；`trap` 是 Shell 版的资源兜底 |
| 一律经 runner 跑用例 | 手写 `docker run bash xxx.sh` 复刻 runner | CI 与本地用同一个 runner（真本 `scripts/run-example.sh`）；口径分裂造成「本地假绿」（素材池 `S-01`：TAG 与 IMAGE_TAG 名字不一致曾让 6 个用例 job 全红） |
| 门禁阈值只引用 `${SHELLCHECK_SEVERITY}` | 在文档/脚本里手写 shellcheck 级别常量 | 升级时手写常量集体过期，且过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：未加引号的路径炸分词**

- 错误做法：

  ```bash
  f="/tmp/my dir/file.txt"
  cat $f          # 少一对引号
  ```

- 复现命令（在 `devbox-shell:latest` 镜像里实测；先把文件造出来）：

  ```bash
  docker run --rm "ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest}" bash -c '
  mkdir -p "/tmp/my dir"; echo hello > "/tmp/my dir/file.txt"
  f="/tmp/my dir/file.txt"
  cat $f; echo rc=$?
  set -- $f;  echo "unquoted args=$#"
  set -- "$f"; echo "quoted args=$#"
  cat "$f"'
  ```

- 后果（实测输出，原样记录）：

  ```text
  cat: /tmp/my: No such file or directory
  cat: dir/file.txt: No such file or directory
  rc=1
  unquoted args=2
  quoted args=1
  hello
  ```

  一个路径被拆成 `/tmp/my` 和 `dir/file.txt` 两个参数（`set -- $f` 得到 2 个
  位置参数），`cat` 找不到任何一个；加上引号后 1 个参数，原样读出。
  这就是 `KP-SH-L1-03` 的可观察判据，用例 `L1-003-quoting-word-splitting`
  把两种写法放进同一份 `expected.txt` 对照验收。

## 4. 真实工作中的变体

**变体 1：CI 门禁的 shellcheck 级别取舍**
仓库门禁按 `images/versions.env` 的 `${SHELLCHECK_SEVERITY}`（warning）判红。
要意识到级别的含义：word splitting 的 `SC2086` 是 **info** 级，实测
`shellcheck -S warning` 对它返回 0（不报）——「门禁绿」不等于「没有分词隐患」
（素材池 `S-07` 的同型问题：绿 ≠ 对）。写脚本时不等门禁替你抓引号，
展开处直接写引号；评审时对 `$` 裸展开单独过一眼。

**变体 2：需要幂等的运维脚本（毕业项目的真实取舍）**
重复执行不产生副作用是 Shell 的「回滚」（docs/20 §3.4 R6）：`mkdir -p`、
幂等步骤（`L2-010-idempotent-steps`）、防重入 `flock`（`L2-006-flock-reentrancy`）、
`trap` + `mktemp` 清理（`L1-029-trap-mktemp`）。与「写完就扔的一次性命令」不同，
进毕业项目的脚本必须按这个标准写。

**变体 3：需要可复现的构建结果**
`:latest` 随 main 变动（`KI-08`），复现历史结果用 `sha-<commit>` 标签：
`TAG=sha-<commit-sha> scripts/run-example.sh shell <ID>`。本地调试自建镜像时
`TAG` 缺省落到 `local`（真本 `scripts/run-example.sh`），`local` 是本地约定，
不要写死进文档或 CI 配置。

**反例（可执行）**

- 错误做法：并发任务都依赖可变标签 `:latest`。
- 复现思路（真实历史 bug `#184`，素材池 `S-02`）：两个任务同时跑，A 推的
  `:latest` 被 B 覆盖，A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」
  无法区分。
- 可直接观察 tag 风险的命令（实测）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh shell L0-hello   # manifest unknown，rc=1
  ```

- 后果与修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  需要固定版本时优先 sha 标签。
