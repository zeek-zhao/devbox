# Shell 轨道开发指南（G2）

> 回答「从零到能改」：环境、目录、一条命令跑通、改动循环。
> 语法本身归知识点清单与 L1 用例，本文只讲本轨道的工程动线。

## 1. 环境与启动

- 镜像：`ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest}`（映射真本 `images/lang-images.tsv`；FROM tool 层，与其他语言镜像横向并列）。
- Bash 5.2 由 Ubuntu 24.04 系统自带，不在 `images/versions.env` 里锁版本；语言层补装 bats、shellcheck、shfmt、jq、curl 等（见 `images/scripts/install/shell.sh`）。
- lint 严重级别口径来自 `images/versions.env` 的 `${SHELLCHECK_SEVERITY}`（当前 warning），命令里写成 `shellcheck -S warning`。
- yq：`install/shell.sh` 声明安装（版本与校验和锁在 `${YQ_VERSION}`/`${YQ_SHA256}`），但 **latest 镜像实测没有 yq**（`command -v yq` 为空）。依赖 yq 的 `shared/lib/yaml.sh` 在当前镜像里跑不起来，需要重建镜像；详见 [工具指南](工具指南.md) §1。
- 容器离线运行：用例与项目只用镜像内已有的命令，不要运行时联网装东西。
- 宿主已有本地镜像时把 `TAG` 换成 `local`；没有镜像就 `scripts/build-images.sh` 建或拉 CI 发布 tag。

## 2. 目录结构与各文件职责

```text
shell/
├── examples/<ID>/        # 54 个用例；run.sh（自运行）+ expected.txt（逐行期望输出）
├── project/              # 毕业项目：部署与巡检工具集
│   ├── src/main.sh       # 主入口（deploy / inspect / report / self-check）
│   ├── lib/common.sh     # 参数、诊断、信号与临时目录清理
│   ├── lib/commands.sh   # 子命令实现
│   ├── tests/commands.bats  # BATS 1.10.0 测试
│   ├── build.sh          # bash -n + shellcheck -S warning 门禁（宿主缺工具自动进容器）
│   ├── check-runtime.sh  # 只读挂载进 runtime 逐字比对固定输出
│   └── COVERAGE.md       # 54 个用例在项目里的真实落点
└── docs/                 # 知识点清单、清单自检、本指南三件套（G2/G4/G5）

scripts/fmt.sh            # 仓库级格式化入口；shell 车道 = shfmt -i 2 -ci -ln bash
```

## 3. 一条命令跑通

```bash
TAG=latest scripts/run-example.sh shell L0-hello
```

真实跑通记录（215 宿主机）：`shell/L0-hello PASS (1s)`、`shell/L1-003-quoting-word-splitting PASS (2s)`、`shell/L2-002-shellcheck-warning-gate PASS (0s)`。列全部用例：`scripts/run-example.sh shell --list`。

失败先看哪里（成本从低到高）：

1. 报镜像拉取失败 / `manifest unknown` → `docker images | grep devbox-shell` 确认本地有哪些 tag，再拉或本地构建；
2. `bash -n` / 语法类报错 → 用例 `run.sh` 本身坏了，`scripts/run-example.sh shell <ID> --keep` 保留容器，`docker exec` 进去单独跑 `run.sh`；
3. 输出与 `expected.txt` 不一致 → 契约是逐行精确、忽略行尾空白与首尾空行；先看 runner 顶部注释，再逐行 diff 实际输出。

## 4. 改动循环（改 → 格式化 → lint → 测试 → 提交）

```bash
# 1) 改：examples/<ID>/ 或 shell/project/src|lib|tests
# 2) 格式化（shfmt 车道：-w -i 2 -ci -ln bash，走容器）
make fmt
# 3) lint（Makefile 同口径：shellcheck -S warning）
make lint
# 4) 测试：项目内一条命令做语法+lint 门禁
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/work" -w /work \
  ghcr.io/zeek-zhao/devbox-shell:${TAG:-latest} bash shell/project/build.sh
#    BATS 测试：进容器后 bats shell/project/tests/commands.bats
# 5) 只查不改（CI 语义）
make fmt-check
# 6) 提交：身份与规范见 T0
git add <文件> && git commit
```

- `shellcheck/shfmt/bats` 三件套是 Shell 的编译循环：shfmt 管排版、shellcheck 管静态错误、bats 管行为回归；参数口径见 [工具指南](工具指南.md) §2。
- 提交身份、门禁文件、PR 约定是跨语言通用内容，见 T0。
