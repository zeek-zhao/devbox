# Go 实践指南（G1）

> 回答「什么时候用 Go 轨道的哪类用例、不用会怎样、怎么验证真的学会了」。
> 语法细节归 L1 用例（见 [知识点清单.md](知识点清单.md)），本篇只讲工程用法，不重复语法。
> 命令契约（规范 §4.3）：统一 `TAG=latest scripts/run-example.sh go <ID>`；
> 版本号只写 `images/versions.env` 的变量名（`${GO_VERSION}`，版本引用契约 §4.4）。

## 1. 适用边界（什么时候用 / 什么时候别用）

**什么时候用本轨道**：你要在 devbox 体系里练 Go 工程能力——L1 语言与标准库
基础（切片、map、接口、错误包装）、L2 工程能力（module、gofmt/vet、表驱动测试、
基准、构建标签、交叉编译）、L3 专题（worker pool 优雅退出、race detector、
pprof、自定义 JSON、TCP echo）、L4 设计模式（23 个），共 77 个用例；终点是
`go/project` 的毕业项目「并发任务网关」（HTTP → 有界 worker pool → 令牌桶 →
指标 → 优雅退出，仅标准库）。每一层都用「可观察判据」验收：用例跑通、输出与
`expected.txt` 逐行一致（验收口径见 [开发指南.md](开发指南.md)）。

**什么时候别用本指南**：

- 想学某个语言特性本身（slice 扩容策略、泛型类型推断规则）——直接跑对应 L1
  用例，指南不讲语法，读了也学不会；
- 想找某个具体故障的排查路径（goroutine 泄漏、channel 死锁、go.sum 校验失败）
  ——去 [问题指南.md](问题指南.md)（G3，按问题域组织：并发、构建与依赖）；
- 想查某个工具的参数——去 [工具指南.md](工具指南.md)（G4）；
- 想引第三方框架（Web 框架、ORM 等）——本轨道 L1–L3 用例与毕业项目只用标准库
  （`go/project/go.mod` 无 `require`，强制禁用代理），引依赖不会通过评审。

**反例（可执行）**

- 错误做法：把本指南当语法书，跳过用例直接背结论。
- 复现命令（语法考点的「正主」在清单与用例里，不在指南里）：

  ```bash
  grep 'KP-GO-L1-27' go/docs/知识点清单.md
  ```

  输出会指向 KP 行与建议用例 `L1-027-goroutines`——goroutine 基本启动知识点的
  载体是用例，不是本篇。
- 后果：只读不跑，等于没碰过 `go build`；channel 只发不收这类泄漏只有跑起来
  才会暴露。正确动作是
  `TAG=latest scripts/run-example.sh go L1-027-goroutines`。

## 2. 最小可运行示例（指向具体用例 ID）

入口是 `L0-hello`——L0 是通路验证层（`KI-05` 定案：L0 表示镜像与 runner 通路
验证，不属于知识难度层级），它验证镜像能编译并运行 Go（`${GO_VERSION}`，
真本 `images/versions.env`），与任何知识点无关：

```bash
TAG=latest scripts/run-example.sh go L0-hello
# 实测输出：go/L0-hello                   PASS (5s)
```

通路没验证之前，不要碰 L2/L3 用例。

**反例（可执行）**

- 错误做法：不验通路，直接上依赖最重的用例。
- 复现命令（把 `TAG` 指向一个不存在的标签，模拟「镜像/tag 出问题」这一最常见
  环境故障）：

  ```bash
  TAG=nosuchtag scripts/run-example.sh go L0-hello
  ```

- 后果（实测）：runner 输出 `FAIL`，stderr 含
  `docker: Error response from daemon: manifest unknown`，以非零退出。
  通路用例 5 秒就能把这类环境问题暴露出来；不验通路时，同样的错误会发生在
  你等得最久的那一步，且难以与代码 bug 区分（素材池 `S-06`）。

## 3. 惯用法与反模式对照表（含可复现反例）

| 惯用法 | 反模式 | 为什么 |
|---|---|---|
| goroutine 的退出路径与创建配对设计（见 `L1-027-goroutines`、`L3-001-worker-pool-shutdown`） | `go func()` 一发了之，不定义谁关闭 channel / 谁 Done | 发送方没有接收者就永久阻塞，goroutine 泄漏；main 返回还会静默丢弃它们（泄漏对照实验见下） |
| channel 归属明确：仅发送方负责 close，收尾用 `range` 或 comma-ok（见 `L1-028-channels-select-close`） | 双方都可能 close、或用 `close` 当「广播」发给无缓冲 channel | 向已关闭 channel 发送 panic；close 未初始化/为 nil 的 channel 也 panic |
| 共享状态要么加锁要么走 channel，用 `-race` 验证（见 `L3-002-race-detector`） | 「跑了几百次都没事」当并发正确性证据 | 竞态是调度时序问题，普通运行通过不代表没有竞态；`go build -race` 才是判据 |
| 一律经 runner 跑用例 | 手写 `docker run` / `go run` 复刻 runner 行为 | CI 与本地用同一个 runner（真本 `scripts/run-example.sh`）；口径分裂造成「本地假绿」（素材池 `S-01` 记录过 TAG 与 IMAGE_TAG 名字不一致导致 6 个用例 job 全红的事故） |
| 依赖一律进 module：`go.mod`/`go.sum` 入库 | 手动往 GOMODCACHE 塞包、或不提交 go.sum | go.sum 缺失/被改时校验失败（SECURITY ERROR），构建不可复现（复现实验见 [问题指南.md](问题指南.md) 构建与依赖节） |
| 版本号只引用 `images/versions.env` 变量 | 在文档/脚本里手写 Go 版本常量 | 升级时手写常量集体过期，且过不了 `scripts/check-version-truth.sh` |

**反例（可执行）：goroutine 泄漏（发送方无接收者）**

- 错误做法：

  ```go
  package main

  import (
      "fmt"
      "runtime"
      "time"
  )

  func main() {
      fmt.Println("before:", runtime.NumGoroutine())
      ch := make(chan int)     // 无缓冲，且永远没有接收方
      go func() { ch <- 1 }() // 阻塞在此，泄漏
      time.Sleep(100 * time.Millisecond)
      fmt.Println("after:", runtime.NumGoroutine())
  }
  ```

- 复现命令（在本轨道镜像里实测）：

  ```bash
  docker run --rm -v "$PWD":/exp -w /exp \
    "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}" go run leak.go
  ```

- 后果（实测输出）：`before: 1`、`after: 2`——泄漏的 goroutine 让计数不回落；
  程序仍以 0 退出（main 返回不报错），所以**这种泄漏不会自己现形**，要靠
  `runtime.NumGoroutine()` 对照或 `goleak` 式断言兜住。修法见
  [问题指南.md](问题指南.md) 并发节：定义 channel 所有者并保证接收方存在，
  或用 `context` 取消 + `select` 让发送方能退出（`L3-001-worker-pool-shutdown`
  是完整范式）。

## 4. 真实工作中的变体

**变体 1：本地已自建镜像（`make images` 或 `scripts/build-images.sh`）**
runner 的取值顺序是 `TAG` → `IMAGE_TAG` → `local`（真本 `scripts/run-example.sh`），
本地调试自建镜像时不传 `TAG` 即落到 `local`，或显式
`TAG=local scripts/run-example.sh go <ID>`。注意 `local` 只是本地约定名，
不要写死进文档或 CI（素材池 `S-01` 的教训就是两个名字各说各话）。

**变体 2：需要可复现的构建结果（对应 `L2-007-cross-compilation` 的工程化延伸）**
`:latest` 随 `main` 变动（ROADMAP `KI-08`），复现历史结果用 CI 每次构建打的
`sha-<commit>` 标签：`TAG=sha-<commit-sha> scripts/run-example.sh go <ID>`。
产物侧同理：`CGO_ENABLED=0 go build` 出静态单二进制，回滚就是换回旧 tag 的
产物（docs/20-开发发布增强.md §3.2 R3/R6）。

**变体 3：整轨回归**
改动波及面大（升级 `${GO_VERSION}`、动公共构建配置）时跑全轨 77 例，与 CI 的
`examples` job 同款入口：`TAG=latest scripts/run-example.sh go --all`。
并发类用例（`L3-001-worker-pool-shutdown`、`L3-002-race-detector`）也在这一步
一起验，不要因为本地跑过单例就跳过整轨。

**反例（可执行）：并发 PR 都把各自的镜像推成 `:latest`**

- 错误做法与后果（真实历史 bug `#184`，素材池 `S-02`）：A 推的 `:latest` 被
  B 覆盖，A 的用例 job 拉到的已是 B 的镜像——症状与「我的代码坏了」无法区分。
- 可直接观察 tag 风险的命令：

  ```bash
  TAG=nosuchtag scripts/run-example.sh go L0-hello   # manifest unknown，实测
  ```

- 修法：PR 只推 `sha-<commit>` 标签、不推 `:latest`（CI 已按此实现）；
  本地需要固定版本时同样优先 sha 标签。
