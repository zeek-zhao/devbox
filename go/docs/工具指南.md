# Go 工具指南（G4）

> 「是否预装」全部在 `ghcr.io/zeek-zhao/devbox-go` 镜像里实测过（2026-11-05，
> probe 命令见 §1 脚注），不是抄 README。版本一律引用 `images/versions.env` 变量名。

## 1. 工具全景表

| 工具 | 用途 | 本工程是否预装 | 版本来源 |
|---|---|---|---|
| go | 编译 / 测试 / vet / pprof 统一入口 | 是（`/usr/local/go/bin/go`） | `${GO_VERSION}`（images/versions.env） |
| gofmt | 格式化 | 是（`/usr/local/go/bin/gofmt`） | 随 `${GO_VERSION}` |
| go vet | 静态检查（CI 门禁的一部分） | 是（go 子命令） | 随 `${GO_VERSION}` |
| go test / cover | 测试与覆盖率 | 是 | 随 `${GO_VERSION}` |
| `-race` | 数据竞争检测 | 是（工具链内置开关，无需安装） | 随 `${GO_VERSION}` |
| go tool pprof | CPU / 内存剖析 | 是（go 子命令） | 随 `${GO_VERSION}` |
| Delve（dlv） | 断点调试器 | 否（实测 `command -v dlv` 无结果） | 需自装，见 §2.6 |
| staticcheck / golangci-lint | 第三方 lint | 否（实测 `command -v` 无结果） | 需自装，见 §2.6 |

复跑实测的 probe 命令：

```bash
docker run --rm "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}" bash -lc \
  'go version; command -v gofmt || echo gofmt: missing;
   for t in dlv staticcheck golangci-lint; do command -v "$t" >/dev/null 2>&1 || echo "$t: 未预装"; done;
   go vet -h >/dev/null 2>&1 && go test -h >/dev/null 2>&1 && echo "vet/test 子命令可用"'
```

## 2. 每工具一节

### 2.1 go（build / vet / test）

- 装在哪：镜像内 `/usr/local/go`（Dockerfile 用官方 tarball 安装，SHA256 来自
  versions.env 的 `${GO_SHA256}`）；环境变量 `GOROOT`/`GOPATH`/`GOTOOLCHAIN`/`GOPROXY`
  已在镜像 ENV 固化，勿在命令行覆盖。
- 怎么调：容器内直接 `go ...`；宿主走 `bash go/project/build.sh`（无 go 时自动落容器）。
- 常用参数速查：

```bash
go build -o out main.go                # 编译（用例 run.sh 就是这么调）
go vet ./...                           # 静态检查（build.sh 会跑）
go test -count=1 ./...                 # 绕缓存重跑全部测试
go test -coverprofile=build/coverage.out ./...   # 覆盖率（build.sh 同款）
go test -bench .                       # 基准测试
```

- 用例参考：gofmt/vet 门禁语义见 L2-002-gofmt-vet，表驱动测试见 L2-003-table-tests，
  覆盖率见 L2-004-test-coverage，基准见 L2-005-go-benchmark。

### 2.2 gofmt

- 怎么调：容器内 `gofmt -l src internal` 列未格式化文件，`gofmt -w` 改写。
- 工程口径：统一走 `bash scripts/fmt.sh --lang go`（`--check` 只查不改，CI 用它），
  不要绕过脚本各处手改，否则本地与 CI fmt job 口径漂移。

### 2.3 -race（数据竞争检测）

- 怎么调：`go test -race ./...` 或 `go run -race main.go`。
- 教学：构造竞争 → 加 `-race` 抓 DATA RACE 的完整过程见 L3-002-race-detector。

### 2.4 go tool pprof

- 怎么调：采集 `go test -cpuprofile=cpu.out .`，分析 `go tool pprof <binary> cpu.out`，
  常用子命令 `top` / `list` / `web`。
- 教学：CPU 热点定位完整流程见 L3-003-cpu-profile。

### 2.5 Delve / 第三方 lint（未预装）

- 需要断点调试时在容器内自装：
  `go install github.com/go-delve/delve/cmd/dlv@latest`（走镜像内 `${GOPROXY}`）。
- staticcheck / golangci-lint 同理自装。注意：本工程门禁只用 go vet；想引入更强的
  lint 属于改判定标准，必须走 T0 §3 的人工评审放行，不许顺手加。

## 3. 选型对比

- 格式化器：不适用：无同类——gofmt 是 Go 官方唯一格式化器，「gofmt 的输出」即标准。
- lint：go vet（预装、进 build.sh 门禁）对比 golangci-lint（更强、未预装、不走 CI）。
  选 vet 的理由：零安装、随工具链走、CI 完全可重现；golangci-lint 规则更全但要拉
  额外依赖且版本漂移会破坏镜像可重现性。

## 4. 常见误用

1. **在宿主机直接敲 gofmt / go test**：宿主（Windows 开发机、CI 构建机）没装 Go
   工具链，必然 command not found。格式化器和被测代码一样只能活在镜像里；宿主入口是
   `bash scripts/fmt.sh --lang go` 或 `bash go/project/build.sh`（自动落容器）。
2. **`go test` 不带 `-count=1`**：结果可能来自缓存，改完测试也可能「全绿」。
   复现：把一个断言改成必败，不带 `-count=1` 跑两次、再带上跑一次，对比差异。
3. **想绕过 `GOTOOLCHAIN=local`**：把 go.mod 的 go 指令写得比镜像新，指望 go 自动
   联网下载新工具链——镜像锁死了该变量，直接报错退出。正确路径是改
   `images/versions.env` 的 `${GO_VERSION}` 走发版流程。
4. **把 `IMAGE_TAG` 当 `TAG` 敲 runner**：runner 读 `TAG`，CI 才传 `IMAGE_TAG`，
   两者是同一个值的两个名字；历史上名字不一致曾让整片用例 job 全红而本地各自「正常」
   （T0 §1）。文档与手敲统一 `TAG=`。
