# Go 排查手册（G3 · 按问题域排障）

> 本文只有一个主要承诺：**按症状查到排查命令与判据**。每个小节统一四件套：
> 典型现象（可观察）→ 排查命令（可执行）→ 判据（期望输出）→ 修复（可验证）。
> §2「错误处理」章的 15 节逐一对应 15 个 E 系示范用例 README 的 exempt 指向
> （`go/docs/排查手册.md 错误处理章`）；索引速查见 [知识点清单](知识点清单.md) §E。
> 命令契约统一 `TAG=latest scripts/run-example.sh go <ID>`（[工程参考](工程参考.md) §5）。

## 1. 怎么用这本手册

1. 按症状在 §2 定位小节（每节标题即问题域）；
2. 先跑「排查命令」拿到真实输出，与「判据」对照——判据行不出现，说明故障形态与本节不同，换节或走 §3 lab；
3. 按「修复」改，重跑同一命令验证判据转绿；
4. 修完跑门禁：`bash go/project/build.sh`（gofmt → go vet → go test，[工程参考](工程参考.md) §3）。

## 2. 错误处理（E 系 15 例对应节）

### 2.1 错误分类与类型体系（E-001-error-taxonomy）

- **典型现象**：同一 `error` 在不同调用点被解读成不同意思——有的拒绝、有的重试、有的吞掉，动作全靠猜。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-001-error-taxonomy`
- **判据**：三种自定义错误类型各归唯一类别与动作，末行 `taxonomy types=3 VALIDATION=1 TRANSIENT=1 INTERNAL=1`。
- **修复**：每类一个自定义错误类型，`classify` 唯一归类，类别映射唯一动作（reject-input / retry / fail-fast）。

### 2.2 创建与抛出（E-002-error-create）

- **典型现象**：错误文本只有 `failed` 不带端口/尝试次数；或成功路径返回 typed-nil 指针，调用方 `err != nil` 误判失败。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-002-error-create`
- **判据**：`typed-nil trap: ok case but err!=nil: true` + `correct: return nil as error gives err==nil: true`。
- **修复**：`fmt.Errorf` 带现场数据，结构化字段用自定义类型；成功路径直接 `return nil`。

### 2.3 捕获与精确匹配（E-003-error-match）

- **典型现象**：中间层 `fmt.Errorf("...: %w", ...)` 之后 `== ErrNotFound` 永不成立；领域规则（逾期 ≥30 天）无法归同类。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-003-error-match`
- **判据**：`match ==: wrapped == ErrNotFound: false` → `match errors.Is(wrapped, ErrNotFound): true`；`match custom Is: 45-day overdue matches policy(30+): true`。
- **修复**：判定一律 `errors.Is`；领域规则给错误类型实现自定义 `Is`。

### 2.4 传播与包装（E-004-error-wrap）

- **典型现象**：原样上抛顶层看不到发生在哪步；`%v` 加了位置却重造错误，`errors.Is` 判根因永远失败。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-004-error-wrap`
- **判据**：`wrap %w keeps chain: errors.Is(err, ErrDiskFull)=true` + `wrap %v loses chain: errors.Is(err, ErrDiskFull)=false unwrap=nil: true`。
- **修复**：中间层统一 `fmt.Errorf("本层位置: %w", err)`，`errors.Unwrap` 可逐层剥开。

### 2.5 错误身份判定（E-005-error-identity）

- **典型现象**：两处 `errors.New("unauthorized")` 文本相同身份不同；拿字段/行号只能解析错误字符串，包装后全丢。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-005-error-identity`
- **判据**：`identity: two errors.New with same text identical: false` + `as: extracted *ParseError ok=true field="age" line=3`。
- **修复**：哨兵值包内唯一定义；结构化字段用自定义类型 + `errors.As` 提取。

### 2.6 上下文附加（E-006-error-context）

- **典型现象**：顶层日志只有 `operation timed out`，不知哪台主机、哪个用户、哪一步；用户输入裸拼进错误文本被注入。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-006-error-context`
- **判据**：`context text: load profile "alice": dial 10.0.0.7:5432: operation timed out` + `context keeps identity: errors.Is(err, ErrTimeout)=true` + `context quotes data: lookup "bobby; drop table users": ...`。
- **修复**：每层用 `%w` 追加自己的现场，身份不丢；数据一律引号包裹。

### 2.7 资源清理（E-007-defer-cleanup）

- **典型现象**：错误路径提前 return 漏关资源；`defer f.Close()` 返回值被丢——磁盘满还报「成功」；清理错误覆盖主错误带偏排查方向。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-007-defer-cleanup`
- **判据**：`primary first: write: simulated write failure` + `cleanup visible: cleanup: simulated close failure` + `error path cleanup: steps=[open close] err=job failed`。
- **修复**：主错误优先、清理错误可见不覆盖；清理动作进步骤序列可验证。

### 2.8 不吞错与重抛（E-008-error-reraise）

- **典型现象**：数据偶发读不到但程序毫无异常——中间层 `err = nil` 或打日志后 `return nil`，调用方拿到假成功。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-008-error-reraise`
- **判据**：`swallow: caller sees success=true (cache miss lost)` + `log-only: caller sees success=true log="ERROR load: cache miss"` + `reraise keeps identity: errors.Is(err, ErrCacheMiss)=true`。
- **修复**：中间层要么重抛（`%w` 保身份）要么显式归类，不许置 nil。

### 2.9 边界转换与错误码（E-009-errno-boundary）

- **典型现象**：标准库失败直接 panic 或 `os.Exit(1)` 一刀切，脚本/调度器分不清「文件不存在」和「权限拒绝」；`strings.Contains(err.Error(), "no such file")` 换环境失效。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-009-errno-boundary`
- **判据**：`boundary is PathError: true` + `boundary code for missing file: 3` + `boundary code for bad number: 2` + `boundary code for unknown: 70`。
- **修复**：进程边界用 `errors.Is(err, fs.ErrNotExist)` 等稳定接口分类，映射退出码协议（参数 2 / 领域 3 / 成功 0 / 未分类 70）。

### 2.10 重试与退避（E-010-retry-backoff）

- **典型现象**：对配额超限、参数错误这类永远修不好的失败反复重试；或无退避原样按固定频率重放放大风暴。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-010-retry-backoff`
- **判据**：`retry non-retryable: attempts=1 waited=0s err=not retryable: quota exceeded` + `retry give-up: attempts=4 waited=70ms err=gave up after 4 attempts: rate limited at attempt 4`。
- **修复**：只重试 TRANSIENT 类，10/20/40ms 指数退避加上限，耗尽把「第几次失败」包进最终错误。

### 2.11 超时与取消（E-011-context-timeout）

- **典型现象**：慢查询无预算控制，goroutine 永远挂；日志只有 `i/o timeout`，分不清「预算到了」还是「调用方不要了」，重试策略选错。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-011-context-timeout`
- **判据**：`timeout identity: errors.Is(err, context.DeadlineExceeded)=true` + `cancel identity: errors.Is(err, context.Canceled)=true` + `enough budget: err=<nil>`。
- **修复**：`context.WithTimeout` 全链透传；`errors.Is` 分辨 deadline 与 cancel，前者按背压处理后者直接放弃。goroutine 泄漏复合演练见 §3。

### 2.12 并发错误聚合（E-012-error-join）

- **典型现象**：批量同步遇到第一个错误整体 return，其余分片失败全失明；自拼 multierror 字符串丢了身份，判不了「失败集合里有没有限流」。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-012-error-join`
- **判据**：`join: err=shard 1: disk unavailable\nshard 3: auth rejected` + `join member disk: errors.Is(joined, ErrDisk)=true` + `join empty: err==nil=true`。
- **修复**：`errors.Join` 聚合全部分片错误，成员身份逐个 `errors.Is` 可判；单错/空集退化正确。

### 2.13 可观测性（E-013-error-observability）

- **典型现象**：一次底层故障在日志里出现五条，每层都「顺便」记一遍且互相不一致；有的错误只在日志里出现过、函数却返回 nil。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-013-error-observability`
- **判据**：`level=ERROR msg="request failed" err="service: repo unavailable" op=list-users` + `observability: errors.Is after logging=true`。
- **修复**：只在进程边界记一次（结构化 level/msg/err/op），中间层不抢日志；记完重抛，身份在日志之后仍可判。

### 2.14 不可恢复与快速失败（E-014-fail-fast）

- **典型现象**：不变量破坏后带病运行（符号表缺条目当 0 继续算，坏结果写进存储）；或库函数随手 panic 穿透三层调用栈。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-014-fail-fast`
- **判据**：`fail-fast policy: unrecoverable -> exit(70) (simulated)` + `fail-fast boundary: panic converted, errors.Is(err, ErrInvariant)=true`。
- **修复**：不变量破坏即停（exit 70），不静默降级；库函数不 panic，进程边界 `recover` 转 error 且 `errors.Is` 可判。

### 2.15 反模式对照（E-015-antipattern-compare）

- **典型现象**：按错误文本判类别（文案一改就误判）、吞错（失败伪装成成功）、中间层抢日志（一条错误 N 份日志）、panic 当流程控制（recover 只得零值）。
- **排查命令**：`TAG=latest scripts/run-example.sh go E-015-antipattern-compare`
- **判据**：`antipattern match-by-text: false / correct errors.Is: true` + `antipattern swallow: err==nil=true / correct return: err==nil=false` + `antipattern panic-control: recovered n=0 / correct err=disk full`。
- **修复**：逐条换成正确写法——`errors.Is` 判身份、错误必传播、日志边界记一次、error 表达失败语义。
