# Go 开发指南（G2）

> 本文只写 Go 轨道的差异；跨语言通用动线（runner、CI、门禁、提交纪律）以
> [13-通用开发指南](../../docs/13-通用开发指南.md) 为单一真本，不在此复制。
> 练什么看[知识点清单](知识点清单.md)，工具细节看[工具指南](工具指南.md)，小疑问看 [FAQ](FAQ.md)。

## 1. 环境与启动

- 镜像：`devbox-go`（定义在 `images/go/Dockerfile`，基于 `devbox-tool` 底座层）。
  版本真本只有一个：`images/versions.env`——Go 版本写 `${GO_VERSION}`，模块代理与校验库
  分别是 `${GOPROXY}`、`${GOSUMDB}`，任何文档不写字面量。
- 获取镜像：`docker pull "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}"`；
  本地自建过镜像就用 `TAG=local`（见 T0 §1 的 TAG 契约）。
- 交互进入容器：`docker run --rm -it "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}" bash`。
- 工具链已锁 `GOTOOLCHAIN=local`：go.mod 里的 go 指令高于镜像版本时直接报错，
  不会自作主张联网下载新工具链——这是特性，保证镜像可重现。
- 宿主机不装 Go 也能干活：`go/project/build.sh`、`go/project/test.sh` 检测到宿主没有
  go 时会自动落到容器里跑。

## 2. 目录结构与各文件职责

```
go/
├── examples/<ID>/        # 教学用例，一个目录一个考点（清单见 知识点清单.md）
│   ├── run.sh            # 自己负责编译与运行，只往 stdout 打业务输出
│   ├── expected.txt      # 期望输出，逐行精确（忽略行尾空白与首尾空行）
│   └── README.md         # 考点说明
├── project/              # 毕业项目（Go 版索引器）
│   ├── build.sh          # 一条龙：gofmt 检查 → go vet → go test（覆盖率）→ 构建 → 自检
│   ├── test.sh           # 测试入口，支持 --integration
│   ├── src/ internal/    # 源码与内部包
│   └── COVERAGE.md       # 覆盖表
└── docs/                 # 本指南层文档（G2/G4/G5）
```

## 3. 一条命令跑通

```bash
cd <仓库根>
TAG=latest scripts/run-example.sh go L1-002-zero-values
```

预期：runner 在 devbox-go 容器里编译运行用例，逐行比对 `expected.txt`，
末尾打印 `PASS`（实测约 2s）。列全部用例：`scripts/run-example.sh go --list`；
跑整门：`TAG=latest scripts/run-example.sh go --all`。

失败时先看哪里：

1. runner 的最后一段输出——会指明是编译失败、运行超时还是期望输出不匹配；
2. 加 `--keep` 保留容器，再 `docker exec` 进去手动跑 `run.sh` 对比现场；
3. 镜像都拉不到（第一步就 manifest unknown）→ 是镜像或网络问题，不是代码问题。

## 4. 改动循环：改 → 格式化 → lint → 测试 → 提交

```bash
# 1) 改代码（go/examples/<ID>/ 或 go/project/）

# 2) 格式化：宿主不装 gofmt，统一走容器入口
bash scripts/fmt.sh --lang go             # 就地格式化 go/ 下源码
bash scripts/fmt.sh --check --lang go     # 只检查，有差异 exit 1（CI 口径）

# 3) lint + 4) 测试：毕业项目一条龙（gofmt 检查 + go vet + go test -coverprofile + 构建 + 自检）
docker run --rm -v "$PWD/go/project:/work" -w /work \
  "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}" bash ./build.sh

# 只重跑测试（必须 -count=1，绕开缓存）：
docker run --rm -v "$PWD/go/project:/work" -w /work \
  "ghcr.io/zeek-zhao/devbox-go:${TAG:-latest}" go test -count=1 ./...

# 5) 提交：身份白名单、Conventional Commits、禁 AI 署名尾巴——纪律见 T0 §5
git add <文件> && git commit
```

要点：

- `go test` 默认走缓存，回归验证必须带 `-count=1`，否则「全绿」可能来自缓存。
- 单测写法：表驱动测试见 L2-003-table-tests，覆盖率见 L2-004-test-coverage，
  基准测试见 L2-005-go-benchmark。
- 格式化/lint 本身是门禁不是可选装饰：`go/project/build.sh` 里 gofmt 检查不过直接 fail
  （这正是 L2-002-gofmt-vet 的考点）。
