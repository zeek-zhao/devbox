# Go 工程参考（G4 · 参考）

> 本文只有一个主要承诺：**Go 轨道的工程事实速查**——镜像、构建、运行、依赖、
> 环境变量、版本真本，一张表对齐，全部可从仓库内文件复核。
> 通用开发动线（runner 细节、CI、门禁、提交纪律）是 T0 真本：

## 2. 镜像层与版本真本

- Go 镜像继承 base → tool 层（`make build-base build-tool build-lang`，
  [docs/01](../../docs/01-镜像体系.md)）；语言层 ARG 有 `${GO_VERSION}`、
  `${GOPROXY}`、`${GOSUMDB}` 等，版本值一律来自 `images/versions.env`，
  Dockerfile 禁止写死版本号（`scripts/check-version-truth.sh` 卡）。
- `GOTOOLCHAIN=local` 是关键环境约束：否则 `go.mod` 写更高 go 版本时 go 命令
  会自作主张联网下新工具链，镜像不可重现（`images/go/Dockerfile` 注释原文）。
- 用例命令里的 `TAG=latest` 与 CI 传入的 `IMAGE_TAG` 是同一个值的两个名字；
  历史教训见 [docs/13](../../docs/13-通用开发指南.md) §1。
- 镜像拉不动时先看 CI 的 `probe` job——那是镜像问题不是代码问题。

## 3. 构建与运行

| 动作 | 命令 | 说明 |
|---|---|---|
| 轨道质量门禁 | `bash go/project/build.sh` | gofmt（格式）→ go vet（静态检查）→ go test -cover（测试），任一步非零即红 |
| 单个用例 | `TAG=latest scripts/run-example.sh go E-003-error-match` | stdout 逐行比对 `expected.txt` |
| 整门语言 | `TAG=latest scripts/run-example.sh go --all` | 全量 92 个用例 |
| 保留现场 | `TAG=latest scripts/run-example.sh go <ID> --keep` | 容器不销毁，`docker exec` 进去复现 |
| 全仓格式检查 | `make fmt-check` | Go 段用 `gofmt -l`（官方工具，无配置文件，[scripts/fmt.sh](../../scripts/fmt.sh)） |
| 全仓 lint | `make lint` | Go 无独立 lint 配置；vet 在 build.sh 与 CI 真跑 |

失败时先看哪里：runner 最后一段输出指明是导入失败、超时还是期望输出不匹配；
再 `--keep` 进容器看现场；最后才怀疑镜像（[docs/13](../../docs/13-通用开发指南.md) §1）。
build.sh 门禁红时按红的那一步修：gofmt 红看列出的文件名，vet 红看诊断行，
test 红看失败断言。

## 4. 依赖纪律

- **运行期只用标准库**：`go/examples/` 各用例不引入任何第三方 module；
  构建脚本固定 `GOPROXY=off GOSUMDB=off`（离线容器没有模块代理）。
- `GOFLAGS="-mod=mod -buildvcs=false"`、`GOWORK=off` 由 build.sh 固定导出，
  避免本地 workspace 配置污染验证结果。
- 格式与静态检查口径：gofmt（官方强制、无配置文件）与 `go vet`，
  对应用例 `L2-002-gofmt-vet`；测试覆盖率落盘见 `L2-004-test-coverage`
  （`build/coverage.out`）。
- 工具链版本只许引用 `${GO_VERSION}`；`go.mod` 的 go 指令不许超过镜像工具链，
  否则触发联网下工具链（被 `GOTOOLCHAIN=local` 拒绝后直接构建失败）。

## 5. 环境变量速查

| 变量 | 谁读 | 作用 | 与错误处理的关系 |
|---|---|---|---|
| `TAG` | `scripts/run-example.sh` / `go/project/build.sh` | 选镜像 tag，文档统一写 `TAG=latest` | 跑 E 系演练用例的前置 |
| `IMAGE_TAG` | CI | `TAG` 的 CI 别名，同一个值 | 禁止在文档里混用两个名字 |
| `REGISTRY` | `scripts/run-example.sh` | 镜像仓库前缀，缺省读 `images/versions.env` 的 `${REGISTRY}` | 私有部署时改 |
| `GOPROXY` | go 命令 | 模块代理；构建脚本固定 `off`（离线） | 排查「下载依赖失败」先看它 |
| `GOTOOLCHAIN` | go 命令 | 镜像固定 `local`，禁止自动下载工具链 | 排查「toolchain 升级」类构建失败 |
| `GOCACHE` / `GOPATH` | go 命令 | 镜像内 `/go/cache`、`/go`，保持构建可重现 | 容器内构建缓存位置 |

## 6. 常见误用

1. **在文档/用例里写死 Go 版本号**（如 `go1.27.3` 字面量）：版本只许引用
   `${GO_VERSION}` 变量名，字面量随升级集体过期——
   [docs/11](../../docs/11-知识点清单增强规范.md) §4.4 版本引用契约。
2. **把 `TAG=latest` 写成 `devbox-go:local` 这类硬编码 tag**：本地自建镜像时才用
   `local`，文档统一 `TAG=latest`（[docs/13](../../docs/13-通用开发指南.md) §1 命令契约）。
3. **给 `go/examples/` 加新目录当演练场**：演练素材放 `go/labs/`，绝不进
   `examples/`（会污染用例计数口径，见 [docs/72](../../docs/72-排障演练规范.md) §1）。
4. **在 `go.mod` 写超过镜像工具链的 go 版本**：`GOTOOLCHAIN=local` 下不会自动
   下载新工具链，构建直接失败；版本升级走 `images/versions.env` 流程。

## 7. 选型对比

不适用：本轨道格式化（gofmt）与静态检查（go vet）都是官方工具链唯一选择，
无同类竞争项需要裁决；第三方错误处理库（multierror 等）被依赖纪律排除，
标准库 `errors.Join` 已覆盖并发聚合。
