# Go 知识点清单

本清单是 Go 用例的考点与验收依据。每个 KP 编号对应一个建议用例 ID；L1 聚焦单文件语言与标准库语义，L2 聚焦离线可复现的工程实践，L3 聚焦并发、性能、序列化和网络专题。所有示例只依赖 Go 标准库，断言输出时须先规整顺序并避免环境相关值。

## 4. L4 设计模式专题

L4 是**专题层**：不再引入新语法，而是把 L1–L3 的能力组合成可复用的结构。
本层素材整理自外部 `go-sample` 仓库的既有实现（cpp/python 有现成单文件，go 需拆分，
java 按本表判据实现），一个模式一个用例，共 23 例。

**与 L1–L3 的三点不同**：

1. 用例一律标 `coverage: pending` —— 设计模式是**可复用结构**的练习，不强制接入毕业项目；
   是否纳入 `--strict` 收口见 `devbox-待办清单.md` 的待定项。
2. 判据只允许「stdout 固定文本 / 退出码 / 编译结果」，**不许出现耗时、随机、并发调度顺序**。
3. 同一模式在四门语言里 ID 相同（`L4-0NN-<slug>`），便于横向对照。

### 为什么 L4 不计入 R-E-01 的每语言 55 软目标

R-E-01 的软目标衡量的是「语言能力覆盖」，L4 是**结构复用**专题，与 L1–L3 的知识点不重叠。把 23 例计入后每语言 76 例，已超出 47–59 区间，这是**有意的范围扩展**，不是漏算。

## 5. 明确不覆盖的

| 内容 | 为什么不覆盖 |
|---|---|
| 任何第三方 Go 包 | 模块缓存为空且容器无外网，依赖下载无法完成；本清单限定标准库与本地源码。 |
| Web 框架、ORM 与第三方日志框架 | 这些属于生态选型而非 Go 语言核心，且会引入无法离线获取的依赖。 |
| 需要外网的 HTTP 请求 | 容器网络不可用且返回内容不可控；网络行为仅用 127.0.0.1 的本机 TCP 验证。 |
| 依赖外部 C 库的 cgo 集成 | gcc 可用不代表外部头文件和库存在；cgo 外部库用例无法在镜像中链接。 |
| 随机调度顺序、时间戳或内存地址作为期望输出 | 结果随运行变化，无法用固定 expected 输出稳定验收；并发输出须同步并排序。 |
| GUI 与平台专属系统调用 | 不属于当前索引器毕业项目的核心流程，且会绑定特定桌面或操作系统环境。 |
| C++ 专属对象生命周期与模板机制 | Go 没有对应语言机制；照搬会变成概念错配，不构成 Go 可运行用例。 |
| 生产级外部服务部署与云 SDK | 需要凭据、外网或特定基础设施，无法在无网络的 Go 镜像中独立重现。 |
