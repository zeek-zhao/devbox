## 现象

两种重试事故：一是「见错就重试」——对配额超限、参数错误这类永远修不好的
失败反复重试，把限流放大成打挂下游；二是无上限重试或无退避——同一时刻的
风暴被原样按固定频率重放。

## 期望输出

与 expected.txt 逐行一致：第 3 次成功（累计退避 30ms）、不可重试错误首次
即停（waited=0s）、持续限流在 4 次预算耗尽后报最后一次错误与尝试次数。

## 为什么这样处理

- 重试决策挂在错误类型上：错误实现 `Retryable() bool`，`errors.As` 沿链
  找到它来问「值得再试吗」——限流可重试、配额超限不可重试，规则由定义错误的
  一方声明，调用方不猜。
- 有限次数 + 指数退避：重试是花钱买恢复，预算（4 次、10ms 翻倍）写死在
  函数签名可见处；预算耗尽必须报错并把最后一次错误用 `%w` 带出去，
  绝不把「重试失败」吞成「成功」。

## 反例

- 无预算、无退避的死循环重试：把抖动放大成事故。
- 对不可重试错误（配额、参数、认证）重试：除了放大故障什么也修不好。
- 重试耗尽后返回 nil 或换一个新错误：排查时丢失真正的最后一次根因。
